## 原始输入（用户需求，逐字保留）

> 新增一个需求：
> 1 用户发起对话时，如果在数字人管理平台开启了意图聚焦（也就是使用laya），那么需要新增一个基于本体（ontology）和本体技能的分析和聚焦。
> 2 根据数字人关联的skills里的各个SKILL.md的头部（不是全部内容），判断是否为本体技能（根据metadata里是否有ontology_id和ontology_name），若有则是，没有则不是。
> 3 如果为本体SKILL技能，并且该技能的ontology_id和存在于ontology里ontology.yaml本体文件中（该文件含有metadata.ontology_id，判断两者是否相同），则选中该技能
> 4 技能聚焦：根据用户关联的SKILL.md文件头部的description和name以及metadata信息（不是全部技能），以及用户输入，依次判断每个SKILL.md与用户意图的关联，保留超过阈值的SKILL。没超过则过滤掉。
> 5 技能工具聚焦：针对每个技能关联的ontology.yaml，提取其本体行为behaviors和functions里的name和title
> 6 利用laya，依次结合用户输入以及behaviors和functions的name和title，来选择大于阈值的behaviors和functions（按behaviors和functions分类保存）
> 7 如果behaviors在ontology.yaml的rules关联的行为里，则提取相应related_functions，并在functions里找到其name和title，作为functions里的聚焦
> 8 对所有聚焦的functions和behaviors进行去重
> 9 接下来和提示词绑定聚焦，进入对话
>
> 所有文档用中文记录，高内聚，低耦合

## Clarifications

### Session 2026-11-04

- Q: 非本体技能在聚焦中如何处理？ → A: 仅基于 `SKILL.md` 头部做技能聚焦，不再聚焦工具，也不进入本体能力聚焦。
- Q: 本体技能在聚焦提示中是否只列行为与函数？ → A: 还需补充对该技能的聚焦说明（技能 `name` 与 `description`），与本体行为 / 函数并列。
- Q: 与既有意图聚焦（工具聚焦）的关系？ → A: 全部替换：原工具聚焦不再执行，意图聚焦开关的语义改为本规格的技能聚焦 + 本体能力聚焦；原工具候选评分调用次数为 0。
- Q: 行为聚焦后应补全什么？ → A: 定位关联 `rules[]`，提取 `data_supplements` 中的查询行为并补入行为聚焦；不再提取 `related_functions`。

### Session 2026-11-06

- Q: 能力聚焦的对象是否包含本体函数？ → A: **不包含**。能力聚焦只针对 `behaviors[]`；
  `functions[]` 不再读取、不再出题、不再进入提示 / 记录 / 卡片。
- Q: `rules[]` 与 `data_supplements` 是否仍参与？ → A: **整体取消**。`rules` 不再解析，
  数据补充链路（主行为入选 → 补入查询行为）删除；查询行为必须自身过阈值才入选。
- Q: 记录结构中「冗余部分」指什么？ → A: 线程侧车 `intent-focus.jsonl` 记录 + 追加给模型的
  提示文本；`tool_tips` 的 wire 结构不变。冗余指恒为常量或只写不读的字段：
  `behaviors[].kind` / `.selected` / `.source`、记录顶层 `functions` / `data_supplements`；
  记录 `behaviors` **只写入选行为**。
- Q: 配置键是否改名？ → A: **不改名**。`max_capabilities` 保留键名，语义变为「行为候选上限」；
  `ontology_threshold` 保留，语义变为「行为阈值」。
- Q: 非本体技能的处理是否变化？ → A: **不变**：仍只做技能级聚焦，只读 `SKILL.md` 头部，
  不读本体、不进入能力聚焦。

## 术语与口径

| 术语 | 定义 |
|---|---|
| **本体技能（Ontology Skill）** | 关联到当前数字人、且 `SKILL.md` 头部 `metadata` 中**同时**存在非空 `ontology_id` 与 `ontology_name` 的技能。 |
| **可聚焦技能（Focusable Skill）** | 当前数字人已关联并物化、且满足以下之一：① 非本体技能；② 本体技能且其 `ontology_id` 能匹配到至少一个已物化 `ontology.yaml`。 |
| **技能聚焦（Skill Focus）** | 结合用户输入与技能头部信息，用 Laya 逐个判定各「可聚焦技能」与用户意图的相关性，保留分数严格大于技能阈值的技能；非本体技能与本体技能使用同一评分口径。 |
| **入选技能（Focused Skill）** | 技能聚焦中分数严格大于阈值、被保留的技能。 |
| **本体能力（Ontology Capability）** | 本体文件 `behaviors[]`（行为）条目，判定只使用其 `name` 与 `title`。**2026-11-06 起不含 `functions[]`。** |
| **能力聚焦（Capability Focus）** | 对入选的**本体技能**所关联本体的行为逐个判定相关性，保留分数严格大于阈值的条目；非本体技能不进入本阶段。 |
| **规则与数据补充（已取消）** | 2026-11-06 起 `rules[]` 不再解析、`data_supplements` 不再补入；查询行为必须自身过阈值才入选。 |
| **意图聚焦提示（Intent Focus Prompt）** | 由技能聚焦与本体行为聚焦结果铸造、仅作用于本轮、追加进本轮补充素材的固定格式中文提示；非本体技能只有技能条目，本体技能另有技能说明与关联行为。 |
| **聚焦轮（Focus Round）** | 一次用户输入所触发的一轮意图聚焦，含技能聚焦、本体行为聚焦、去重与提示铸造；原工具聚焦不再参与。 |

**比较口径**：`ontology_id` / `scenario_id` 一律按**字符串归一化**后比较（去首尾空白；YAML 中的数字 `1` 与字符串 `'1'` 视为相同），避免同名不同型导致误判。
**阈值口径**：一律为「严格大于阈值才保留」（`score > threshold`），等于阈值即丢弃。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 技能聚焦：非本体技能与本体技能（优先级：P1）

某数字人已开启「意图聚焦」，关联了非本体技能与本体技能。用户发送一条输入后，系统只读取
每个 `SKILL.md` 的**头部**：非本体技能直接进入技能聚焦；本体技能先比对 `ontology_id`，
能匹配到已物化 `ontology.yaml` 的才进入技能聚焦，匹配不到的按原始需求不选中。随后系统
结合用户输入与技能头部的 `name`、`description`、`metadata`，用 Laya 逐个判定相关性，
只保留分数超过技能阈值的技能。非本体技能到此为止；本体技能继续进入行为 / 函数聚焦。
入选技能（含本体技能的聚焦说明与本体能力）写入本轮意图聚焦提示。

**为什么是这个优先级**：它是整条链路的入口，也是"非本体技能只聚焦技能文件"这一新口径的
落点。若技能识别或筛选错了，后面的行为与函数聚焦再准也没有意义。

**独立测试**：用 4 个技能（非本体技能 A、可匹配本体技能 B、`ontology_id` 无匹配本体的
本体技能 C、非本体但低分的 D）与桩评分实现跑一轮，断言：A、B、D 进入技能评分，C 不评分；
A 与 B 入选时，提示中 A 只有技能条目、B 有技能说明与本体能力；全程无工具候选评分调用。

**验收场景**：

1. **Given** 数字人关联了非本体技能 A 与本体技能 B（`metadata` 两者齐全且可匹配本体），
   **When** 发起一轮对话，**Then** A 与 B 都进入技能聚焦，A 不读取本体、不触发行为 / 函数聚焦。
2. **Given** 本体技能 B 的 `ontology_id` 为 `1`，该数字人已物化本体文件的
   `metadata.ontology_id` 为 `'1'`，**When** 识别，**Then** 因归一化后相同而判定为可聚焦本体技能。
3. **Given** 本体技能 C 的 `ontology_id` 为 `2`，该数字人所有本体文件中均无 `ontology_id = 2`，
   **When** 识别，**Then** C 不进入技能评分，并记录「无匹配本体」原因。
4. **Given** 3 个可聚焦技能分别得到 0.82 / 0.61 / 0.60，技能阈值为 0.6，
   **When** 技能聚焦，**Then** 只有前两个被保留（第三个等于阈值被丢弃），且按分数降序排列。
5. **Given** 本轮没有技能被保留，**When** 本轮继续，**Then** 不发起行为 / 函数聚焦，
   不追加任何意图聚焦提示，回答行为与未开启该功能时一致。
6. **Given** 非本体技能 A 入选，**When** 生成本轮提示，**Then** 提示只含 A 的技能说明，
   不含行为 / 函数段，且该轮本体读取次数与工具候选评分次数均为 0。

### 用户故事 2 - 本体行为聚焦（优先级：P1）

对每个入选的**本体技能**所关联的本体文件，系统提取 `behaviors[]` 的 `name` 与 `title`，
结合用户输入，用 Laya 逐个判定相关性，保留超过阈值的行为并写入本轮提示；
非本体技能不进入本阶段。**2026-11-06 起 `functions[]` 不再参与**。

**为什么是这个优先级**：技能只是"该看哪本本体"，真正指导本轮回答的是本体里的行为；
没有这一步，本体技能的聚焦只剩一个技能名，无法收敛到可执行的业务能力；而"技能说明"本身
也必须随本体行为一起出现，模型才知道这些能力属于哪个技能。

**独立测试**：构造含 3 个行为、2 个函数的本体，桩评分返回 0.9 / 0.5 / 0.6 / 0.8 / 0.8
（阈值 0.6），断言：只有 2 个行为入选（等于阈值的被丢弃）、函数不出题也不出现；
提示中只出现「关联行为」段且条目使用 `title（name）` 形式。

**验收场景**：

1. **Given** 入选的本体技能关联的本体含 `behaviors` 与 `functions`，**When** 能力聚焦，
   **Then** 只使用 `behaviors[].name` / `title` 作为判定素材，`functions` 不读取、不出题，
   也不读取行为描述正文或代码文件。
2. **Given** 行为 `CreatePurchaseRecord`（`title: 创建采购记录`）得分 0.9、行为 `QueryStock` 得分 0.5，
   **When** 阈值为 0.6，**Then** 只有 `CreatePurchaseRecord` 进入行为聚焦结果。
3. **Given** 两个技能关联同一个 `ontology_id`，**When** 本轮聚焦，
   **Then** 该本体文件只解析一次，行为评分结果被两个技能共享，不重复判定、不重复出现在提示中。
4. **Given** 本体中 `title` 缺失，**When** 生成聚焦结果，**Then** 以 `name` 兜底展示，不得出现空标题。
5. **Given** 本体中无 `behaviors`（或为空），**When** 本轮聚焦，
   **Then** 该本体零产出，不视为失败，其他本体照常处理。
6. **Given** 入选技能中只有非本体技能，**When** 本轮聚焦，
   **Then** 不发起任何本体行为判定，提示只含技能条目，结果与工具候选评分无关。

### 用户故事 3 - 规则不参与聚焦与行为去重（优先级：P2）

`rules[]` 与 `data_supplements` **不再参与**聚焦：规则既不用于补入查询行为，也不影响
阈值判定。所有行为（含查询行为）一律以自身分数与阈值决定是否入选；入选集合按
`ontology_id + name` 去重，跨本体同名各自保留。

**为什么是这个优先级**：它决定"聚焦结果从哪里来"——一旦规则仍能绕过阈值补入行为，
"只聚焦本体行为"的口径就不成立；去重则保证同一行为不会在提示与记录里重复出现。

**独立测试**：本体含行为 B1、B2、Q1、Q2 与规则 R1（`behavior: B1`，
`data_supplements: [Q1, Q2]`），只给 B1 高分。断言：入选集合只有 B1，Q1/Q2 **不出现**；
记录中不存在 `data_supplements` 字段。

**验收场景**：

1. **Given** `ontology.yaml` 含 `rules[]`，**When** 本轮聚焦，
   **Then** 规则不被解析，行为候选数等于 `behaviors[]` 条目数。
2. **Given** 行为 B1 入选且被规则 R1 声明 `data_supplements: [Q1]`、Q1 分数低于阈值，
   **When** 生成结果，**Then** Q1 **不**进入入选集合。
3. **Given** 行为 B1 同时被两条规则引用，**When** 生成结果，**Then** B1 只出现一次
   （去重键为 `ontology_id + name`）。
4. **Given** 同一 `ontology_id` 被物化成多份文件，**When** 构造候选，
   **Then** 同本体同名行为只出一题、不重复判定。
5. **Given** 同名行为分属不同本体，**When** 去重，**Then** 两项都保留，`ontology_id` 各不相同。

### 用户故事 4 - 提示绑定、替换旧方案与降级（优先级：P3）

技能聚焦与本体能力聚焦结果被铸造成固定格式的中文提示，追加到本轮补充素材末尾后进入主
模型；提示不进入历史、摘要、记忆与后续轮次，也不出现在用户可见界面。原工具聚焦不再执行。
功能关闭、预置动作入口、无关联技能、Laya 不可用或超时等情形下，用户仍得到正常回答。

**为什么是这个优先级**：它不产生新的业务能力，却决定"能否安全上线"——错误地污染历史、
把失败暴露给用户，或旧工具聚焦与新方案同时生效，代价远高于聚焦本身少给几条建议。

**独立测试**：开关关闭、卡片入口、无关联技能、Laya 超时四种情形各跑一轮，断言：
主模型照常回答；补充素材中没有意图聚焦提示；历史与摘要中没有相关文本；用户界面无异常；
旧工具候选评分调用次数为 0；四种情形均在同一条线程记录中留有可区分的处置结论。

**验收场景**：

1. **Given** 本轮技能聚焦结果非空，**When** 主模型调用前组装素材，
   **Then** 补充素材中**只追加一次**意图聚焦提示，位置在本轮补充素材末尾。
2. **Given** 技能聚焦结果为空，**When** 本轮继续，
   **Then** 不追加任何意图聚焦提示，补充素材与未开启该功能时逐字一致。
3. **Given** 连续两轮对话，**When** 第二轮组装素材，
   **Then** 第二轮不携带第一轮的意图聚焦提示；历史文件、滚动摘要与记忆中均无相关文本。
4. **Given** 数字人「意图聚焦」关闭，**When** 用户发送消息，
   **Then** 不解析技能头部、不读取本体、不调用 Laya、不新增聚焦记录。
5. **Given** 用户点击「下一步动作」或首屏问题实例卡片发送，**When** 本轮执行，
   **Then** 意图聚焦整体跳过，记录处置为「跳过」，卡片自带引导照常生效。
6. **Given** 数字人开启了「意图聚焦」且存在可用工具，**When** 本轮执行，
   **Then** 系统不再构造工具候选、不再调用 Laya 做工具评分，提示中也不出现原工具聚焦措辞。

### 边界情况

- **技能目录缺失 / 无关联技能**：聚焦阶段零产出，记录 `empty`（原因 `no_skills`），不改动本轮其他行为。
- **`SKILL.md` 缺失、不可读或 frontmatter 非法**：跳过该技能并记录原因，其余技能照常处理。
- **`metadata` 只有 `ontology_id` 或只有 `ontology_name`**：不视为本体技能；作为非本体技能仍 MUST 参与技能聚焦，仅使用技能头部。
- **`ontology_id` 为空白或仅空格**：按缺失处理，归一化后为空即不视为本体技能，按非本体技能处理。
- **只有非本体技能入选**：技能条目照常进入提示；本体读取、行为判定与工具候选评分次数均为 0。
- **本体技能未匹配到任何本体文件**：按原始需求第 3 条不选中、不评分；记录原因，不影响其他技能。
- **同一个 `ontology_id` 对应多个 `ontology.yaml`**：全部纳入，行为按 `ontology_id + name` 去重合并。
- **本体文件损坏、缺 `metadata` 或 `metadata.ontology_id` 为空**：跳过该本体并记录原因，不影响其他本体。
- **本体路径越界 / 符号链接逃逸**：拒绝读取并记录，MUST NOT 读取该数字人目录之外的文件。
- **用户输入为空或仅空白**：不发起聚焦（沿用既有发送校验）。
- **超长输入**：判定素材按 Laya 既有 200 字符上限截断，记录标注「已截断」；不影响本轮正常发送。
- **候选超限**：技能候选上限 32；行为候选上限 96、单批 ≤32；超限按本体原序截断并记录。
- **全部候选低于阈值**：技能或行为结果为空集，等价于该阶段零产出，不追加空提示或只有前缀的提示。
- **`ontology.yaml` 含 `rules[]` / `data_supplements`**：MUST 忽略，不解析、不补入、不写记录；行为候选数只由 `behaviors[]` 决定。
- **主行为入选但其查询行为分数低于阈值**：查询行为**不**入选（规则不再兜底）；这是 2026-11-06 的预期语义。
- **本体只有 `functions[]` 没有 `behaviors[]`**：该本体零产出，本轮不产生 `toolTips`，下一步动作卡片不产出。
- **同名行为分布在多个本体**：不合并（键含 `ontology_id`），各自保留并各自归属自己的本体。
- **本体文件在聚焦过程中被改动 / 删除**：按本轮读取到的快照继续，读取失败即降级该本体，不重试。
- **Laya 未配置 / 不可达 / 超时 / 响应结构非法 / 分数缺失**：该阶段静默降级，不追加提示，
  正常回答；原始错误进入结构化日志，MUST NOT 回退主对话模型。
- **存量工具聚焦配置仍然存在**：运行链路 MUST 忽略它，MUST NOT 再构造工具候选或做工具评分；
  仅保留配置解析的向后兼容，不产生任何工具聚焦行为。
- **并发发送**：同线程两轮各自独立聚焦与留档，MUST NOT 相互覆盖或串写提示。
- **本轮为重新生成 / 重试**：经同一发送链路重发，同样执行聚焦，不视为跳过。
- **记录写入失败**：回答不受影响，原始错误进入结构化日志（含线程标识与原因）。

### 关键实体

- **技能头部（Skill Header）**：`SKILL.md` frontmatter 的判定用字段。属性：`name`、`description`、`metadata.ontology_id`、`metadata.ontology_name`、`metadata.scenario_id`、`metadata.scenario_name`。
- **本体定义（Ontology Definition）**：一份 `ontology.yaml` 中与本特性相关的部分。属性：`metadata.ontology_id`、`metadata.ontology_name`、`behaviors[]`（`name`/`title`/`op_type`）。**`functions[]` / `rules[]` 不建模。**
- **技能聚焦结果（Skill Focus Result）**：单个可聚焦技能的判定结论。属性：技能 `name`、`description`、分数、是否本体技能、是否匹配本体、匹配的本体引用、是否入选、未入选原因。
- **本体行为项（Behavior Item）**：一条行为聚焦结果。属性：`name`、`title`、分数、来源本体。
- **意图聚焦记录（Intent Focus Record）**：单轮聚焦的留档，落在当前线程侧车记录内。属性：处置结论（已聚焦 / 空结果 / 跳过 / 降级 / 未配置）、原因、技能决策与分数、入选行为、提示原文、耗时。
- **意图聚焦提示（Intent Focus Prompt）**：由技能聚焦与本体能力聚焦结果铸造的中文提示，只作用于产生它的那一轮。

## 假设

- **与既有工具聚焦的关系（已澄清）**：本特性**全部替换** `013` 的工具聚焦，不是叠加；工具候选构造、工具评分与原工具聚焦提示全部停用。`013` 的开关、触发粒度、卡片跳过与上下文隔离口径沿用。
- **非本体技能口径（已澄清）**：非本体技能只做技能聚焦（只读 `SKILL.md` 头部），不做本体读取、不做行为聚焦、不做工具聚焦；入选后提示只含技能说明。
- **本体技能提示口径（已澄清）**：本体技能入选后，提示中必须先有该技能名，再列其本体行为；不能只列行为不列技能。
- **本体技能的判定口径**：`metadata` 中 `ontology_id` 与 `ontology_name` 必须**同时**存在且非空；仅凭 `ontology_id` 不足以认定为本体技能（与需求第 2 条一致）。
- **可聚焦口径**：非本体技能一律可聚焦；本体技能以 `ontology_id` 归一化后相等为门槛（需求第 3 条），匹配不到任何本体文件的按原始需求不选中、不评分。`ontology_name` 与 `scenario_name` 用于定位本体文件与展示，不额外收紧门槛。定位失败时允许在该数字人 `ontology/` 目录内按 `ontology_id` 查找。
- **ID 类型差异**：`SKILL.md` 中的 `ontology_id: 1` 与 `ontology.yaml` 中的 `ontology_id: '1'` 视为相同，一律字符串归一化比较。
- **候选来源**：只读该数字人**已关联并物化**的技能；技能头部的 `name`、`description` 与 `metadata` 参与技能评分，技能正文不参与；非本体技能不构造本体字段。
- **阈值**：技能阈值沿用 `INTENT_FOCUS_SKILL_THRESHOLD`（语义由工具阈值改为技能阈值），本体行为阈值使用 `INTENT_FOCUS_ONTOLOGY_THRESHOLD`，两者缺省均为 **0.8**（2026-11 产品口径，替换原先的 0.6 标定）；阈值区间校验只在 `config.ts` 一处，domain 层不再做归一；本期不新增管理台开关。
- **评分方式**：技能判定与本体行为判定**都使用 `noul` 模式**——每个候选（技能 / 行为）各一条真值命题，题与题互不竞争，可同时命中多个；按绝对阈值筛选，不使用 `choice`，不依赖模型生成自然语言；候选按批串行提交。
- **提示格式**：中文编号清单（首行前缀 `本轮的任务与以下技能或本体行为密切相关，请重点关注（仅供参考，不必局限）`，其后每个入选技能一行 `n）…`）。本体技能为 `{name}（本体技能；ontology_name='…'，ontology_id='…'；关联行为：{title}（{name}）、…）`，非本体技能为 `{name}（非本体技能）`；无入选行为时省略该段，最多 1200 字符；`name` / `title` 保留原文不翻译，`description` 不进入提示；MUST NOT 出现「关联函数」。
- **失败语义**：任一阶段失败等价于该阶段零产出，用户不可见，原始错误进结构化日志；与 `013` 的静默降级同口径。
- **记录形态**：复用 `013` 的线程侧车记录文件与滚动上限；记录主体为技能决策 + **入选行为**，原工具字段与 `functions` / `data_supplements` 不再写入。
- **性能预算**：聚焦阶段（技能评分 + 行为评分）共享独立总预算 ≤ 10 秒；原工具聚焦停用后不再产生第二段串行等待。
- **范围边界**：只涉及 `agent-backend` 的运行期链路与运行环境配置；不改管理平台页面、接口与部署产物格式。
- **用户前提**：单用户工作台上下文，具备稳定本站连接；网络中断按降级处理。
