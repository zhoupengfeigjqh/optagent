# 功能规格：聊天页头部对齐与空数据新手引导

**Feature Branch**: `014-chat-onboarding-hint`

**Created**: 2026-10-29

**Status**: 已评审（2026-10-29）

**Input**: User description: "1 agent聊天页面，上方展示的MCP服务的连接情况的展示，与数字人的切换按钮左对齐；2 增加新手引导：满足（1）用户文件空间里有数据准备、（2）数据准备里每个非预定义的二级目录都为空、（3）用户切换数字人后 三个条件时，在上传文件的「+」上自动出现气泡提示「当前您还没有准备数据，请点击 “+” 上传吧。」，气泡右上角有 × 可关闭；关闭后直到用户下一次切换数字人后才重新进行条件判断。"

## 用户场景与测试 *(mandatory)*

### 用户故事 1 - 空数据时主动提示上传（Priority: P1）

新用户切换到某个数字人后，该数字人的「数据准备」空间里没有任何可用的业务数据。此时界面在上传文件的「+」入口上主动冒出一句引导气泡，告诉用户"还没有准备数据，点 + 上传"，用户顺着提示就能完成第一次上传，不必自己猜测数据该放哪里。

**为何优先级最高**：这是本需求真正的业务价值——把"下一步该做什么"直接送到用户眼前，减少首次使用时的空转与求助。

**可独立验证**：只需一个已配置场景、且「数据准备」下非预定义目录全空的数字人，切换后观察「+」上是否出现气泡；不依赖头部对齐改动。

**验收场景**：

1. **Given** 数字人 A 的「数据准备」存在且其所有非预定义二级目录均为空，**When** 用户从其它数字人切换到 A 且切换成功，**Then** 在「+」上传入口上出现气泡，内容为「当前您还没有准备数据，请点击 “+” 上传吧。」，气泡右上角带一个关闭按钮「×」。
2. **Given** 气泡正在展示，**When** 用户点击气泡右上角的「×」，**Then** 气泡立即消失，且在当前这次数字人选择下不再自动出现。
3. **Given** 用户已关闭过气泡，**When** 用户切换到另一个同样满足条件的数字人 B，**Then** 针对 B 重新进行条件判断，气泡重新出现。
4. **Given** 气泡正在展示，**When** 用户点击「+」进入上传流程并成功上传一个文件，**Then** 气泡自动消失（引导已不再符合事实），无需用户再点「×」。
5. **Given** 气泡正在展示，**When** 用户点击「+」，**Then** 上传菜单照常打开，气泡不拦截、不遮挡该入口。

---

### 用户故事 2 - 头部 MCP 状态与切换按钮左对齐（Priority: P2）

用户在聊天页顶部先看到「切换」按钮，其下方（或右侧）是数字人名称与各 MCP 服务的连接状态。当前这段 MCP 状态的左边缘相对「切换」按钮存在明显缩进，视觉上像是挂在名称下面的一截内容；对齐后，头部左侧形成一条统一的视觉基准线，扫视更顺畅。

**为何优先级次之**：属于界面整洁度与可读性改进，不阻塞任何业务动作，但直接影响"这一屏是否显得专业"。

**可独立验证**：给定任意一个已选中、已配置多个 MCP 服务的数字人，测量「切换」按钮与 MCP 状态区域左边缘是否落在同一垂直基准线上；不依赖新手引导改动。

**验收场景**：

1. **Given** 已选中数字人且该数字人有 1 个及以上 MCP 服务状态，**When** 打开聊天页，**Then** MCP 状态区域（首个服务状态项）的左边缘与「切换」按钮的左边缘对齐。
2. **Given** 数字人名称很长、MCP 服务数量较多需要换行，**When** 头部渲染，**Then** 对齐关系不因换行或内容变长而破坏，右侧动作按钮位置不受影响。
3. **Given** 尚未选中数字人，**When** 查看头部，**Then** 仅显示"请选择数字人"提示、不出现 MCP 状态区域（沿用既有行为，不因本次对齐产生空容器或多余留白）。

---

### 边界情况

- **未选中数字人**：不触发引导气泡（没有文件空间视角，也无从判断空数据）。
- **数字人未配置场景 / 文件空间清单加载失败**：不弹引导气泡；既有错误提示照常呈现，引导不得掩盖或替代错误。
- **「数据准备」下只有平台预定义目录（算法规则）**：视为"没有可上传业务数据的目录"，不弹气泡（避免把用户引向规则目录误传业务数据）。
- **预定义目录（算法规则）里有文件、非预定义目录全空**：仍弹气泡——判断只看非预定义目录。
- **非预定义目录里只有空文件（0 字节）**：只要有文件即视为非空，不弹气泡。
- **切换数字人失败**：保持原数字人与原界面状态，不进行条件判断、不弹气泡。
- **重新选择当前数字人**：不算一次切换（不判定、不重置关闭状态）。
- **切换后清单仍在加载**：等清单就绪后再判定，避免用上一个数字人的数据误判；加载期间气泡不闪现。
- **气泡展示期间再次切换数字人**：先收起当前气泡，再按新数字人重新判定。
- **气泡文案中的「+」**：指界面上真实存在的上传入口，文案固定，不随后端配置或模型输出变化。
- **窄屏 / 大字号**：气泡不溢出可视区域、不遮挡「+」与发送按钮，文本可换行且完整可读。
- **键盘与读屏用户**：可聚焦到关闭按钮并用 Enter/Space 关闭；气泡内容可被读屏识别为提示信息。

## 需求 *(mandatory)*

### 功能需求

**头部对齐**

- **FR-001**：聊天页头部展示的 MCP 服务连接状态区域，其左边缘 MUST 与数字人「切换」按钮的左边缘落在同一条垂直基准线上（视觉偏差不超过 1 像素）。
- **FR-002**：对齐调整 MUST NOT 改变头部既有信息顺序与层级（切换按钮 → 数字人名称 → MCP 状态），MUST NOT 移除或重排右侧搜索、工作空间等动作入口。
- **FR-003**：数字人名称过长或 MCP 服务较多时，MUST 保持 FR-001 的对齐关系，且不得挤压右侧动作入口或产生横向溢出。
- **FR-004**：未选中数字人时，头部 MUST NOT 渲染 MCP 状态区域（沿用既有口径），仅保留"请选择数字人"提示。

**新手引导触发条件**

- **FR-005**：引导判定 MUST 仅在"用户成功切换数字人"之后触发一次；页面首次加载、刷新、以及数字人未变化时的任何操作 MUST NOT 触发。
- **FR-006**：判定 MUST 在新数字人的文件空间清单加载完成后进行；清单未就绪或加载失败时 MUST NOT 弹出气泡。
- **FR-007**：条件一——文件空间中存在「数据准备」空间。不存在时判定为不满足。「数据准备」MUST 以结构特征识别（唯一拥有二级目录清单的空间），MUST NOT 硬编码空间名。
- **FR-008**：条件二——「数据准备」下的**每个非预定义二级目录**的文件清单均为空。"非预定义目录"指该数字人场景中除平台预定义目录（算法规则）以外、由管理员配置的二级目录；预定义目录的内容 MUST NOT 参与该判定。该「预定义」标记 MUST 由文件空间清单随目录下发，前端 MUST NOT 硬编码目录名。
- **FR-009**：若「数据准备」下不存在任何非预定义二级目录，则条件二判定为不满足，MUST NOT 弹出气泡。
- **FR-010**：三个条件（FR-007、FR-008/FR-009、FR-005 的切换事件）同时满足时，MUST 在上传文件的「+」入口处展示引导气泡，文案精确为：`当前您还没有准备数据，请点击 “+” 上传吧。`
- **FR-011**：条件不满足任一项时，MUST NOT 展示气泡，且 MUST NOT 以其它形式（toast、横幅、角标）替代提示。

**气泡交互**

- **FR-012**：气泡 MUST 锚定在「+」上传入口附近（按钮上方或侧上方），MUST NOT 覆盖「+」按钮本身、模型选择、思考开关与发送按钮，且在窄屏下不溢出可视区域。
- **FR-013**：气泡右上角 MUST 提供「×」关闭入口；点击「×」只关闭气泡，MUST NOT 触发上传菜单或发送动作。
- **FR-014**：用户关闭气泡后，在当前这次数字人选择下 MUST NOT 再次自动出现，直到用户下一次成功切换数字人；每次成功切换 MUST 重置关闭状态并重新判定。
- **FR-015**：气泡展示期间若条件失效（例如用户上传文件后非预定义目录不再全空），气泡 MUST 自动消失，无需用户手动关闭。
- **FR-016**：气泡展示 MUST NOT 阻断「+」入口：用户仍可直接点击「+」打开上传菜单并完成上传。
- **FR-017**：气泡 MUST 可被读屏识别为提示信息；关闭入口 MUST 具备可读的无障碍名称，并支持键盘聚焦与操作；动效 MUST 在用户偏好减少动效时降级为静态呈现；提示语义 MUST NOT 仅依赖颜色传达。

**降级与一致性**

- **FR-018**：文件空间清单加载失败、场景未配置或数字人切换失败时，引导 MUST 静默不出现；既有错误提示与重试入口 MUST 保持原样，不得被引导逻辑吞掉或改写。（与 FR-006 同源的失败路径：FR-006 约束判定时机，本条约束降级行为。）
- **FR-019**：气泡文案 MUST 是界面固定常量，MUST NOT 取自数字人配置或模型输出。

### 关键实体

- **数字人切换事件**：一次成功的数字人变更，是引导唯一的触发点，也是关闭状态的重置点。
- **文件空间清单**：某数字人视角下的三空间（数据准备 / 共享空间 / 临时空间）与各二级目录的文件列表，是条件一、条件二的判断依据。
- **数据准备二级目录**：分为平台预定义目录（算法规则，恒存在、不可移除）与管理员配置的非预定义目录；只有后者参与空数据判定。
- **引导气泡状态**：本次页面会话内"未判定 / 展示中 / 已关闭"三种状态；已关闭只对当前数字人选择有效，切换数字人即失效。

## 成功标准 *(mandatory)*

### 可量化结果

- **SC-001**：满足全部条件并成功切换数字人后，1 秒内即可看到引导气泡（清单加载耗时除外）。
- **SC-002**：在"未选中数字人""场景未配置""清单加载失败""仅剩预定义目录""非预定义目录已有文件"五类场景下，误弹率为 0。
- **SC-003**：用户关闭气泡后，到下一次切换数字人之前，气泡复现次数为 0；下一次切换到同样满足条件的数字人时，出现概率为 100%。
- **SC-004**：气泡展示时点击「+」，上传菜单打开成功率 100%；上传成功后 1 秒内气泡自动消失。
- **SC-005**：在常用桌面宽度（1280、1440、1920）下，MCP 状态区域与「切换」按钮的左边缘视觉偏差不超过 1 像素。
- **SC-006**：仅使用键盘即可完成"聚焦关闭按钮 → 关闭气泡 → 打开上传菜单"的完整操作，且读屏能读到气泡文案与关闭按钮名称。

## 假设

- **预定义目录的口径**：沿用平台既有的「算法规则」为唯一预定义二级目录；其余由管理员在场景中配置的目录一律视为非预定义目录。
- **关闭状态的保留范围**：关闭行为只保留在当前页面会话期间，不跨浏览器标签页、不跨刷新保留；刷新后需再次切换数字人才会重新判定（与"条件三"一致）。
- **文件即数据**：只要二级目录下存在任意文件（包括 0 字节文件）即视为"非空"；不递归统计更深层目录。
- **数据来源的边界**：不新增接口、不新增存储；文件空间清单已同时提供目录与文件列表，本次仅为其目录项增加一个只读的「预定义」标记，用于条件二判定。
- **对齐不改变信息架构**：本次只调整视觉基准线，不重新设计头部布局，也不新增/删除任何头部入口。
- **影响范围**：改动限于对话工作台（聊天页头部与输入区上传入口），管理后台与数字人部署语义不受影响。
