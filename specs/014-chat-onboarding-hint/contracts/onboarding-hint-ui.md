# 界面契约：空数据新手引导气泡

**Feature**: `014-chat-onboarding-hint` | **Date**: 2026-10-29

本契约描述气泡的**用户可见行为**，不约束内部实现。任何实现都必须满足以下可观察行为。

## 1. 触发

| 项 | 规定 |
|---|---|
| 触发事件 | 用户**成功**切换数字人（切换到同一数字人不算，切换失败不算） |
| 判定时机 | 新数字人的文件空间清单加载完成后（加载中、加载失败、场景未配置都不判定） |
| 其他事件 | 页面首次加载、刷新恢复、发送消息、打开工作空间、上传、删除文件都**不**触发判定 |
| 条件一 | 文件空间中存在「数据准备」空间 |
| 条件二 | 「数据准备」下**每个非预定义二级目录**的文件清单均为空；没有非预定义目录时视为条件不满足 |
| 条件三 | 上述触发事件刚刚发生 |

三条件同时成立才展示；任一不成立则不展示，且不以外观替代（无 toast、无横幅、无角标）。

## 2. 文案

固定常量，逐字一致（含中文引号）：

```text
当前您还没有准备数据，请点击 “+” 上传吧。
```

- 不取自数字人配置、模型输出或服务端文本。
- 不因数字人、场景、语言环境变化。

## 3. 位置与外观

- 锚定在上传入口「+」附近（按钮上方或侧上方）。
- MUST NOT 覆盖「+」按钮、模型选择、思考开关、发送按钮。
- 窄屏或大字号下不溢出可视区域，文本可换行且完整可读。
- 右上角有「×」关闭入口。

## 4. 交互

| 用户动作 | 结果 |
|---|---|
| 点击「×」 | 气泡消失；当前数字人选择下不再自动出现 |
| 点击「+」 | 上传菜单照常打开（气泡不拦截点击、不遮挡入口） |
| 上传成功后 | 气泡自动消失（条件不再成立），无需点「×」 |
| 气泡展示时再次切换数字人 | 先收起旧气泡，按新数字人重新判定；若仍满足则继续展示 |
| 关闭后再次切换数字人 | 重新判定；满足则重新出现 |
| 关闭后上传、删除、重载清单 | 不重新出现（直到下一次切换数字人） |

气泡自身不发起任何网络请求，不改变文件空间数据。

## 5. 无障碍

- 气泡文本可被读屏识别为提示（`role="status"`），关闭入口是原生按钮并具备可读名称（如「关闭提示」）。
- 可用键盘完成：Tab 聚焦关闭按钮 → Enter/Space 关闭；焦点可见。
- 提示语义不依赖颜色；`prefers-reduced-motion` 下动效降级为静态。
- 关闭后不强制转移焦点到其它控件（避免打断当前输入）。

## 6. 降级

- 清单加载失败 / 场景未配置 / 切换失败：不展示气泡；既有错误提示与重试入口保持原样，不被引导逻辑吞掉或改写。
- 判定所需字段缺失（例如服务端未下发 `predefined`）：按"不满足条件"处理，宁可不提示，也不误判为"无数据"。

## 7. 非目标

- 不在工作空间抽屉、`@` 引用面板或上传菜单内重复提示。
- 不做"忽略后永久不再提示"的持久化偏好。
- 不改变上传菜单的目录结构、可上传类型与既有错误文案。
