# 特性规格：聊天区粘贴上传（2026-11-17）

**特性编号**：023　**状态**：已实现（v1.3）　**影响侧**：frontend（无后端与契约变更）

## 1. 目标

在聊天区输入框支持「复制 / 粘贴」上传文件与图片（含截图）。粘贴没有"选目录"这一步，因此目标**固定临时空间**；并且**发送之前不落盘**——粘进来的文件只活在内存里，用户真的点了发送才写进临时空间，名字由"临时空间现存 + 本条消息已有"共同决定，重名自动加序号，全程不打断用户。

## 2. 用户故事

**US1**：作为用户，我截了图/复制了文件后直接在输入框 `Ctrl+V` 就能带上它，不必先点「+」再在目录树里挑位置。

**US2**：作为用户，我粘错了、改主意了，只要不发送，文件空间里就不会多出任何垃圾。

**US3**：作为用户，我反复粘同名的截图，不希望被弹窗打断，也不希望临时空间里两个文件分不清谁是谁。

## 3. 功能需求

| 编号 | 需求 |
|---|---|
| **FR-001** | 仅当剪贴板含 `kind === 'file'` 项时才走粘贴；**纯文本粘贴的既有行为（按纯文本插入）MUST 一字不变**；输入区处于发送中禁用态时 MUST 不处理。 |
| **FR-002** | 目标空间 MUST 固定为 `临时空间`（扁平空间根），MUST NOT 弹目录选择、MUST NOT 写入数据准备或共享空间。 |
| **FR-003** | **未发送不落盘**：粘贴阶段 MUST NOT 发起任何上传请求、MUST NOT 在磁盘上创建文件；文件只以内存 `File` 的形式挂在输入区。 |
| **FR-004** | 粘贴时的校验 MUST 覆盖三项：扩展名 ∈ 临时空间 `upload_extensions`、单文件 ≤ 5MB、单条消息引用数 ≤ 10。**MUST NOT 检查磁盘重名**（那时没有清单可比，也没有必要）。 |
| **FR-005** | **逐文件取舍**：合格的文件立刻挂成胶囊，不合格的**跳过**并由一条 toast 汇总说明（最多列 3 个文件名及原因；部分收下时 MUST 说明"已附加 N 个，M 个未附加"）。MUST NOT 因个别文件不合格而整批作废（v1.2 口径作废：既然没有半成品落盘，就没有原子性理由）。 |
| **FR-006** | 呈现 MUST 复用「+」上传的胶囊链路（`FileReference` + `@标记`），但**不打开上传面板**、MUST NOT 建上传记录（面板没开，记录一旦出现就是"自己没点过的成功行"）；反馈只走 toast。 |
| **FR-007** | 白名单未就绪时 MUST 先加载 workspace；仍取不到临时空间或其白名单为空 → 提示「文件空间尚未就绪」，不挂胶囊（MUST NOT 以空名单放行，那等于跳过格式校验）。 |
| **FR-008** | 剪贴板文件无扩展名时 MUST 按已知 MIME 补名（`粘贴-<时间戳>-<序号>.<ext>`）；MUST NOT 因补名放行白名单外类型（如 `image/svg+xml` 不映射 `.svg`）。 |
| **FR-009** | 剪贴板同时含文件与文本（图文混贴）时 MUST 只处理文件，MUST NOT 把同一段文字再插入正文。 |
| **FR-010** | 胶囊标记 MUST 显示**原始文件名**。当它与**本草稿里看得见的已有胶囊**（含「+」上传、`@` 面板选中的真实文件）或同批粘贴件重名时，MUST 就地改成 `原名(n).ext`——两个同名标记会让"删掉一个"连带删掉另一个（标记匹配按文本）。**看不见的引用（文本里没有它的 `@标记`，例如别的会话残留）MUST NOT 参与占名**。磁盘重名不在此时检查（见 FR-012）。 |
| **FR-011** | 落盘时机 MUST 在发送链路中**所有拦阻性检查之后**（正文非空 → 引用有效 → 018 术语替换确认 → MCP 就绪）、**`threads.create()` 之前**、`chat.send` 之前——建会话会让会话 id 由 `null` 变真 id，而待发件按会话分桶（FR-016），换桶之后再取就取不到，消息会带着"线上不存在或同名旧文件"的引用发出去。任一文件上传失败 → **整条中止**：MUST NOT 发出消息，草稿、胶囊、内存文件 MUST 原样保留，并 toast 列出失败项与原因；用户再次发送即整批重试，**已落盘的文件 MUST 复用上次的服务端真名**（不得在临时空间留下第二份）。 |
| **FR-012** | 发送时命名：待发件的候选名 MUST 对照「临时空间现存文件」+「本条消息中其他引用」+「本批内部已分配」去重，重名用 `原名(n).ext`（半角括号、紧贴主名、编号在扩展名前、从 1 起、比对大小写不敏感；`a.tar.gz` ⇒ `a.tar(1).gz`）。候选名 MUST 作为上传请求的 filename；**唯一权威是服务端返回的 `filename`**，附件载荷与气泡 MUST 都用它（前端候选取不到清单时更保守，服务端再加一层序号属正常兜底）。 |
| **FR-013** | 发送成功后胶囊清空、文件留在临时空间归用户所有；**MUST NOT 有任何自动删除**（v1.2 的 30 秒冷却回收整条作废）。 |
| **FR-014** | 未发送就删掉胶囊（点 `x` 或退格删标记同口径）、点「新建对话」、切换数字人、刷新页面 → 内存文件 MUST 直接丢弃；MUST NOT 发删除请求、MUST NOT 提示（磁盘上本来什么都没有，丢掉等于"没粘过"）。**切换会话不是丢弃**：各会话的待发件各自保留，切回来仍可直接发送（见 FR-016）。 |
| **FR-015** | MUST NOT 弹出任何"文件名重复"确认（v1.2 的重名弹窗作废）。 |
| **FR-016** | **会话隔离**：文件引用与粘贴待发件 MUST 按会话分桶，规则与输入区草稿一致（切走存、切回取、`null` 视图态新对话不建桶、桶数有上限）。**自动建会话（首条消息 `null → 真 id`）MUST 视为"接管"而非"切换"**：当前这批引用与待发件随该条消息走，MUST NOT 被清空。目的：①会话 2 粘贴同名文件不得因会话 1 的残留而多加 `(1)`；②看不见的残留引用 MUST NOT 被当成附件发送。 |

## 4. 验收场景

1. 粘贴 1 张截图 → 输入区出现 `@image.png` 胶囊 → **临时空间里此刻还没有这个文件**；点发送后才出现，气泡显示同名。
2. 粘贴 3 个文件（含 1 个 `.exe`）→ 两个进胶囊、`.exe` 被跳过；toast 说明"已附加 2 个文件，1 个未附加：xx.exe（格式不支持）"。
3. 粘贴 6MB 图片 → 跳过并说明「文件超过 5MB」，其余文件照常进胶囊。
4. 复制纯文字粘贴 → 行为与上线前一致（不触发上传）。
5. 发送中粘贴 → 无反应、无请求。
6. 已 `@` 了面板里的 `plan.csv`，再粘一个 `plan.csv` → 粘贴件胶囊显示 `plan(1).csv`；删其中一个胶囊不会连带删掉另一个。
7. 临时空间里已有 `报告.csv`，粘一个 `报告.csv` 并发送 → 落盘为 `报告(1).csv`，气泡显示 `报告(1).csv`。
8. 粘贴后删掉胶囊 → 不发任何请求，临时空间无变化。
9. 粘贴后发送失败（如断网）→ 消息未发出、草稿与胶囊都在；恢复后再次发送成功，临时空间只有一份文件。
10. 粘贴后不发送直接切数字人/刷新 → 胶囊消失，临时空间无新文件。
11. 通过「+」上传到临时空间 → 行为不变（立即落盘、服务端重名自动加序号、无弹窗）。
12. **新对话**（尚未建会话）粘贴 1 个文件 → 点发送 → 文件正常落盘为 `报告(1).csv`（若临时空间已有同名），气泡显示该名；消息 MUST NOT 冒用临时空间里的同名旧文件。
13. 会话 1 粘贴 `a.csv`（不发送）→ 切到会话 2 → 再粘 `a.csv` → 会话 2 的胶囊显示 `a.csv`（**不带** `(1)`）；此时在会话 2 发送 → 只上传这一份；切回会话 1 → 胶囊与文件都还在，可直接发送。

## 5. 边界

- jsdom 没有真实剪贴板：单测用桩对象构造 `paste` 事件；真实链路需手工验收（Win+Shift+S 截图、资源管理器复制多文件、Word 图文混贴、超限与黑名单扩展名）。
- 服务端仍是权威：客户端预演名可能被服务端再改一次（并发写同名文件）；界面一律取响应里的 `filename`。
- 命名规则在前后端各有一份实现（前端 `utils/upload-name.ts` 只做预演、后端 `domain/upload-name.ts` 才是唯一权威）。**风险登记**：两处必须同改；前端按大小写不敏感比对，在大小写敏感的 Linux 上只是更保守（多改一次名），不会造成真实冲突。
- 前端取不到最新清单（`GET /api/files/list` 失败）时回退 workspace 缓存，可能比磁盘旧一秒；后果仅是服务端再套一层序号，不会覆盖已有文件。
