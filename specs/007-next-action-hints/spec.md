## 原始输入（用户需求，逐字保留）

> 1 每一轮交互完毕，LLM会在输出末尾，换行：输出一句话，您接下来可以操作以下动作，请选择
> 2 每个动作为一个卡片（类似首页欢迎下的问题实例（快速上手），包含调用某个或几个工具的信息），点击后有个确认弹窗，然后发送消息到聊天区进行下一轮的对话
> 3 卡片上为依据简洁的提示词（如调用xxx工具进行xxx操作，注意都是中文，不要工具英文名哈），控制在50字内。提示词背后包含工具信息（不展示，类似问题实例卡片）
> 4 卡片提示词为LLM根据上下文生成的下一步任务提示词，##严格遵守全部中文、意图清晰简洁、包含关联工具（工具不展示出来）###
> 5 生成提示词的上下文有：当前问题的输入和输出，已调用工具，当前数字人可调用的全部工具基本信息，让LLM输出0~3个下一步任务的提示词，每个提示词输出为一个卡片提示词，展示在聊天结果的下方（类似豆包输出的用户建议卡片，点击即可发送消息）
> 6 LLM也可以不输出下一步的工具，比如用户的目标已达到，用户进行无关任务的闲聊等，此时LLM输出任务可以为空
> 7 这个功能需要有一个按钮作为开关，放在数字人管理平台的数字人管理里的SOUL里，作为一个开关命名为，是否开启下一步动作提示。若关闭，则部署后该功能消失，开启后该功能生效。
> 8 输出结果如果报错等，请降级处理不输出下一步提示。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 每轮回答结束后出现下一步动作卡片（优先级：P1）

用户与数字人完成一轮对话（提问 → 回答）。回答正文的末尾下方出现若干张"下一步动作"卡片，
每张卡片是一句可直接点击的中文指令（≤50 字），引导用户继续推进任务。

**为什么是这个优先级**：这是功能本体，也是最小可用切片——即使还不能点击发送，
"回答之后告诉我下一步能做什么"已经产生价值；后续故事都在此之上叠加。

**独立测试**：以桩模型固定返回 2 条提示，走完一轮对话，断言：
回答正文下方按顺序出现 2 张卡片；引导句出现在正文末尾；卡片文本为中文且 ≤50 字；
正文、工具记录、视图入口与改造前逐字一致。

**验收场景**：

1. **Given** 某数字人已开启本功能且本轮成功回答、模型判定有 2 条下一步动作，
   **When** 本轮回答完成，**Then** 回答正文下方按顺序出现 2 张卡片，每张卡片文本为该提示词全文。
2. **Given** 模型判定无需下一步（目标已达成、闲聊等），
   **When** 本轮回答完成，**Then** 不出现任何卡片，也不出现引导句，界面与未开启该功能时一致。
3. **Given** 本轮回答为失败轮（模型报错 / 中断 / 输出为空），
   **When** 该轮结束，**Then** 不出现卡片与引导句，用户只看到正常的失败提示。
4. **Given** 已渲染的卡片，**When** 检查其文本，**Then** 全部为中文、不含任何工具英文名或工具标识符、长度 ≤50 字。
5. **Given** 会话内已展示数字人 A 的卡片，**When** 用户把当前数字人切换为 B，**Then** A 的卡片不再展示（该会话返回空），MUST NOT 存在"A 的卡片被点击后把 A 的工具引导注入 B 的一轮"的路径。

### 用户故事 2 - 点击卡片经确认后发起下一轮（优先级：P2）

用户点击某张卡片，弹出二次确认弹窗（展示该提示词全文），
确认后该提示词作为一条用户消息发送到聊天区，开启下一轮对话。

**为什么是这个优先级**：这是卡片真正产生"推进任务"效果的一步；但它依赖故事 1 先有卡片，
故排在故事 1 之后。

**独立测试**：渲染 1 张卡片 → 点击 → 断言弹窗出现且**未**发送任何消息 → 确认 →
断言聊天区新增一条以该提示词为内容的用户消息，并触发新一轮。

**验收场景**：

1. **Given** 回答下方有卡片，**When** 用户点击其中一张，**Then** 弹出确认弹窗，弹窗内展示该卡片提示词全文，提供"发送 / 取消"。
2. **Given** 确认弹窗已打开，**When** 用户点击"取消"或按 `Esc`，**Then** 弹窗关闭且**未**发送任何消息。
3. **Given** 确认弹窗已打开，**When** 用户确认发送，**Then** 聊天区出现一条内容等于该提示词的用户消息，并开始新一轮对话。
4. **Given** 卡片关联了工具信息，**When** 查看卡片与已发送的用户消息，**Then** 均**不**展示任何工具名。
5. **Given** 未选中数字人（或会话不可用），**When** 用户点击卡片，**Then** 明确提示不可发送，且不产生会话残留。

---

### 用户故事 3 - 管理台开关与部署生效（优先级：P2）

管理员在数字人管理的 SOUL 配置里打开"是否开启下一步动作提示"，保存并部署后，
该数字人在聊天前台开始产生卡片；关闭并重新部署后，该功能在该数字人上消失。

**为什么是这个优先级**：开关是功能上线与回滚的唯一开关闸；没有它，功能无法按数字人灰度。

**独立测试**：管理台打开开关并保存 → 断言设计态与部署产物均带该开关的开启值 →
在开启与关闭两种部署产物下各跑一轮对话，断言卡片分别出现 / 不出现。

**验收场景**：

1. **Given** 管理台数字人 SOUL 配置页，**When** 查看配置项，**Then** 存在名为"是否开启下一步动作提示"的开关。
2. **Given** 开关从关闭改为开启并保存、部署，**When** 在聊天前台与该数字人对话，**Then** 回答后出现卡片。
3. **Given** 开关开启改为关闭并保存、部署，**When** 在聊天前台与该数字人对话，**Then** 不再出现卡片与引导句。
4. **Given** 开关为关闭，**When** 观察该数字人的一轮对话，**Then** 不产生任何为生成提示而发起的额外模型调用。

---

### 用户故事 4 - 附加能力失败不打扰用户（优先级：P3）

提示生成环节的任何失败（模型调用失败、超时、输出格式非法、提示词不合规、工具清单不可用）
都不影响本轮回答，也不向用户报错；原始错误进入结构化日志供排查。

**为什么是这个优先级**：在故事 1 的链路上加一道"失败即静默"的护栏，是可用性底线，
但它只在异常路径上被观察到。

**独立测试**：让生成链路分别注入"调用抛错 / 超时 / 返回非法结构 / 返回 5 条超限与含英文名的条目"，
断言四种情况下用户端均无卡片、无引导句、无错误提示，本轮回答展示正常，且日志中各有对应记录。

**验收场景**：

1. **Given** 生成链路超时，**When** 本轮回答完成，**Then** 用户端无卡片、无引导句、无报错；本轮回答与工具记录照常展示。
2. **Given** 生成链路返回 5 条（超上限）且其中有条目含工具英文名或超过 50 字，
   **When** 该结果被采用，**Then** 只展示不超过 3 条合规条目，不展示违规条目。
3. **Given** 生成链路全部条目均不合规，**When** 该结果被采用，**Then** 不展示任何卡片与引导句。

### 边界情况

- **失败轮与中断轮**：模型报错、连接中断、用户中止的轮次一律不生成、不展示提示。
- **回答为空**：回答正文为空（无内容）的轮次视为不产出提示。
- **超限与重复**：模型给出超过 3 条时只保留前 3 条；提示词为空、超 50 字、含英文工具名或与其它卡片重复的条目一律丢弃，其余照常展示。
- **工具引用越界**：卡片关联的工具不在该轮真实装配的可用清单内时，丢弃该工具引用；**裁剪后已无任何有效引用的条目 MUST 整条丢弃**（MUST NOT 作为"无工具卡片"下发，见 FR-009），其余条目照常展示。
- **无可用工具的数字人**：该轮不产出任何下一步动作提示（等价于"本轮无卡片"，见 FR-009）；提示词本身仍 MUST NOT 提到工具（FR-003）。
- **模态竞争**：任一时刻同一会话最多只有一轮卡片；用户在提示出现前又发了一条消息时，上一轮的提示作废。
- **未产出即清空**：新一轮产出 0 条（含生成失败降级）时，上一轮卡片 MUST 立即消失，MUST NOT 继续展示过期引导。
- **刷新与重进**：刷新页面或重进该会话后，最新一轮的卡片 MUST 仍可见、可点击；历史轮次的位置 MUST NOT 出现卡片。
- **未选数字人 / 会话被删**：点击卡片被拒绝并给出可感知提示，不产生残留会话。
- **重复点击**：确认弹窗已打开或发送进行中时，再次点击不重复发送。
- **数字人切换**：会话**不绑定**数字人且可跨数字人（既有行为），故卡片 MUST 与**产生它的那个数字人**绑定：当前选中数字人与卡片归属数字人不一致时，MUST NOT 下发、MUST NOT 展示（见 FR-019），从而不存在"A 的卡片被点击后把 A 的工具引导注入 B 的一轮"的越权路径。切回该数字人后可重新展示。
- **开关关闭后的历史会话**：关闭并重新部署后，该数字人在任何会话中都不得再展示提示（含改动前已持久化的最新一轮卡片）。
- **流式未结束**：回答仍在流式输出时不得出现卡片；只有该轮结束后才允许出现。

## 需求 *(必填)*

### 功能需求

#### 生成（运行环境侧）

| 编号 | 需求 | 验收 |
|---|---|---|
| **FR-001** | 开启该功能的数字人，其**成功完成**的每一轮对话结束后，系统 MUST 基于本轮上下文产出 **0~3** 条下一步动作提示 | 成功轮必有生成动作；失败轮 MUST NOT 生成 |
| **FR-002** | 生成所依据的上下文 MUST 至少包含：本轮用户输入、本轮回答输出、本轮已调用的工具、当前数字人可调用的全部工具的基本信息（名称与用途摘要） | 桩测试：断言上述四类信息均进入生成请求；工具清单与该数字人当下可用工具一致 |
| **FR-003** | 每条提示词 MUST 为**中文自然语言指令**，MUST NOT 出现工具英文名、工具标识符或英文缩写；单条长度 MUST ≤ **50 字** | 桩测试：含英文工具名的条目被判定不合规；51 字条目被判定不合规 |
| **FR-004** | 产出条数 MUST 为 0~3 条；为 0 条时 MUST NOT 展示引导句与卡片 | 0 / 1 / 3 / 4 条四种输入各 1 例 |
| **FR-005** | 系统 MUST 允许模型判定"无需下一步"（用户目标已达成、闲聊、任务闭环等），此时等价于 0 条 | 桩模型返回"无需下一步"→ 无卡片、无引导句 |
| **FR-006** | 生成 MUST NOT 改变本轮回答正文内容，也 MUST NOT 改变既有工具调用记录与视图入口的展示 | 回归：改造前后同一轮的回答正文与侧车数据逐字一致 |
| **FR-007** | 生成 MUST NOT 阻塞、延迟本轮回答的完成与渲染；提示在回答结束后补出，未产出前界面 MUST 与未开启该功能时一致（不得出现骨架屏或阻塞态） | 桩测试：回答 `done` 时刻与提示展示时刻解耦；回答阶段无额外等待 |
| **FR-008** | 生成 MUST 有界：单次生成 MUST 有明确超时上限（≤ 10 秒）且 MUST NOT 无限重试 | 超时用例：超时后无卡片，回答不受影响 |
| **FR-009** | 每条下发的提示 MUST 关联**至少一个**本轮可用工具（判据 = 该引用命中本轮真实装配的可用清单）；**裁剪后无任何有效引用的条目 MUST NOT 下发**（整条丢弃，MUST NOT 降级为"无工具卡片"）；本轮全部条目均因此被丢弃时，本轮为 0 条（不展示卡片与引导句）。**理由**：无工具绑定的建议会退化为开放式闲聊指令，产生大量与数字人能力无关的"奇怪指令"（2026-10-14 用户口径） | 三条用例：①`tools` 为空的条目被丢弃；②`tools` 引用越界（清单外 / 名字写错）→ 裁剪后为空 → 整条丢弃；③混合输入（1 条有效 + 2 条无工具）→ 只下发 1 条 |

#### 展示（聊天前台）

| 编号 | 需求 | 验收 |
|---|---|---|
| **FR-010** | 卡片 MUST 展示在该轮**回答正文之后**（与工具调用记录、视图入口同层的侧车位置），MUST NOT 插入正文中间 | 组件测试：卡片容器在正文容器之后渲染 |
| **FR-011** | 存在 ≥1 张卡片时，回答正文末尾 MUST 出现固定引导句"您接下来可以操作以下动作，请选择"；该句 MUST 由**界面固定渲染**，MUST NOT 依赖模型生成，模型输出中的任何措辞 MUST NOT 改变该句 | 有卡片时该句出现一次且文案逐字一致；无卡片时不出现；切换模型/语言后该句不变 |
| **FR-012** | 卡片 MUST 与首页"快速上手"问题实例卡片**同源同形态**（复用同一卡片视觉与交互体系），MUST NOT 引入第二套视觉体系 | 代码审阅 + 视觉回归：两处卡片形态一致 |
| **FR-013** | 卡片 MUST NOT 展示关联工具信息；卡片对用户呈现的全部内容只有该提示词文本 | 组件测试：卡片 DOM 文本等于提示词 |
| **FR-014** | 无卡片时 MUST NOT 渲染任何卡片容器（无 DOM 即无间距） | 组件测试：无提示时容器不存在，回答区布局与改造前一致 |
| **FR-015** | 卡片 MUST **只展示在该会话最新一轮回答下方**：历史轮次的位置一律不展示卡片；同时该最新一轮的卡片 MUST **持久保留**，刷新页面或重进会话后仍可见、可点击 | 场景测试：新一轮完成后旧轮卡片消失；刷新 / 重进会话后最新轮卡片仍在；任意历史轮次位置无卡片 |
| **FR-016** | 无障碍：卡片 MUST 是可键盘到达的按钮（`Tab` 可达、`Enter` / `Space` 触发），列表 MUST 有语义容器与可读标签，焦点 MUST 可见；动效 MUST 随 `prefers-reduced-motion` 降级为静态 | 键盘与读屏验证；`prefers-reduced-motion` 下无动效 |
| **FR-017** | 新一轮产出 0 条时 MUST **覆盖并清除**上一轮的卡片：该会话此后不再展示任何卡片，MUST NOT 继续展示过期引导 | 一轮有卡片 → 下一轮 0 条 → 旧卡片消失且无新卡片 |
| **FR-018** | 提示快照 MUST **有界**：每个会话至多保留最新一轮的提示，MUST NOT 随轮次累积 | 连续多轮对话后，该会话仅存有最新一份提示快照 |
| **FR-019** | 卡片 MUST 与**产生它的数字人**绑定：下发的下一步动作提示 MUST 同时满足「该数字人当前开关为开」与「该数字人 = 当前选中数字人」两个判据，任一不满足即 MUST NOT 下发、MUST NOT 展示（会话可跨数字人，故这是消除隐藏引导越权注入的必要判据） | 集成测试：切换当前数字人后，原数字人快照不再下发；切回后可重新下发；两种不一致态各 1 例 |

#### 点击与发送（聊天前台）

| 编号 | 需求 | 验收 |
|---|---|---|
| **FR-020** | 点击卡片 MUST 先弹出二次确认弹窗，弹窗 MUST 展示该提示词全文，并提供"发送"与"取消" | 交互测试：点击后弹窗出现，此时**未**发送任何消息 |
| **FR-021** | 确认后 MUST 以该提示词文本作为用户消息发起下一轮对话，并复用既有发送链路（与用户手输同一条通路） | 集成/组件测试：聊天区新增用户消息内容等于提示词；走既有发送与流式链路 |
| **FR-022** | 取消（含 `Esc`、`取消` 按钮、点击遮罩若既有弹窗组件支持）MUST NOT 发送任何消息 | 组件测试：取消后消息列表长度不变 |
| **FR-023** | 发送进行中或确认弹窗已打开时，重复点击 MUST 被抑制；发送失败 MUST 给出可感知提示，MUST NOT 静默 | 组件测试：连点只发一次；失败时提示可见 |

### 关键实体

- **下一步动作提示（Next Action Hint；代码名 `NextAction`）**：一条建议。关键属性：提示词文本（中文，≤50 字）、关联工具引用列表（**≥1 项**，可含内置工具与 MCP 服务+工具，**仅内部使用、不展示**；裁剪后为空的条目不成立、不下发，见 FR-009）、序号（决定展示顺序）。
- **最新一轮提示快照（Latest Round Hints）**：归属某会话**最新一轮**回答的 0~3 条提示，随该轮产生；新一轮产出时**整体覆盖**上一轮（存储有界），为空表示"本轮无需下一步"（此时该会话不展示任何卡片）。
- **数字人功能开关（下一步动作提示开关）**：布尔值，归属数字人的 SOUL 配置；经部署物化后由运行环境读取，决定是否启用生成。
- **可调用工具清单**：某数字人当下可用的内置工具与 MCP 工具（名称 + 用途摘要），来自该数字人配置，用于生成上下文与工具引用合法性校验。
- **本轮上下文**：本轮用户输入、本轮回答输出、本轮已调用工具清单，三者共同构成生成依据。

### 不可破坏的不变量

| # | 不变量 | 落点 |
|---|---|---|
| **I-1** | 回答正文内容与展示逐字不变；本功能只做"追加"，MUST NOT 改写回答 | 回答渲染链路 |
| **I-2** | 既有工具调用记录卡片与视图入口的展示与行为不变 | 回答区侧车数据渲染 |
| **I-3** | 用户消息气泡中 MUST NOT 出现任何工具名或隐藏引导内容 | 发送链路与消息持久化 |
| **I-4** | 发送链路唯一：卡片发送复用用户手输发送的同一条通路，MUST NOT 新增第二套发送实现 | 发送 composable |
| **I-5** | 平台是配置唯一权威源；部署为整体覆盖；运行环境 MUST NOT 反向写回平台 | 部署物化链路 |
| **I-6** | 数字人的人格提示词语义不受本开关影响 | SOUL 渲染与 System Prompt 组装 |

## 假设

- **生成方式**：提示由模型产出结构化结果（提示词文本 + 关联工具引用），而非规则拼接；由运行环境统一解析、校验与下发，前端零规则知悉。
- **生成时机**：本轮回答成功完成后**异步补出**，不阻塞回答收尾；不改变既有流式事件与消息历史的既有语义（仅新增"追加型"数据）。引导句由界面固定渲染，不依赖模型输出。
- **工具信息的用途**：卡片背后的工具信息用作**隐藏引导**，注入下一轮模型上下文（与"问题实例卡片"同一通道）；引导内容由运行环境在生成提示时一并产出于卡片数据中，前端只做原样回传，MUST NOT 自行拼装工具名。引导 MUST **明确指出本轮要调用哪个工具**（工具名 + 用途摘要），使"绑定"落到下一轮指令上；工具引用越界时丢弃该引用，**裁剪后引用为空的条目整条丢弃**（见 FR-009）。引导是**强提示而非强制**：本特性不引入 Function Calling，本轮是否真的发起调用仍由模型在工具循环中决定（与「非目标」一致）。首屏"问题实例"卡片的引导文案 MUST NOT 因本特性改变（不强制其绑定工具，见用户口径 2026-10-14）。
- **可见与留存**：卡片只展示在会话最新一轮回答下方；该轮卡片持久保留（刷新、重进会话后仍可见可点击），新一轮产出时整体覆盖上一轮，存储保持有界。
- **语言**：提示词一律中文，与数字人回答所用语言无关；工具英文名一律不得进入展示文案。
- **开关默认值**：存量数字人与未显式设置的数字人默认**关闭**（零行为变化，符合"关闭即功能消失"与宪章"不追溯存量"）。
- **开关语义边界**：开关只控制本功能，不属于数字人人格提示词，不进入 System Prompt 语义。
- **范围边界**：只涉及聊天前台、管理平台数字人 SOUL 配置页与运行环境；不涉及 `gateway` / `ocr-service` / `jev-service`。
- **用户前提**：用户处于单用户工作台上下文，具备稳定的本站连接（网络中断按"失败轮不提示"处理）。
- **不新增配置形态**：开关并入既有 SOUL 结构化配置，不新增独立配置文件。

## 非目标（本次明确不做）

- 不做卡片的用户偏好学习、点击率统计与个性化排序（展示顺序只按模型给出的顺序）。
- 不做卡片的手工编辑、收藏、置顶或历史检索。
- 不做多语言提示词（一律中文，不随数字人回答语言变化）。
- 不做跨会话、跨数字人的提示复用或推荐。
- 不改变工具权限模型：隐藏引导只是"建议优先使用"，不新增或收窄任何工具的可用性。
- 不改变 HITL 交互弹窗链路与既有倒计时/拒绝/提交语义。
- 不引入提示词质量的人工审核流程。
- 不对存量数字人做回溯性改造或批量开启。
