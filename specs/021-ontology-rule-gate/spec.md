## 1. 背景与目标

本体产物 `ontology.yaml` 的 `rules` 里写着"某个行为在什么条件下才算成立"：每条规则用 `behavior` 指向行为、用 `position` 标明前置/后置、用 `related_functions` 声明需要哪些函数的执行结果、用 `rule_design` 给出可机械求值的条件树（`combine` + `groups[].conditions[].{function, field, operator, values}`），并自带 `pass_message` / `fail_message`。

现状是这份规则**从未被执行**：016 明确"`rules` 一律忽略"，020 只消费 `behaviors` 与 `securities.yaml`。于是本体里写明的"创建采购单前必须校验原料单位、到位时间、供应商存在性"完全依赖模型自觉——模型可以先落库再校验，或者干脆跳过校验。020 解决的是"谁可以调用"，本特性解决的是"这次调用是否成立"。

本特性给本体行为（`query` 与 `command` 一视同仁）加两道以**行为**为粒度的规则闸门：

- **前置闸门**（`position: 前置`）：行为真正执行**之前**，要求规则的 `related_functions` 在本轮都已被成功执行过（缺就停下、让模型先补），再用本轮记录的函数结果对 `rule_design` 做一次**不经 LLM 的机械求值**；结果为 `true` 才放行，为 `false` 则拒绝执行**并挂起本轮工具**（软收尾：模型说明原因后正常结束）。
- **后置提示**（`position: 后置`）：行为执行**成功之后**，把规则内容附着在结果后面一起返回，提示模型继续调用相关函数完成推导。

支撑这两道闸门的是一份**轮内**函数执行记录：本轮每一次"函数"调用（仅成功）留一条结果，供前置闸门求值时读取；每轮开始时**重新创建**，不跨轮、不落盘、不参与历史回放。

## Clarifications

### Session 2026-11-09

- Q: 后置规则的函数注册校验应放在行为执行之前还是执行成功之后？ → A: B —— 执行**成功后**校验：行为照常执行并落库；随后发现未注册函数则放弃追加该后置提示、中止整轮，并在聊天区输出中断原因（已执行的事实须在文案中说明）。
- Q: 判断规则函数是否"已注册"应以哪份工具清单为准？ → A: A —— 以**本轮真正挂载给模型的 MCP 工具集合**为准（服务注册后经白名单与权限过滤、真正可被调用的那一份）；不在其中即视为"不存在"，直接阻断。
- Q: 阻断发生后"中断原因"应以哪种形式出现在聊天区？ → A: A —— **复用现有失败提示块**：本轮以失败态收尾，逐条原因进 `details`（行为、规则、未注册函数、下一步建议）；MUST NOT 额外插入 assistant 或系统消息。
- Q: "函数未注册"这种阻断应该用哪个错误码？ → A: A —— **复用中止码 `ONTOLOGY_RULE_DENIED`**，在 `details` 与日志 `reason` 中区分 `unregistered` / `condition_false` / `config_unavailable`；不新增第三个码（总数仍为 2）。

## 2. 用户场景与测试 *(mandatory)*

### 用户故事 1 - 前置规则：缺函数先补，齐备才算 (Priority: P1)

数字人「采购助手」的本体 `原材料采购和库存` 里，`CreatePurchaseRecord`（创建采购单）挂着三条前置规则，分别是"原料存在且单位一致"（需要 `checkRawMaterialUnit`）、"到位时间合理性"（需要 `checkArrivalTimeValidity`、`getCurrentDate`）与"供应商名称一致"（需要 `checkSupplierExistence`）。用户在聊天里说"给高强度钢板下一张 50 吨的采购单，下周五到货"，模型**直接**发起 `CreatePurchaseRecord`。系统当场把这笔调用按下：不落库、不产生采购单，并把规则原文连同"`checkRawMaterialUnit`、`checkArrivalTimeValidity`、`getCurrentDate`、`checkSupplierExistence` 尚未执行，校验无法通过，请先执行完善"一起返回。模型据此先逐个调用校验函数，再重发采购单——这次函数记录齐备，规则求值全部为 `true`，采购单才真正落库。

换成另一种输入：模型确实先调了校验函数，但 `checkSupplierExistence` 返回"供应商不存在"，规则求值为 `false`。这次不是"暂停"，而是**拒绝**：采购单不落库，本轮其余工具不再执行，模型据此给出明确说明（哪个行为、哪条规则、`fail_message` 原文）后正常结束；不会出现"校验不通过却已写入"的数据，也不会甩给用户一句失败提示就断线。

还有第三种情况：规则里写的 `checkSupplierExistence` 在本体的 `functions[]` 里有声明，但对应工具**没有挂载给模型**（被白名单过滤掉）。这时"先补调函数"永远补不上——系统不会让它一直空转，而是**阻断**：不执行行为、挂起本轮工具，卡片里说明"`checkSupplierExistence` 未注册（未启用），请检查工具白名单与本体的函数声明"。这类问题属于配置错误，早拒绝比无限等待有用。

**为何优先级最高**：这是本需求交付的全部价值——把 `rule_design` 从"写给人看的判定设计"变成运行期真实约束；没有它，前置规则只是注释，业务数据随时可能被未校验的调用写入。

**可独立验证**：对同一行为构造两份本体（一份含三条前置规则、一份不含规则），用同一句要求触发调用：前者必然先出现"缺函数 → 暂停"，补完函数后才执行；后者一次直通。再构造"函数返回失败"的分支，确认拒绝并挂起本轮工具、业务数据零变化，且本轮以模型总结正常结束。

**验收场景**：

1. **Given** 行为 `CreatePurchaseRecord` 有前置规则且 `related_functions` 全部未执行，**When** 模型调用该行为，**Then** 行为不执行、无任何业务副作用，返回内容包含该规则全部字段（名称、标题、描述、`related_functions`、`rule_design`、`pass_message`、`fail_message`）与"请先执行以下函数"的明确指令，且本次调用以失败态呈现。
2. **Given** 同一轮内模型随后成功调用了全部 `related_functions`，**When** 再次调用该行为，**Then** 不再暂停，进入规则求值并按其结果放行或拒绝。
3. **Given** `related_functions` 齐备且 `rule_design` 求值为 `true`，**When** 执行，**Then** 行为按原样执行，入参、返回值、业务结果与"没有规则闸门"时完全一致。
4. **Given** 求值为 `false`，**When** 执行，**Then** 行为**不执行**、无业务副作用，本轮其余工具不再执行，模型收到「结论 + 明细 + 终局指令」后向用户说明并正常结束（不产生 error 失败轮），可见原因包含行为名、规则名与 `fail_message`。
5. **Given** 该行为没有任何前置规则，**When** 调用，**Then** 直接执行，闸门不产生暂停、拒绝或额外文案。
6. **Given** 一次暂停已发生，**When** 查看会话，**Then** 该次调用以失败卡片呈现，文案点名缺失的函数，且不揭示任何与权限相关的内部信息。
7. **Given** 某条前置规则的 `related_functions` 中有一个未注册函数（不在本轮可用工具集合内），**When** 调用该行为，**Then** 行为不执行、**不进入暂停**，拒绝并挂起本轮工具，卡片点名规则与该未注册函数，日志 `reason = unregistered`。
8. **Given** 同一批函数全部已注册、但其中两个本轮尚未执行，**When** 调用该行为，**Then** 走暂停（提示先执行），MUST NOT 被误判为"未注册"而阻断。

### 用户故事 2 - 每轮重建记录：上一轮的函数结果不算数 (Priority: P2)

模型在新一轮里又想创建采购单，而校验函数是**上一轮**调用过的。系统不会把上一轮的结果拿来复用：本轮的函数记录是空的，前置闸门照样按下这次调用，要求模型在本轮重新执行校验。反之，同一轮里翻来覆去调用同一个函数十次，记录里也只留一条、取**最后一次**调用的结果——不因调用次数膨胀；若最后一次恰好报错，记的就是 `null`（不会被更早的成功值"兜底"），相关条件因此不成立。

**为何优先级次之**：记录的生命周期决定了闸门"能不能真的挡住没校验就落库"。如果记录跨轮复用，用户第二句话就能绕过前置规则；如果"最新一次"语义不统一（例如失败不覆盖），模型在修正参数后重调，求值读到的还是旧值，规则结论会与模型的真实动作脱节。

**可独立验证**：第 1 轮先跑齐校验函数再创建采购单（通过）；第 2 轮直接创建采购单（应暂停）；第 3 轮同一轮内先调 `checkRawMaterialUnit` 失败一次、再成功一次，然后创建采购单（应按成功值放行）；第 4 轮同一轮内先成功、后失败一次，再创建采购单（应按 `null` 判定条件不成立 → 拒绝并挂起本轮）。

**验收场景**：

1. **Given** 上一轮已成功执行全部 `related_functions`，**When** 本轮首次调用该行为，**Then** 仍判定为"缺函数"，暂停并提示先执行。
2. **Given** 同一轮内同一函数先失败后成功，**When** 前置规则求值，**Then** 使用最后一次（即成功那次）的结果。
3. **Given** 同一轮内同一函数成功后又被调用且失败，**When** 前置规则求值，**Then** 使用最后一次（即失败）的 `null`——该函数的一切条件判不成立，按拒绝并挂起本轮处理（**失败覆盖成功**）。
4. **Given** 同一轮内同一函数调用多次，**When** 查看记录，**Then** 只有一条记录，值为最后一次调用的结果（成功为对象、失败为 `null`），且该键存在即表示"已执行"（不触发暂停与注册校验）。
5. **Given** 一轮对话结束，**When** 开始新一轮，**Then** 记录为空且不读取任何历史文件；上一轮的函数结果既不出现在记录里，也不出现在任何持久化产物中。

### 用户故事 3 - 后置规则：行为做完，把推导提示递到模型手上 (Priority: P3)

采购单创建成功的那一刻，系统把"采购目的推理"这条后置规则（`related_functions: inferPurchasePurpose`）整段附在结果后面："该行为执行后需完成以下推导……请调用 `inferPurchasePurpose`"。模型读到后继续调用该函数，把"这次采购可能是在补库存"的结论写进回答。用户因此拿到的是"单子下好了，而且说明了为什么下这张单"，而不是一张冷冰冰的创建成功回执。反过来，某个行为没有后置规则，结果就保持原样，不多一句废话。

但如果这条后置规则引用的 `inferPurchasePurpose` **没有注册**（工具未挂载），提示就永远无法兑现。规则在三个环节上生效：行为已经执行成功、单子已经落库之后，系统放弃追加提示并挂起本轮工具，明确告诉用户"采购单已创建，但后续推导所需函数未启用"——不让用户误以为整轮什么都没发生。

**为何优先级第三**：后置提示**不阻断行为本身**（注册校验发生在执行成功之后，也不会撤销已发生的写入），但它决定了"规则体系能否驱动模型走完整个推理链"；没有它，`rules` 里的 infer 类规则永远只能停在纸面上。

**可独立验证**：对同一行为分别配置/不配置后置规则，各执行一次成功调用：前者结果末尾多出该规则全文与"请继续调用相关函数"的引导，后者结果逐字不变；再让行为执行失败一次，确认失败结果不多出后置提示；最后把后置规则的函数换成未注册名，确认行为仍执行成功、提示被放弃、本轮挂起且文案说明"已写入"。

**验收场景**：

1. **Given** 行为有后置规则且执行成功，**When** 结果返回给模型，**Then** 原始结果正文完整保留，规则全文以明确分界附着在其后，并提示继续调用相关函数完成推导。
2. **Given** 同一行为有多条后置规则，**Then** 全部按规则顺序附着，一条不漏。
3. **Given** 行为没有后置规则，**Then** 结果与无闸门时逐字相同。
4. **Given** 行为执行失败（业务失败或异常），**Then** 不附加任何后置提示。
5. **Given** 模型看到的被追加后的结果，**When** 用户展开该工具卡片，**Then** 看到的是同一份文本（模型可见与记录内容一致）。
6. **Given** 后置规则的 `related_functions` 中有未注册函数，**When** 该行为执行成功，**Then** 行为结果与业务数据保持不变、**不追加**该规则提示，拒绝并挂起本轮工具，卡片在业务正文之后追加说明，文案明确说明"该行为已执行成功、数据已写入"，日志 `reason = unregistered`。

### 边界情况

- **同一行为挂多条前置规则**：全部参与判定（逻辑与）；只要**任一**规则缺函数，即先做注册校验（`FR-041`）——全部已注册才进入"暂停"（不计算其他规则、不执行、不挂起），并把**所有**缺函数的规则一并反馈；存在未注册函数则阻断并挂起本轮工具。
- **同一行为既有前置又有后置规则**：先前置（可能暂停/拒绝），执行成功后追加后置；两段互不影响。
- **前置规则的 `related_functions` 为空数组**：不存在"缺函数"，直接进入求值（若同时缺 `rule_design`，则视为无需计算、直接放行）。
- **`rule_design` 引用了未在 `related_functions` 中声明的函数**：该函数不会被记录（也不在检查范围内），条件取不到值即判定为"不满足"；因此规则可能求值为 `false` 并导致拒绝与挂起。该情形 MUST 记告警，指向规则名与被引用的函数名。
- **函数已记录但结果不含条件所需的字段**：按"字段缺失"处理，该条件不成立（不猜测、不补默认值）。
- **函数结果不是对象**（纯文本、图片占位、被截断的报文）：记录为"无可用字段"，对该函数的任何条件都不成立。
- **函数结果是数组**：按 `count`（元素个数）与 `items`（原数组）两个字段提供，条件按字段名读取。
- **函数结果过大**：单条结果记录超出上限时丢弃该条并记告警（该函数在本轮视为"未记录"，会导致前置暂停而非静默通过）。
- **函数名与本体行为同名**：该工具按"本体行为"被排除在记录之外，规则会一直认为它"未执行"→ 行为永久暂停。这是配置冲突，MUST 记告警并在文案中如实说明缺哪个函数。
- **同名函数由多个 MCP 服务提供**：记录按函数名去重，取**最后一次调用**的结果（后到覆盖先到，失败亦覆盖为 `null`），并记一次告警。
- **函数执行失败 / 无结果（记录为 `null`）**：该函数已记入记录，故**不触发**"缺函数"与注册校验；但其一切条件都取不到值 → 相关规则求值不成立 → 按 `FR-024` 拒绝并挂起本轮（不猜测、不当作通过）。
- **规则引用了未注册函数**：若属于前置规则 → 阻断并挂起本轮（`FR-041`）；若属于后置规则 → 行为执行成功后放弃提示并挂起本轮（`FR-042`）。两者都**不是**"暂停"，模型无法通过补调函数自救。
- **函数在服务里存在但被白名单/权限过滤掉**（未挂载给模型）：按"未注册"处理 → 阻断（`FR-043`）。这是配置不匹配，不是暂时状态，MUST 记告警并在文案中提示"该函数未被启用，请检查工具白名单与本体的函数声明"。
- **本体 `functions[]` 与可用工具集不一致**（声明了但未挂载，或挂载了但未声明）：以**可用工具集**为注册判据；`functions[]` 只用于取字段声明类型，二者冲突时记告警。
- **同一轮内并行调用多个本体行为**：各自独立判定；一个被拒绝时，已经完成的调用结果保持既成事实，同一批已发出的调用允许自然完成，尚未开始的调用不再执行。
- **行为执行失败**（业务失败或异常）：属于"执行完成但不成功"，不追加后置提示；前置闸门在调用前已完成，不受影响。
- **规则字段缺失或取值非法**：`behavior` 为空、`position` 既非"前置"也非"后置"的规则 MUST 被忽略（不参与任何判定）并记告警；`related_functions` 不是字符串数组时按"无法解析"处理（fail-closed：拒绝并挂起 + 告警）。
- **`position` 书写差异**：按去首尾空白后与"前置"/"后置"精确比对；其他写法（如 `前`、`pre`）不猜测语义，视为非法并忽略 + 告警。
- **本体目录不可读 / `ontology.yaml` 损坏**：无法识别该工具为某本体的行为 → 按"非本体行为"放行（与 020 一致），不进入规则闸门、不产生噪声；但若行为已被识别、只是其 `rules` 段结构非法，则按 fail-closed 处理（拒绝 + 挂起 + 告警）。
- **数字人未部署任何本体**：所有工具照常执行，规则闸门不产生暂停、拒绝、追加文案或日志。
- **部署更新与读取并发**：重新部署后，下一次调用即按新规则判定；任一次判定 MUST 读到完整文件，不得读到半更新内容。
- **读屏与视觉**：暂停与拒绝沿用既有工具失败态（文案为主、颜色为辅），不新增仅靠颜色传达的信息。

## 需求 *(mandatory)*

### 术语与判定口径

| 术语 | 口径 |
|---|---|
| 一轮对话 | 一条用户消息触发的一整轮（含该轮内多次模型调用与工具循环），轮结束即销毁 |
| 函数 | 可被模型调用的工具中，**排除**平台内置工具、**排除**能被任一已部署本体的 `behaviors[]` 识别出的工具（即本体行为，其 `securities.yaml` 条目就是 `action_name`）之后剩下的那些 |
| 已注册函数 | **本轮真正挂载给模型的 MCP 工具集合**中的一个（服务注册后经白名单与权限过滤、模型确实能调用的那份），按与记录同一口径归一后比对；内置工具与本体行为不在此集合的判定语义内 |
| 函数执行记录 | 本轮内"函数名 → 该函数**最后一次调用**的结果"的映射；执行报错或结果缺失记为 `null`；每轮新建，不落盘 |
| 规则 | `ontology.yaml` 的 `rules[]` 一条，含 `name` / `title` / `description` / `behavior` / `position` / `related_functions` / `data_supplements` / `rule_design` |
| 前置规则 / 后置规则 | `position` 为"前置" / "后置" 的规则 |
| 规则求值 | 用函数执行记录对 `rule_design` 做机械计算，得到 `true` 或 `false` |
| 暂停 | 本次行为调用不执行，以工具失败结果返回规则全文与"请先执行函数"的引导；本轮继续 |
| 拒绝并挂起本轮 | 本次行为调用不执行（后置阻断时业务已执行），且本轮不再执行任何后续工具；模型收到「结论 + 明细 + 终局指令」后向用户说明并正常结束（软收尾）；模型固执重试时纯中止（`ABORTED`）兜底 |
| 阻断 | 注册校验发现规则引用的函数**不存在**（未挂载给模型）时的处置：不执行行为（前置）或放弃提示（后置），拒绝并挂起本轮并输出原因；**不可自愈**，与"暂停"相对 |

### 功能需求

**A. 轮内函数执行记录**

- **FR-001**：系统 MUST 在每轮对话开始时创建一份**空的**函数执行记录，并在该轮结束时丢弃；MUST NOT 跨轮复用、MUST NOT 落盘、MUST NOT 进入历史回放或摘要。
- **FR-002**：记录的条目 MUST 只来自"函数"（按术语口径）：平台内置工具 MUST NOT 记录；**本体行为**（被任一已部署本体的 `behaviors[]` 识别出、因此在 `securities.yaml` 有 `action_name` 管控条目的工具）MUST NOT 记录；其余每一次调用 MUST 记录。行为识别 MUST 与权限闸门采用**同一口径与同一实现**（同一工具名归一与匹配规则），MUST NOT 另建一套识别逻辑。
- **FR-003**：每一次"函数"调用 MUST 记录一条，**不以成败为条件**：正常返回 → 记该次结果（`FR-006`）；执行报错、超时、结果缺失 → MUST 记为 `null`。MUST NOT 记录**未真正发出**的调用（被权限闸门拒绝、被前置规则暂停、中止后未执行）。**键存在即表示"该函数本轮已执行过"**，其值可能为 `null`。
- **FR-004**：记录的键 MUST 为函数名，且 MUST 按"MCP 服务前缀之后的名字"归一（例如 `{服务名}__checkRawMaterialUnit` 记为 `checkRawMaterialUnit`），以便与规则的 `related_functions` 同名；比对口径为去首尾空白、大小写不敏感。
- **FR-005**：同一函数在同一轮内被多次调用时，MUST 只保留**最后一次调用**的结果（后到覆盖先到；成功与失败**同样覆盖**，失败记 `null`）；记录中同一函数名 MUST 只有一条。
- **FR-006**：记录的值为该次调用的**业务数据部分**（可按字段名读取的键值形态），MUST NOT 为仅供人读的一段文本：结果若带**统一信封**（即同时含 `data`，且含 `success` / `error` / `status` 之一），MUST 取其中的 `data`（规则的 `field` 正是相对该层声明的）；无信封时取结果对象本身（如扁平返回 `{status, message, ...}` 的服务）；纯文本结果按是否为合法 JSON 对象解析；结果为数组时 MUST 以 `count`（元素个数）与 `items`（原数组）提供。无法得到对象的，MUST 记为"无可用字段"。
- **FR-007**：单条结果 MUST 有体积上限；超出上限时 MUST 丢弃该条并记告警，MUST NOT 静默存入半份数据。
- **FR-008**：记录 MUST NOT 因为规则判定失败、暂停或中止而被清空或回滚（同一轮内已发生的调用是既成事实）。

**B. 前置规则判定**

- **FR-009**：前置判定 MUST 发生在该本体行为的权限校验**通过之后**、行为真正执行**之前**；权限校验未通过的行为 MUST NOT 进入规则判定。
- **FR-010**：规则来源 MUST 是该行为**所属本体**的 `ontology.yaml` 的 `rules`（与权限闸门同一归属判定，`{场景}/{本体}`），MUST NOT 从其他本体的同名规则、平台配置或第二处数据源读取。
- **FR-011**：规则与行为的匹配 MUST 以 `behavior` 字段为准，口径为去首尾空白、大小写不敏感；`position` MUST 为"前置"（后置同一口径）。
- **FR-012**：该行为没有前置规则时，MUST 直接执行，不产生暂停、拒绝或任何追加文案。
- **FR-013**：该行为有多条前置规则时，MUST 全部参与判定；判定顺序 MUST 为「缺函数检查 → 函数注册校验（`FR-041`）→ 暂停或阻断 → 规则求值」，且任一条规则缺函数即在该条上终止后续步骤。
- **FR-014**：暂停条件 MUST 为"前置规则的 `related_functions` 中至少有一个函数不在函数执行记录里"（含该规则 `related_functions` 为空时永不满足）。暂停时：不执行行为、不产生业务副作用、不中止整轮。
- **FR-015**：暂停 MUST 把触发暂停的**每一条**规则的全部内容（`name` / `title` / `description` / `behavior` / `position` / `related_functions` / `data_supplements` / `rule_design` / `pass_message` / `fail_message`）如实反馈给模型，并明确列出该规则中**尚未执行**的函数名，指示模型先执行这些函数再重试该行为。
- **FR-016**：暂停 MUST 以工具失败结果的形式返回（沿用既有失败标记通道：卡片失败态、模型收到可读文本），MUST NOT 抛异常、MUST NOT 以成功结果伪装；该通道 MUST 使用全局唯一的工具失败码 `ONTOLOGY_RULE_FUNCTIONS_MISSING`（与中止码 `ONTOLOGY_RULE_DENIED` 分属两条通道，MUST NOT 互相复用）。
- **FR-017**：`related_functions` 齐备后，系统 MUST 直接调用一个**规则计算模块**（纯计算，不经过 LLM、不发起网络请求）完成求值：输入为函数执行记录与 `rule_design`，输出为 `true` / `false`。
- **FR-018**：求值语义 MUST 为：`rule_design.combine`（`and` / `or`，缺省 `and`）组合各 `groups` 的结果；`groups[].combine`（缺省 `and`）组合其 `conditions` 的结果；`conditions[]` 以 `function` + `field` 读取记录值，用 `operator` 与 `values` 判定。
- **FR-019**：`operator` MUST 支持规则设计约定的**全集 16 个**：`eq` / `ne` / `gt` / `gte` / `lt` / `lte` / `between` / `contains` / `not_contains` / `starts_with` / `ends_with` / `matches` / `in` / `not_in` / `empty` / `not_empty`；取值个数 MUST 按算子决定（`empty` / `not_empty` 为 0 个、`between` 为 2 个、`in` / `not_in` 至少 1 个、其余恰好 1 个）。未知 `operator` 或取值个数与算子不符时，MUST 使该条件判定为不成立并记告警，MUST NOT 抛出异常。
- **FR-020**：比较口径 MUST 确定可测：`values` 恒为字符串数组，解释时按**该函数 `response` 中该字段声明的类型**强制转换（`boolean` / `integer` / `number` / `string`）；字段未声明类型时按字符串精确比较（数值算子除外，转数字失败即不成立）。`gt` / `gte` / `lt` / `lte` / `between` 一律数值比较。`field` MUST 支持"逐段对象路径 + `[]` 数组元素层"（如 `pass`、`detail.qty`、`items[].qty`、`a[].b[].c`）；任一段缺失即视为字段缺失。`matches` 的正则非法、或待比较文本超长时 MUST 判为不成立而不是异常。若 `related_functions` 中的**公共函数**未在本体 `functions[]` 中声明（只存在于平台公共函数库），其字段一律按"未声明类型"处理并记一次告警；MUST NOT 猜测类型、MUST NOT 因此拒绝执行。
- **FR-021**：字段缺失、函数未记录、**记录值为 `null`（该函数执行失败）**、`values` 个数不符 MUST 使该条件判定为不成立；MUST NOT 猜测值、MUST NOT 视为 `true`、MUST NOT 因 `null` 而跳过该条件。
- **FR-022**：`rule_design` 缺失的前置规则 MUST NOT 阻断执行（视为"无需计算"，与 `related_functions` 检查相互独立），并 MUST 记一条告警以便治理。
- **FR-023**：求值为 `true` 时 MUST 允许执行该行为，且执行路径与"没有规则闸门"时一致（不改入参、不改返回值语义）。
- **FR-024**：求值为 `false` 时 MUST 拒绝执行该行为（无任何业务副作用）**并挂起本轮工具**（见 `FR-045`：软收尾，不硬切断本轮）。
- **FR-025**：前置规则的读取或结构异常（`rules` 段不可解析、`related_functions` 非字符串数组、`rule_design` 结构非法）MUST 按 fail-closed 处理：拒绝执行、挂起本轮工具、记告警，并在用户可见文案中说明"规则配置不可用"。MUST NOT 因异常而放行。

**C. 后置规则提示**

- **FR-026**：后置提示 MUST 发生在该本体行为执行**成功之后**；该行为没有后置规则时 MUST NOT 追加任何内容，结果与无闸门时逐字相同。
- **FR-027**：后置规则 MUST 来自该行为所属本体的 `ontology.yaml`（口径同 `FR-010` / `FR-011`），`position` 为"后置"；多条时 MUST 全部追加，顺序为文件内顺序。
- **FR-028**：追加内容 MUST 包含规则全文（`name` / `title` / `description` / `related_functions` / `data_supplements` / `rule_design`（若有）/ `pass_message` / `fail_message`（若有）），并以明确分界与原始结果区分；同时 MUST 提示模型继续调用相关函数完成推导。
- **FR-029**：追加 MUST 保留原始结果正文的完整内容与顺序，MUST NOT 改写、删减或重排原始结果。
- **FR-030**：行为执行失败（业务失败或异常）时 MUST NOT 追加后置提示。
- **FR-031**：模型可见的被追加结果 MUST 与记录（会话内工具卡片展开内容）为同一份文本，不得出现"模型看到一份、用户看到另一份"。

**D. 拒绝语义与可观测**

> **2026-11-09 修订（用户决策）**：本节由"硬中止整轮 + 失败轮"改为与 020 权限闸门一致的**软收尾**。
> 理由：规则拒绝与权限拒绝对用户都是"这次不让做、需要解释"，硬切断会让用户看到一句失败提示就结束，
> 既看不到明细，也没有模型的解释；同时与 020 的体验分叉。

- **FR-032**：拒绝（`FR-024` / `FR-025` / `FR-041` / `FR-042`）MUST **立即停止执行本轮其余工具**：不再判定、不再调用真实实现；已完成的调用结果保持既成事实。**并行批次语义**：拒绝发生在某次工具调用内时，同一批已发出的调用允许自然完成（其副作用保留），但 MUST NOT 再发起任何新批次（本约束只覆盖后续批次，已发出的无法撤回）。
- **FR-033**：拒绝 MUST 以**工具失败结果**的形式返回（复用既有失败标记通道：卡片失败态、模型收到可读文本），MUST 使用**拒绝通道唯一**的错误码 `ONTOLOGY_RULE_DENIED`；该码 MUST 全局唯一，MUST NOT 与其他工具错误码、暂停码（`FR-016`）或权限闸门的错误码混用。本特性新增的错误码总数为 **2 个**（暂停 1 个、拒绝 1 个），MUST NOT 再有第三个。**MUST NOT 再以 SSE `error` / 失败轮的方式收尾**（2026-11-09 修订）。
- **FR-034**：用户可见文案 MUST 讲清"哪个本体、哪个行为、哪条规则、为什么"，并在规则给出 `fail_message` 时包含其原文；MUST NOT 出现内部错误码原文作为唯一说明，MUST NOT 泄露与权限相关的配置内容。拒绝卡片的正文 MUST 同时包含**结论**、**逐条明细**与**终局指令**（`FR-045`），MUST NOT 只给一个笼统短语。**呈现形态 MUST 复用既有工具卡片**（失败态 + 正文多行），MUST NOT 额外插入 assistant 消息或系统消息；后置规则阻断时，文案 MUST 同时说明"该行为已执行成功、业务数据已写入"。
- **FR-035**：每次暂停、拒绝、规则不可用 MUST 留一条结构化记录，含用户标识、数字人、会话、工具名、本体、行为、规则名、缺失函数清单（暂停时）或求值结果（拒绝时）与时间；因配置异常产生的记录 MUST 为 `error` 级并带 `alert: true`（可观测性不得因软收尾而降级）。
- **FR-036**：规则判定 MUST NOT 改变既有工具调用统计口径：暂停与拒绝的调用 MUST NOT 计入实际发生的 MCP 调用次数（它们从未真正发出）。

**E. 数据源与生效**

- **FR-037**：规则的唯一数据源 MUST 是部署产物中的 `ontology.yaml`；MUST NOT 在平台侧新增规则存储、MUST NOT 解析或改写 `rule_design` 语义。
- **FR-038**：规则读取 MAY 缓存以控制开销，但缓存 MUST 随部署变化失效；任一次判定 MUST 读到完整文件，MUST NOT 读到半更新内容；重新部署后下一次调用即按新规则判定（无需重启、无需新建会话）。
- **FR-039**：规则闸门 MUST NOT 提供"按数字人关闭""按行为关闭"的旁路开关；需要放开时由本体侧修改或删除规则。
- **FR-040**：函数执行记录 MUST NOT 写入任何持久化产物（历史、日志正文、临时文件）。日志 MAY 记录**元信息**（函数名、是否记录成功、结果体积、条目数量），MUST NOT 记录结果正文、MUST NOT 记录工具入参。

**F. 函数注册校验（2026-11-09 补充）**

- **FR-041**：前置规则出现"未执行函数"时（`FR-014`），系统 MUST **先校验这些函数是否已注册**，再决定走向：全部已注册 → 进入暂停（`FR-014`~`FR-016`）；存在未注册（函数不存在）→ **阻断**：不执行行为、不进入暂停，拒绝并挂起本轮工具（`FR-032`），卡片正文指出规则名与未注册的函数名。
- **FR-042**：后置规则的函数注册校验 MUST 发生在该行为**执行成功之后、追加提示之前**：全部已注册 → 按 `FR-026`~`FR-031` 追加；存在未注册 → **放弃**该规则（及该规则后续的）提示追加，拒绝并挂起本轮工具；业务结果正文 MUST **完整保留**（不改写成失败结果），只在其后追加阻断说明与终局指令——文案 MUST 同时说明"该行为已执行成功、业务数据已写入"，避免用户误判。
- **FR-043**：注册校验 MUST 是**确定性集合判断**——查"**本轮真正挂载给模型的 MCP 工具集合**"（服务注册后经白名单与权限过滤后的可用集），按与函数记录同一的名称归一比对；MUST NOT 通过试调用探测、MUST NOT 依赖 LLM、MUST NOT 发起网络请求。**推论**：服务里存在但未挂载给模型的函数，等同于"未注册"，按 `FR-041` / `FR-042` 阻断；本体 `functions[]` 有声明但工具未挂载的，同样视为"未注册"（声明不能替代可用性）。
- **FR-044**：注册校验 MUST NOT 改变"暂停"的既有语义：已注册但未执行 → 仍是暂停（可自愈，`ONTOLOGY_RULE_FUNCTIONS_MISSING`）；未注册 → 才是阻断（不可自愈）。两者 MUST 使用不同的错误码与不同的用户可见文案。**阻断 MUST 复用拒绝码** `ONTOLOGY_RULE_DENIED`，并在 `details` 与结构化日志的 `reason` 字段区分三类：`unregistered`（函数未注册）/ `condition_false`（求值不成立）/ `config_unavailable`（规则不可用）；MUST NOT 为此新增第三个错误码（码表总数仍为 2）。

**G. 拒绝后的本轮语义（2026-11-09 增补，与 020 同口径）**

- **FR-045**：任一次拒绝后，本轮**其余工具调用 MUST NOT 执行**（既不判定也不调用真实实现），并返回「本轮已停止执行工具」的失败结果。拒绝卡片的正文 MUST 由三段构成：**结论**（哪个行为、为什么被拒）、**明细**（规则名、未成立条件 / 未注册函数等逐条原因）、**终局指令**（要求模型停止调用工具、向用户说明原因并结束回答）。终局指令 MUST 只出现在工具结果正文（模型可见），MUST NOT 写入结构化失败字段（`details.toolError.message` 仍是拒绝原因原文）。本轮 MUST NOT 因拒绝而硬切断：模型收到结果后总结并正常 `done`。
- **FR-046**：挂起后模型仍继续调用工具时 MUST 有界兜底：第 2 次（`attempts > 1`）即纯中止本轮，走与用户点"停止"**相同**的路径（`ABORTED` 收尾），MUST NOT 写入任何业务错误码、MUST NOT 制造失败轮原因；该兜底出口在单轮内 MUST 最多触发一次。
- **FR-047**：挂起状态 MUST 由装配层**每轮创建一次**，与 020 权限闸门**共享同一份实例**（021 在内侧，模型后续调用会先过 020；两层看到不同状态会导致"规则拒绝后仍可能被权限闸门放行"）；MUST NOT 落实例状态、MUST NOT 跨轮复用。挂起后的每次工具调用 MUST 留一条 `rule_gate.suspended` 记录（含工具名、拦截码与 `attempts`），MUST NOT 重复记录判定字段；`config_unavailable` 类拒绝 MUST 仍保留 `rule_gate.unavailable` 的 `error` 级记录与 `alert: true`。

### 关键实体 *(include if feature involves data)*

- **函数执行记录**：本轮内的内存映射；键 = 归一后的函数名，值 = 该函数**最后一次调用**的结果（成功为业务数据部分，口径见 `FR-006`；执行报错或结果缺失为 `null`）。键存在 = 本轮已执行过。生命周期 = 一轮对话。
- **规则**：`ontology.yaml` 的 `rules[]` 一条；关键属性：名称、标题、描述、`behavior`、`position`（前置/后置）、`related_functions`、`data_supplements`、`rule_design`、`pass_message` / `fail_message`。
- **规则条件**：`rule_design` 的最小单元；关键属性：所属函数、字段路径、比较算子、期望值列表。
- **规则求值结果**：`true` / `false`；附加信息：命中的规则名、被判定不成立的条件（供日志与文案）。
- **行为调用裁决**：四态——`直接执行`（无前置规则）/ `暂停（缺函数）` / `允许（求值通过）` / `拒绝并挂起本轮（求值不通过、函数未注册或规则不可用）`。对应的实现变体见 `data-model.md` §6.1：前两态的"非本体行为"分支记为 `function`（放行并记录），"本体行为"分支记为 `behavior`。
- **本轮工具挂起状态**：与 020 共享的轮内对象；关键属性：是否已挂起、触发码、被拦次数、兜底是否已用。生命周期 = 一轮对话（装配层新建，随工具数组丢弃）。

- **前端（`frontend`）**：**软收尾下零代码改动**。拒绝复用既有工具失败卡片（正文多行照常展示），不新增 UI、不新增组件、不新增消息类型；`ONTOLOGY_RULE_DENIED` 的文案映射与 `details` 受控透传（2026-11-09 初版新增）保留，用于展示**改动前已落盘**的历史失败行。
- **管理平台（`admin-backend` / `admin-frontend`）**：**零改动**。`rules` 现状已随本体整包导入、原样下发、平台不解析语义（与 016/020 一致）。
- **现状缺口（必须改变项）**：
  1. 运行环境当前**完全不读** `rules`（016 契约明确"`rules` 一律忽略"）。本特性首次消费该段，需要一处唯一的"规则读取 + 按行为索引"实现。
  2. 本轮没有"函数执行结果"这类状态：`RunImpl.calledTools` 只记工具名（且含本体行为与内置工具），语义不同，MUST NOT 复用；记录需要独立的轮内载体。
  3. 工具结果目前只有"放行/拒绝"两态（020），没有"结果后处理"——后置提示需要一处统一的结果追加点，且必须与落盘文本同源（宪章原则二）。
  4. "中止整轮"目前只有用户主动中断（`ABORTED`）一条路径；本特性**不新增业务中止路径**，规则拒绝改为挂起本轮工具（软收尾），只复用 `ABORTED` 作为"模型固执重试"的兜底出口。
  5. 规则求值没有任何实现，`rule_design` 的算子集合与比较口径尚无代码约定（本规格 `FR-018`~`FR-021` 首次定义）。
  6. "本轮可用的工具集合"目前只以数组形式在装配处短暂存在（`availableTools`），没有作为**判据**被消费过；注册校验（`FR-041`~`FR-043`）需要把它按同一名称归一后交给闸门，MUST NOT 另建一份"已注册函数"清单。

## 口径决策（2026-11-09 本次收敛）

> 本表记录**决策来源与理由**，不构成第二套口径。判定语义以功能需求为唯一正本；两者冲突时以功能需求为准，并回写本表。

| # | 决策 | 理由 |
|---|---|---|
| 1 | 记录值取**结构化对象**而非原始文本 | 规则按 `field` 读字段；存文本等于让求值模块再写一套解析 |
| 2 | **每一次调用都记**，失败/无结果记 `null`；同名多次取**最后一次**（失败亦覆盖） | 用户 2026-11-09 明确要求 `value` 在"结果不存在或执行报错"时为 `null`；键存在即"已执行"，故失败不能被当成"还没跑"去触发暂停 |
| 3 | 记录键用**去服务前缀**的函数名 | `related_functions` 写的是裸函数名；用带前缀名必然全部"未执行" |
| 4 | 缺函数 → **暂停**（不中止） | 这是模型能自愈的状态；一缺函数就中止会让多工具协作的行为完全不可用 |
| 5 | 求值 `false` → **拒绝 + 中止整轮** | 用户明确要求"拒绝执行并中止整个对话"；也让"未通过校验的数据"不可能被后续步写入 |
| 6 | 缺 `rule_design` 的前置规则**不阻断** | 存量数据里存在这种规则（有 `related_functions`、无 `rule_design`），阻断会让该行为永久不可用 |
| 7 | 结构非法 / 未知算子 → 条件不成立 → 中止 + 告警 | 与 020 的 fail-closed 一致：配置异常必须暴露，不能变成"悄悄放行" |
| 8 | 多条前置规则按"逻辑与"，缺函数检查先于求值 | 任一规则不成立即不该执行；先处理可自愈的暂停，避免用中止掩盖"还没算" |
| 9 | 后置提示只在**执行成功**时追加 | 失败结果已自带原因，再附推导提示会让模型误解为"可以继续推理" |
| 10 | 行为与规则的匹配口径为**去空白 + 大小写不敏感**，`position` 不做语义猜测 | 与 020 的命名口径一致；凭空猜 `pre`/`前` 等同义词只会制造不可解释的行为 |
| 11 | 不开"关闭闸门"的开关 | 本需求的目的就是让规则生效；要放开就改规则，单一来源 |
| 12 | 记录不落盘、不进历史 | 用户明确要求"每次对话重新创建"；落盘还会让下一轮出现"看似已校验"的假象 |
| 13 | 缺函数时**先查注册**：已注册 → 暂停（可自愈）；未注册 → 阻断（不可自愈） | 用户 2026-11-09 明确要求；"函数根本不存在"不是模型补调能解决的状态，让它一直暂停只会把配置错误伪装成正常等待 |
| 14 | 注册口径 = **本轮挂载给模型的工具集合**（非服务全集、非 `functions[]` 声明） | 只有挂载给模型的函数才可能被执行；用服务全集会让白名单过滤后的函数永久暂停，用声明则把"写进产物"误当"可调用" |
| 15 | 后置规则的注册校验放在**执行成功之后**（选 B） | 用户选择；后置规则只承担"推导引导"，但其函数不存在属配置错误，故执行后仍要中止并如实说明"数据已写入" |
| 16 | 阻断复用中止码，靠 `details` / 日志 `reason` 区分三类原因 | 码表保持 2 个，前端只维护一条映射；运维按 `reason` 仍能精确区分"配置坏"与"条件不成立" |

## 假设

- **轮的定义**：一轮 = 一条用户消息触发的一整轮（含该轮内多次模型调用与工具循环）；中断或失败同样视为该轮结束，记录随之丢弃。
- **数据来源**：`rules` 由本体市场提供并整包下发，平台不编辑；管理员改规则的入口在本体侧，改完重新部署即生效。
- **命名约定**：`related_functions` 里的函数名与 MCP 工具名一致（现状成立）；不同名时该函数永远被视为"未执行"，表现为持续暂停，而不是静默通过。
- **结果形态**：函数返回的业务数据可解析为对象或数组（现状成立：校验类函数返回 `{ pass }`、日期类返回 `{ date }`、筛选类返回计数或列表）。
- **模型行为**：暂停后模型会按提示补调函数并重试该行为；若模型不重试，本轮就以"该行为未执行"收尾，不视为系统缺陷。
- **拒绝后的用户操作**：拒绝是软收尾（本轮正常结束、不产生失败轮），用户看完说明后可重新发起请求；不提供"从拒绝处继续"的能力。模型固执重试触发兜底纯中止时按既有 `ABORTED` 处理。
- **文案语言**：暂停与拒绝文案均为中文，面向终端用户可读；错误码只进日志与结构化字段。
- **性能基线**：规则读取与求值均为同步内存操作，不引入外部依赖、不发起网络请求；规则与函数记录都不做持久化。
- **测试口径**：用例以本地桩数据构造本体、规则与工具结果，不依赖真实 MCP 服务与真实 LLM。
