# 特性规格：只有附件也能发送（2026-11-18）

**特性编号**：026　**状态**：已实现（v1.0）　**影响侧**：frontend（**无后端与契约变更**）

## 1. 目标

用户往聊天区粘一个文件、或从「+」传一个文件，然后**什么都不写**，现在的发送按钮是灰的——因为发送链路把「正文非空」当前置条件（服务端 `POST /api/threads/{id}/messages` 的 `content` 是 `minLength: 1` 的必填字段）。这是"设计如此"，但对用户毫无道理：文件都选好了，意图已经足够明确。

本特性让这种消息**发得出去**，且**不改服务端契约**。

## 2. 方案选择（为什么不做"正文可空"）

| | 方案 A：发送时合成默认话术（**采纳**） | 方案 B：放宽"正文可空" |
|---|---|---|
| 后端 schema | 不动（`content` 恒非空） | 改必填/加跨字段校验 |
| 会话标题 | 不动（取首条正文前 20 字，标题非空） | 空正文 ⇒ 标题为空串，左栏出现空白行 |
| 意图聚焦 | 不动（有正文可判） | 需新增 `skip:empty_content` |
| 术语替换 018 | 合成时跳过 | 必须跳过（否则每次 400） |
| 气泡 / 导出 / 回放 | 不动 | 要处理空正文占位、复制按钮、导出空行 |
| 落点 | **3 个前端文件** | 10 处（含后端与契约） |

结论：合成一句常量话术，把"空正文"这个状态在**进入不可逆链路之前**消掉，是成本最低且语义最干净的做法。

## 3. 功能需求

| 编号 | 需求 |
|---|---|
| **FR-001** | 触发条件 MUST 精确：正文剥掉 `@文件名` 标记与 `/技能名` 标记、并 `trim()` 后为**空**，且本条消息 `attachments.length ≥ 1` → 用合成话术作为 `content`。任一条件不满足 MUST NOT 合成（有正文时逐字原样提交）。 |
| **FR-002** | 话术口径 MUST 为：1 个附件 → `请查看这个文件`；≥2 个 → `请查看这些文件`。**动词用「查看」不用「解析」**（图片类附件 `read_file` 只支持文档类型，说"解析"会诱导一次注定失败的工具调用）；**不带文件名**（路径由服务端追加的 `[引用文件] …` 段承载，正文重复列名是浪费预算）。 |
| **FR-003** | 合成 MUST 发生在**唯一发送链路**（`useChatPanel.onSend`，即 `@` 剥离之后、拦阻性检查之前），MUST NOT 放在 `Composer`：手输、重试、卡片、重新生成都过这一处，旧历史里空正文轮次的重试也因此被覆盖。 |
| **FR-004** | 输入区 MUST 同步放行：`Composer.canSend` 与工具栏 `:can-send` MUST 在"正文为空但引用集合非空"时可用；**流式中 MUST 仍保持禁用**（不得因 `\|\| references` 绕过 `sending`）。 |
| **FR-005** | 合成话术 MUST 跳过 018 术语替换预检（机器生成的句子不得触发"是否替换"弹窗）。 |
| **FR-006** | 既无正文、也无附件（含只打了 `/技能名`、或正文只有空格）MUST 仍被拦截并提示「请输入消息内容」，行为与改造前一字不差。 |
| **FR-007** | 服务端契约 MUST NOT 改动：`content` 仍是必填且 `minLength: 1`；附件路径仍由 `[引用文件] …` 段交给模型。本特性 MUST NOT 触碰 `POST /api/threads/{id}/messages` 的校验、`threads` 存储格式与前后端 DTO。 |

## 4. 验收场景

1. 「+」上传一个文件、不写字 → **发送按钮可用**，点发送后气泡显示「请查看这个文件」+ 附件胶囊。
2. 上传两个文件、不写字 → 显示「请查看这些文件」。
3. 输入正文 + 附件 → 正文**逐字不变**（无任何追加）。
4. 只打 `@文件名`（不写字）→ 以前是"按钮亮但点了报错"，现在正常发出并合成话术。
5. 什么都不选/只打空格 → 仍提示「请输入消息内容」，不发请求。
6. 流式中（回答未结束）→ 发送键仍禁用（不可借"有附件"绕过）。
7. 空正文历史轮次的「重试本轮」→ 同样被合成话术覆盖，可重发。

## 5. 已知取舍

- **左栏会话标题会重名**：标题取首条消息前 20 字，纯附件会话都叫「请查看这些文件」。用户已拍板不带文件名，故接受；后续若要解决，最小改法是让话术带上文件名（不涉及后端）。
- **图片附件仍不可被模型读取**（`read_file` 仅支持 `.csv/.xlsx/.xls/.txt/.json/.pdf/.md/.log/.html`）：话术只是把消息发出去，模型读图仍会如实回"不支持"。属既有能力边界，不在本特性范围。
- 话术**不会回填输入框**：发送后输入框是空的，气泡里是合成句；用户若想改措辞只能自己打字（不引入"可编辑的默认话术"这类额外状态）。
