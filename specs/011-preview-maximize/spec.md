## 原始输入

> 我们聊天区里，点击 viewUrl 会跳转到一个页面（iframe，只针对同源的），这个页面上，我需要增加一个按钮，在关闭符号 x 的左边，
> 增加一个放大页面按钮，就像 workbuddy 点开的文件，右上角有一个按钮，点击后平铺到整个页面，放大后，可以缩小恢复。

**逐句落点**（避免后续理解漂移）：

| 原话 | 本规格的落点 |
|---|---|
| "点击 `viewUrl` 会跳转到一个页面（iframe，只针对同源的）" | 已有的**同源预检 + 面板内 iframe** 机制（`TR-41`/`usePreview.openView`），本特性**不改动**其判定与降级口径 |
| "在关闭符号 x 的左边，增加一个放大页面按钮" | 入口位置 = 面板头部动作区内、**「收起」按钮左侧**（`FR-001`） |
| "就像 workbuddy 点开的文件，右上角有一个按钮，点击后平铺到整个页面" | 交互范式：一键把**预览内容**平铺到**整个视口**，压住三栏骨架的其余部分（`FR-003`） |
| "放大后，可以缩小恢复" | 同一个入口可逆切换，恢复后界面与放大前**一致**（`FR-004`） |

> **澄清结论（2026-10-16，Q1 = C）**：放大入口只给**有版面**的预览形态——**同源 `viewUrl` 的 iframe 页面**、以及本地文件中的 **PDF 与图片**；
> **纯文本预览**与**「需下载」引导（含预检失败的错误态）不加**。理由：原话锚定的是"这个页面"，"workbuddy 点开的文件"类比指向的是**成版面的内容**
> （报表页 / PDF / 图片）；文本流本身不因宽度变宽而更可读，下载引导页更是没有可放大的内容。该口径即 `FR-010`，并由 `FR-013` 钉住"范围外零出现"。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 一键平铺、一键还原（优先级：P1）

用户在回答里点开一个 `viewUrl` 入口（同源 → 右侧面板内 iframe 渲染）；同样的处境也会发生在文件空间里打开的 PDF 与图片上。
这份内容明显不是给 1/3 宽准备的：表格被挤成一列、图表看不全、图纸看不清。他点面板头部「收起」左侧的**放大**按钮，
预览内容**平铺到整个视口**，其余两栏被压在下面；看完再点同一位置（此时是**缩小**），界面回到放大前的一模一样：
宽度、滚动位置、内容都还在，没有重新加载、没有闪白。

**为什么是这个优先级**：这是本次诉求的**全部价值所在**——其余条目都是它的约束条件（位置、可逆、不打扰）。

**独立测试**：挂载 `WorkspacePanel`（内容态三种**可放大**目标：同源 `kind:'url'` + `renderMode:'iframe'`、`content.renderMode:'pdf'`、`content.renderMode:'image'`）
与工作台视图，断言：① 放大入口存在且 DOM 顺序在「收起」按钮**之前**；② 触发后出现平铺态（根节点带放大态标记 / 视口内其余栏不可见）；
③ 再次触发后标记消失且面板宽度、预览目标的 DOM 节点未被替换（同一 `iframe` 元素仍在，`src` 未被重设）；
④ 三种**范围外**目标（`renderMode:'text'` / `'download'` / `'error'`）下入口**零出现**。

**验收场景**：

1. **Given** 面板处于内容态且顶部动作区可见，**When** 观察动作区，**Then**「收起」按钮左侧有一枚可点的「放大页面」入口
   （`aria-label` 明确表达"放大"而非仅有图标）。
2. **Given** 正在看一个同源 iframe 入口，**When** 点击「放大页面」，**Then** 预览内容平铺**整个视口**：左栏（历史会话）与中栏
   （聊天区）都不再可见，预览区可用的宽度与高度等于视口。
3. **Given** 已处于放大态，**When** 观察同一入口，**Then** 它已变为「缩小」（文案与 `aria-label` 同步变更，不得只换图标不换语义）。
4. **Given** 已处于放大态，**When** 点击「缩小」，**Then** 界面**精确**回到放大前：面板宽度与放大前相同、分隔条仍可拖拽、
   其余两栏恢复可见，且预览内容**没有被重新加载**（用户视角：无闪白、无加载态、滚动位置保持）。
5. **Given** 已处于放大态，**When** 点击面板头部的「收起」（X），**Then** 面板收起且放大态一并退出；再次打开内容态时是**正常**
   宽度（不得"一打开就是全屏"）。
6. **Given** 已处于放大态，**When** 在面板内切换到另一个预览目标（点另一个文件 / 另一个入口），**Then** 新内容仍然占据整个视口
   （放大态跟随内容保留），且**不出现**旧内容的残留（`FR-012`）。
7. **Given** 处于放大态，**When** 刷新页面，**Then** 回到**非**放大态（放大态不持久化）。
8. **Given** 预览是一份**纯文本**文件（`.txt` / `.csv` / `.json`），**When** 观察动作区，**Then** **没有**放大入口（除「收起」外不新增任何按钮）。
9. **Given** 预览是**需下载**的入口（预检为 `download`）或**预检失败的错误态**（`error`，含"下载完整文件"引导），**When** 观察动作区，
   **Then** **没有**放大入口——动作区与改动前**逐像素一致**（`FR-013`）。
10. **Given** 预览是本地 **PDF** 或**图片**，**When** 点击放大入口，**Then** 与同源 iframe 表现一致（平铺整个视口、同一入口可缩小恢复，
   且 PDF / 图片**不重新加载**）。

### 用户故事 2 - 键盘可用、可退出、不误伤回答（优先级：P2）

键盘用户不用鼠标也能放大：Tab 到入口、Enter / Space 触发；看完按 Esc 退出放大。关键在于：**Esc 只退出放大，不会顺手掐掉
正在输出的回答**——而"Esc 中断本轮"是这个工作台里已有的行为（`ChatPanel` 监听全局 `window` 的 Esc）。

**为什么是这个优先级**：宪章原则四要求所有交互控件键盘可达；而 Esc 的**冲突**是本次改动唯一可能"误伤用户"的地方
（一次 Esc 让正在生成的长回答被中断），优先级仅次于主线。

**独立测试**：组件测试断言入口为原生按钮（Tab 可达、有可见焦点环、Enter / Space 派发事件）；放大态下按 Esc 断言放大态退出
且"中断本轮"的回调**未被调用**（事件被拦下，不冒泡到全局处理）。

**验收场景**：

1. **Given** 焦点在「放大页面」入口上，**When** 按 Enter 或空格，**Then** 进入放大态（与鼠标点击等价）。
2. **Given** 已处于放大态，**When** 按 Esc，**Then** 退出放大态；**且**本轮若正在输出回答，回答**不被中断**。
3. **Given** 未处于放大态，**When** 按 Esc，**Then** 行为与改动前**完全一致**（有回答在输出时仍按既有口径中断）。
4. **Given** 焦点位于放大态下的面板头部，**When** 观察焦点环，**Then** 焦点可见（不被平铺层遮蔽或裁掉）。
5. **Given** 系统开启"减少动效"，**When** 切换放大 / 缩小，**Then** 过渡降级为静态（不出现动画）。

### 用户故事 3 - 不打扰正在进行的会话（优先级：P2）

用户一边放大看报表，一边 agent 还在输出。放大期间：中栏的聊天不会被卸载或重建——消息滚动位置、输入框里打了一半的草稿、
历史会话列表的选择状态都还在；缩回去什么都不缺。

**为什么是这个优先级**：这是"放大"这个动作最容易踩的坑（用"隐藏 / 销毁其余栏"来实现平铺，会把草稿和滚动位置一起丢掉），
而不打扰是工作台的默认承诺。

**独立测试**：在工作台视图中进入放大态，断言中栏与左栏的组件实例**未被销毁**（挂载计数不增加 / 输入框内的文本仍在），
退出后中栏滚动位置与草稿文本与进入前一致。

**验收场景**：

1. **Given** 输入框里有一段未发送的草稿，**When** 进入放大态再退出，**Then** 草稿原样保留。
2. **Given** 消息列表滚动到非底部位置，**When** 进入放大态再退出，**Then** 滚动位置保持（不被重置为底部）。
3. **Given** agent 正在流式输出，**When** 进入放大态并停留，**Then** 输出**继续**（界面与请求都不被中断）；
   退出后中栏呈现的是当前的完整内容。
4. **Given** 已处于放大态，**When** 窗口尺寸变化（拖拽窗口 / 改变分辨率），**Then** 预览区仍然铺满视口（不出现露出底层栏的缝隙）。
5. **Given** 视口很窄，**When** 进入放大态，**Then** 预览区仍可用（内容不被裁切成不可操作）。

### 边界情况

- **列表态**：面板停在文件空间列表时**没有**放大入口（三栏骨架里也没有可放大的预览内容）。
- **不可内联的入口**（预检为需下载）：本特性**不改变**其"面板给外部打开入口"的既有口径；该态**不提供**放大入口（`FR-010` 的澄清结论 Q1 = C）。
- **纯文本预览**（`.txt` / `.csv` / `.json`）：**不提供**放大入口——文本流不因变宽而更可读，加了只是多一枚无效按钮。
- **错误态**（预检失败 / 拉取超限或不存在）：**不提供**放大入口（该态的出口是"下载完整文件"，不是"看得更大"）。
- **放大态下的破坏性操作**：放大态不涉及任何写操作（只切界面），MUST NOT 引入二次确认弹窗。
- **放大态下要点「收起」**：X 必须仍然可达（`FR-005`），否则用户会"放进去出不来"。
- **面板被拖动过宽度**：先拖窄、再放大、再缩小，宽度 MUST 回到拖窄后的值（而不是默认 1/3）。
- **预览目标在放大态下消失**（例如文件被删除）：按既有口径退回列表态，放大态一并退出（不留在空的全屏面板上）。
- **极窄视口 / 极矮视口**：预览区高度不为负、不出现横向滚动条（内容占满且自身滚动）。
- **首帧**：放大态不写地址栏、不入 `sessionStorage`（刷新即回到非放大态）。

## 需求 *(必填)*

> 每条附「验证方式」，与 `tasks.md` 的测试任务一一对应。

### 功能需求

#### A. 入口与位置（US1）

- **FR-001**: 当一个**可放大**目标（见 `FR-010`）处于内容态时，面板头部 MUST 在「收起」（X）按钮**左侧**提供一枚"放大页面"入口；
  该入口 MUST 与既有按钮同一动作区位、同一视觉等级（不新增工具条、不改变既有按钮顺序）。
  *验证方式*：`WorkspacePanel.spec.ts` 断言入口存在、DOM 顺序为「… → 放大 → 收起」、`aria-label` 含"放大"。
- **FR-002**: 入口 MUST 是**单个**可逆控件（放大 / 缩小同一位置），MUST NOT 出现"放大一个、缩小另一个"两枚按钮。
  *验证方式*：同一用例断言动作区内匹配项唯一，且切换前后是同一个 DOM 节点。
- **FR-005**: 放大态下头部 MUST 保持可见，「缩小」与「收起」两个出口 MUST 都可点（MUST NOT 被平铺层覆盖或裁掉）。
  *验证方式*：放大态下断言两枚按钮 `exists()` 与可点击（触发后状态确实变化）。
- **FR-010**: **可放大范围**（澄清结论 2026-10-16，Q1 = C；2026-10-20 增补 `.html`）MUST 恰为"有版面的预览"三组：
  ① **同源 `viewUrl` 入口的内联渲染**（`target.kind:'url'` 且 `renderMode:'iframe'`）；
  ② **本地文件的 PDF 与图片预览**（`content.renderMode:'pdf' | 'image'`）；
  ③ **本地 HTML 预览**（`content.renderMode:'html'`，2026-10-20 随 `.html` 可上传与沙箱内联新增，与 PDF 同属"有版面"）。
  **范围之外 MUST NOT 提供入口**：`renderMode:'download'`（含同源预检为需下载的入口与不支持内联的文件类型）、
  `renderMode:'text'`、`renderMode:'error'`、`target.kind:'none'`、`view:'list'`。
  该判据 MUST **只有一处实现**（宪章原则二），MUST NOT 在模板与脚本里各判一套。
  *验证方式*：**判据矩阵与消费点分开测**（2026-10-16 由 `/speckit.plan` 细化落点，见「修订记录」）——
  9 例判据矩阵（范围内 4 例 + 范围外 5 例）钉在**判据所在模块** `usePreview.spec.ts`；
  `WorkspacePanel.spec.ts` 钉 **prop → 渲染映射**（入口有 / 无、两态可访问名称）。
  如此"可放大范围"只有一处实现（`usePreview`），面板侧不再对 `target` / `content` 判第二遍。
- **FR-011**: 列表态、以及内容态**无任何可预览目标**时 MUST NOT 渲染该入口（无 DOM 即无占位）。
  *验证方式*：`view: 'list'` 与 `target: { kind: 'none' }` 两类空态用例断言入口不存在。
- **FR-013**: 范围外的内容态（文本 / 需下载 / 错误态）MUST 与改动前**完全一致**：MUST NOT 新增任何入口，动作区、内容区、
  文案与行为 MUST NOT 发生任何变化。*验证方式*：`WorkspacePanel.spec.ts` 既有用例全绿（不改断言口径）
  + 三类范围外态的"动作区按钮集合不变"断言。

#### B. 平铺与恢复（US1）

- **FR-003**: 触发放大后，预览区 MUST 平铺**整个视口**（宽高都等于视口），MUST NOT 只在中栏/右栏范围内放大。
  *验证方式*：断言根节点带放大态标记 + 放大态下其余两栏不呈现（样式/结构断言），并由人工确认项复核视觉。
- **FR-004**: 再次触发 MUST **精确恢复**放大前的界面：面板宽度与放大前**相同**（含用户曾拖拽调整过的像素宽度）、
  分隔条仍可拖拽、其余两栏恢复可见。*验证方式*：先拖拽设置一个非默认宽度 → 放大 → 缩小 → 断言宽度值不变。
- **FR-006**: 放大 / 缩小 MUST NOT 重新加载预览内容：预览目标不变、承载内容的节点 MUST NOT 被替换、地址 MUST NOT 被重设。
  *验证方式*：断言 `iframe` 元素引用在切换前后相同、`src` 未被重设（若实现引入 `key` 或条件渲染导致重建，该用例必红）。
- **FR-007**: 放大态 MUST 是**瞬态**界面状态：不持久化、不写地址栏；刷新、关闭面板、切回列表态后 MUST 回到非放大态。
  *验证方式*：关闭面板与 `backToList` 两条收敛用例 + 「刷新回到非放大态」由"仅内存状态、无任何持久化写入"结构性保证（含
  与 `sessionStorage` / URL 无关的断言）。
- **FR-012**: 放大态下切换预览目标（另一个文件 / 另一个入口）MUST **保持**放大态，且 MUST NOT 残留上一个目标的内容。
  *验证方式*：放大态下替换 `target`，断言仍为平铺且渲染的是新目标。

#### C. 键盘与无障碍（US2，宪章原则四）

- **FR-020**: 入口 MUST 为原生按钮语义（Tab 可达、Enter / Space 触发、`type="button"`），MUST 有可见焦点环。
  *验证方式*：组件测试（键盘触发 + `focus()` 后焦点环相关类/样式断言）+ 人工确认项。
- **FR-021**: 放大态下 Esc MUST 退出放大态，且 MUST **拦下**该按键使其不触发"Esc 中断本轮回答"（事件不得冒泡到全局处理）；
  非放大态下 Esc MUST 保持改动前的既有行为。*验证方式*：两条用例（放大态中断未发生 / 非放大态中断照常）。
- **FR-022**: 状态 MUST NOT 只靠图标或颜色传达：入口 MUST 以 `aria-label`（或等价的 `aria-pressed` + 文案）区分
  "放大页面"与"缩小页面"两态。*验证方式*：切换前后断言可访问名称不同。
- **FR-023**: 放大态切换 MUST NOT 抢走或丢失焦点：触发后焦点 MUST 仍落在该入口（或明确落到平铺内容上并可见）。
  *验证方式*：组件测试断言 `document.activeElement`。
- **FR-024**: 若引入过渡动效，MUST 在 `prefers-reduced-motion: reduce` 下降级为静态。
  *验证方式*：样式断言 + 人工确认项（无过渡的纯状态切换则标注"不适用"）。

#### D. 不打扰与不越界（US3、宪章原则五 / 九）

- **FR-030**: 进入 / 退出放大态 MUST NOT 卸载或重建左栏与中栏（消息列表滚动位置、输入草稿、历史列表选择状态 MUST 保持）。
  *验证方式*：工作台视图用例（草稿文本与滚动位置在切换前后一致；组件挂载计数不因切换增加）。
- **FR-031**: 放大态 MUST NOT 影响会话与请求：正在进行的流式输出、会话切换、"停止 / 中断"等能力 MUST 全部照常
  （它只改变视觉呈现，不改变任何业务状态）。*验证方式*：放大态下断言发送 / 停止入口的状态与行为不变。
- **FR-032**: 放大态下若预览目标失效（文件被删除等），MUST 按既有口径收敛（退回列表态或空态）并同时退出放大态，
  MUST NOT 停留在空的全屏面板上。*验证方式*：删除当前预览文件的用例 + 目标置空用例。
- **FR-033**: 窗口尺寸变化（含 `ResizeObserver` 缺失的测试环境）MUST NOT 使放大态失效；缺 API 时 MUST 有存在性守卫。
  *验证方式*：存在性守卫用例（jsdom 无该 API 时不抛错）+ 人工确认项。
- **FR-034**: 平铺 MUST NOT 破坏既有降级口径：既不改变同源预检与"异源直跳 / 需下载给外部入口"的分派，也不新增任何
  "假装正常"的静默分支；放大态下出现渲染失败时 MUST 沿用既有错误呈现（宪章原则九）。*验证方式*：既有 `WorkspacePanel.spec.ts`
  用例全绿 + 放大态下的错误态用例。

#### E. 工程质量（宪章原则二 / 三 / 六，本次改动的自检）

- **FR-040**: MUST **零新增依赖**（不引入图标库、不引入全屏 API 封装库）。*验证方式*：`frontend/package.json` 依赖段 `git diff` 为空。
- **FR-041**: 本次改动与新增的每个 `.ts` / `.vue` MUST ≤ **500 行**（含改动后的 `WorkspacePanel.vue`）；超出时按
  "拆子组件 / 抽 `useXxx` / 抽纯函数"收敛。*验证方式*：`tasks.md` 末登记实测行数。
- **FR-042**: 本次新增或实质改动的模块 MUST 有**一一对应的同名测试**，且语句覆盖率 ≥ **80%**；全局覆盖率地板只上不下。
  *验证方式*：目录比对 + `npm run test:coverage` 实测值回写（含 `vite.config.ts` 阈值清单登记）。
- **FR-043**: 本特性 MUST NOT 触碰 `agent-backend` / `admin-backend` / `admin-frontend` 与任何接口契约
  （无新增端点、无字段变更、无事件变更）。*验证方式*：改动文件清单比对（仅 `frontend/**`）。

### 关键实体

- **预览目标（`PreviewTarget`）**：面板内容态当前呈现的对象——本地文件（按扩展名分派）或同源地址（`renderMode: iframe | download`）。
  放大态**依附于它**，不改变它。
- **放大态（本特性新增的界面状态）**：二值瞬态状态（正常 / 平铺），归属由 `plan.md` 定（候选：`usePreview` 的会话态、或工作台视图的局部状态）；
  唯一真源，MUST NOT 在组件内另立影子标志（宪章原则二"同一职责只有一处实现"）。
- **面板视图（`PanelView`）**：`list | content`。放大只在 `content` 有意义，`list` 下入口零出现。

> 本特性**不涉及数据**：无落盘、无接口字段、无持久化键。

## 成功标准 *(必填)*

- **SC-001**: 位置一次到位——放大入口与「收起」的相对位置在所有内容态下一致（不因目标类型左右漂移）。
- **SC-002**: 一次点击即平铺——从一个 1/3 宽的预览到铺满视口，只需一次点击，无中间步骤、无二次确认。
- **SC-003**: 可逆且无损——缩小后界面与放大前一致（宽度、内容、滚动位置），预览**不重新加载**（用户可感知：无闪白、无等待）。
- **SC-004**: 零附带损失——放大 / 缩小往返一次后，输入草稿与消息滚动位置**逐字 / 逐像素**保持。
- **SC-005**: 键盘完整可用——Tab 可达、Enter / Space 可切换、Esc 可退出，且 Esc **不会**中断正在输出的回答。
- **SC-006**: 门禁全绿（前端本地）：`npm run lint` / `npm run typecheck` / `npm run test:coverage` / `npm run build` 全部通过；
  零新增依赖；改动文件 ≤ 500 行。
- **SC-007**: 后端零改动（`git diff` 中不含 `agent-backend/**` 与任何契约文档）。
- **SC-008**: 范围外零变化——纯文本、「需下载」与错误态三类面板的动作区、内容区与文案与改动前**完全一致**（无新按钮、无位移）。

## 假设

1. **只涉及聊天前台单侧**：`viewUrl` 的抽取（后端 `TR-44`）、入口行渲染（`TR-47`）、同源预检与渲染分派（`usePreview`）**一律不变**；
   本特性只增加"已经渲染出来的预览如何占据更大的视觉空间"。
2. **放大 = 覆盖整个视口**（"平铺到整个页面"按"铺满浏览器视口"理解），**不是**浏览器原生全屏（后者会把整个应用连同 x 一起藏起来，
   与"缩小恢复"的诉求不匹配，且不满足"X 仍可达"）。
3. **放大态随"预览目标"存在，随"面板关闭 / 回到列表"消失**；目标变化时保持放大态（`FR-012`）。
4. **其余两栏不卸载**，只被覆盖/隐藏（`FR-030`）——这是"不丢失草稿与滚动位置"的前提。
5. 面板头部在放大态仍可见（`FR-005`）；这与"平铺"不矛盾：平铺的是**内容区**，头部是**出口**。
6. **Esc 优先级 = 先退出放大**（`FR-021`）；非放大态下既有"Esc 中断本轮"行为**零变化**。
7. 移动端 / 触屏手势不在本次范围（与既有三栏工作台一致）。
8. 按已收敛的 Q1 = C 口径实现（`FR-010`）：**有版面的预览**可放大（同源 iframe 页面 / PDF / 图片），文本与需下载、错误态不加。
