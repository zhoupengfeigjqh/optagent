# 特性规格：用户登录与鉴权（2026-11-17）

**特性编号**：024　**状态**：Draft　**影响侧**：四侧（`admin-backend` / `admin-frontend` / `agent-backend` / `frontend`）；`gateway` 无需改路由，部署编排（`docker-compose.yml`）需为运行侧与平台侧注入同一份凭据校验密钥

## 1. 目标

为聊天前台增加登录能力：数字人管理平台在**新建用户**时一并设置该用户的密码；用户在聊天前台以「用户标识 + 密码」登录，登录通过后才能进入聊天页面。

采用**方案 A**（已在调研中与用户确认）：数字人管理平台是账号与密码的**唯一权威源**，登录时由平台校验密码并签发登录凭据；运行环境**不接触密码**，只对凭据验签并据此确定"当前用户"。登录打通后，既有的"按用户划分数据域"机制自然生效——每个用户只能看到/操作自己被分配的数字人、会话与文件。

**范围边界**：本期只保护**聊天前台**（`frontend`）；管理台（`/admin/`）自身的登录保护不在本期范围（其错误码已在既有契约中预留）。本期只做"新建用户时设置密码 + 登录 + 登出 + 单会话（同一账号同时只一人，后登踢前登）"，不含"重置密码 / 用户自助改密"。

## 2. 用户故事

### 用户故事 1 - 管理员新建用户时设置初始密码（优先级 P1）

管理员在数字人管理平台新建一个业务使用者时，除了填写用户标识与勾选关联数字人，还要为该用户设置一个初始密码，密码随用户记录一并保存，供该用户登录聊天前台使用。

**为何此优先级**：密码是登录的前提；没有这一环，后续所有登录故事都无法验证。

**独立测试**：仅在管理台新建一个用户并设置密码即可完成验证；随后可用该账号密码登录聊天前台（串起故事 2）。

**验收场景**：

1. **Given** 管理员打开"新建用户"弹窗并填写用户标识、关联数字人、设置密码，**When** 提交，**Then** 创建成功，该用户出现在用户列表中。
2. **Given** 管理员新建用户时密码为空或长度不满足最低要求，**When** 提交，**Then** 创建被拒绝，弹窗内给出可读提示且已填内容不丢失。
3. **Given** 用户已创建，**When** 在用户列表或任意详情/日志中查看该用户，**Then** 任何地方都看不到明文密码。

---

### 用户故事 2 - 用户在聊天前台登录（优先级 P1）

用户打开聊天前台，若尚未登录则看到登录页，输入自己的「用户标识 + 密码」，校验通过后进入聊天工作台。

**为何此优先级**：这是本特性的核心诉求——"登录通过后才能进入聊天页面"。

**独立测试**：仅用正确的账号密码完成一次登录即可验证，无需依赖其它故事。

**验收场景**：

1. **Given** 用户输入正确的用户标识与密码，**When** 点击登录，**Then** 成功进入聊天工作台。
2. **Given** 用户输入的密码错误或账号不存在，**When** 点击登录，**Then** 停留在登录页并收到统一提示（提示不区分"账号不存在"与"密码错误"）。
3. **Given** 用户登录成功，**When** 之后进行对话、查看数字人等正常操作，**Then** 全程无需再次输入密码。

---

### 用户故事 3 - 未登录访问聊天页面被拦截（优先级 P1）

任何未持有有效登录凭据的人，直接访问聊天页面地址，或被引导到登录页，其调用后端接口的请求被拒绝且拿不到任何业务数据。

**为何此优先级**：这是"必须登录才能进入聊天页面"的直接体现，也是数据隔离的前置防线。

**独立测试**：未登录状态下直接访问聊天页地址、直接调用受保护接口，分别验证"被拦截"与"返回未认证错误"即可。

**验收场景**：

1. **Given** 用户未登录，**When** 直接访问聊天工作台地址，**Then** 被重定向到登录页。
2. **Given** 用户未登录或凭据已失效，**When** 调用任何受保护的聊天接口，**Then** 返回统一的"未认证"错误，响应中不含任何业务数据。
3. **Given** 用户已登录，**When** 刷新聊天页面，**Then** 保持登录态，不被打回登录页。

---

### 用户故事 4 - 登录后按用户隔离数据（优先级 P2）

用户登录后，系统以其登录身份确定"当前用户"，该用户只能看到/操作自己被分配的数字人、会话与文件空间，与其他用户的数据互不可见、互不串扰。

**为何此优先级**：登录的价值最终落在"每个人只看到自己的数据"上；它建立在故事 2/3 之上，但可独立验证。

**独立测试**：分别用两个不同账号登录，各自查看数字人列表、会话与文件空间，验证互不可见。

**验收场景**：

1. **Given** 用户 A 登录，**When** 查看数字人列表，**Then** 只看到分配给 A 的数字人。
2. **Given** 用户 A 与用户 B 分别登录并各自进行对话/上传文件，**When** 双方各自查看，**Then** 数据互不串扰，A 看不到 B 的会话与文件。
3. **Given** 用户 B 尝试访问仅属于 A 的数据入口，**When** 发起请求，**Then** 被拒绝或解析不到任何数据。

---

### 用户故事 5 - 登出与登录态过期（优先级 P2）

用户可主动登出；登录凭据有有效期，过期后继续操作会被引导重新登录。

**为何此优先级**：安全收尾，避免凭据长期有效或无人认领的会话；是完整登录闭环的必要部分。

**独立测试**：登录后执行登出、以及模拟凭据过期，分别验证"回到登录页"与"被引导重新登录"。

**验收场景**：

1. **Given** 用户已登录，**When** 点击登出，**Then** 回到登录页，且该凭据立即失效（再次访问被拦截）。
2. **Given** 用户的登录态已过期，**When** 继续操作（如发消息），**Then** 被明确提示"登录已过期"并引导重新登录，且不产生业务副作用。

---

### 边界情况

- **密码绝不下发/不落日志**：密码明文不得出现在任何接口响应、用户列表/详情、审计日志、错误提示中。
- **存量用户无密码**：既有用户记录没有密码字段；本期定义明确兜底——无密码即无法登录，不提供补设入口（后续特性提供），亦不得静默放行。
- **用户被删除后的既有登录态**：删除用户后该账号必须无法再次登录；其尚未过期的既有凭据如何处理（是否即时失效）作为安全口径在计划阶段确定并测试。
- **同一账号多端登录**：同一账号同时只允许一个有效会话；后登踢前登，被踢端在下一次受保护请求时收到明确提示（"已在其它设备登录"）并回到登录页。
- **错误不泄露账号是否存在**：登录失败时不得通过提示区分"账号不存在"与"密码错误"，避免枚举账号。
- **密码存储损坏/无法校验**：极端情况下应表现为"无法登录"并落入结构化日志，不得静默放行。

## 3. 功能需求

| 编号 | 需求 |
|---|---|
| **FR-001** | 管理员在"新建用户"时 MUST 能够为该用户设置初始密码，密码与用户记录一并保存。 |
| **FR-002** | 密码 MUST 以不可逆摘要保存；任何接口响应、用户列表/详情、日志与审计记录 MUST NOT 出现明文密码或可用于还原明文的材料。 |
| **FR-003** | 新建用户时，密码为空或不满足最低复杂度要求 MUST 被拒绝，并给出可读提示；MUST NOT 因校验失败丢弃已填写的用户标识与关联数字人。 |
| **FR-004** | 聊天前台 MUST 提供登录页，用户以「用户标识 + 密码」登录。 |
| **FR-005** | 登录校验 MUST 以数字人管理平台为唯一权威源；运行环境 MUST NOT 持有、存储或比对任何密码。 |
| **FR-006** | 登录成功后系统 MUST 下发一份**带有效期、可被服务端校验**的登录凭据，凭据携带"当前用户"身份。 |
| **FR-007** | 未登录或凭据失效的用户访问聊天页面 MUST 被引导至登录页。 |
| **FR-008** | 后端 MUST 拒绝缺失或无效凭据的请求，返回统一的"未认证"错误，且 MUST NOT 返回任何业务数据。 |
| **FR-009** | 登录成功后系统 MUST 以凭据中的用户身份确定"当前用户"；该用户的数字人、会话、文件空间 MUST 严格按其既有数据域隔离，MUST NOT 跨用户访问。 |
| **FR-010** | 系统 MUST 提供登出能力；登出后该凭据立即失效，再次访问被拦截。 |
| **FR-011** | 鉴权错误 MUST 使用统一错误格式与全局唯一、语义稳定的错误码；"未携带/凭据失效"（未认证）与"登录失败"（账号或密码错误）MUST 分别有确定且不冲突的语义，登录失败 MUST NOT 区分"账号不存在"与"密码错误"。 |
| **FR-012** | 被删除的用户 MUST 无法再以原账号登录。 |
| **FR-013** | 存量用户（无密码）MUST 有明确可预期的兜底口径：默认无法登录；MUST NOT 因缺失密码而静默放行。管理员补设密码的能力不在本期范围，后续特性提供。 |
| **FR-014** | 同一账号同一时间 MUST 只允许一个有效会话：同一账号再次登录成功后，先前会话 MUST 立即失效（后登踢前登）；先前会话的后续受保护请求 MUST 被拒绝并返回"已在其它设备登录"的明确错误。 |

## 4. 关键实体

- **业务使用者（用户）**：数字人管理平台中"被分配数字人的使用者"（标识即用户标识）；本特性为其增加"密码摘要"属性，与既有"关联数字人清单"同属一条用户记录。
- **登录凭据**：登录成功后由平台签发、携带"用户身份 + 会话标识 + 有效期"的可校验令牌；运行环境验签并校验会话有效性、不接触密码。
- **活跃会话（单会话登记）**：平台为每个账号维护"当前唯一有效会话标识"，用于判定某凭据是否仍为当前会话；新登录覆盖旧会话实现"后登踢前登"。

## 5. 成功标准

| 编号 | 标准 |
|---|---|
| **SC-001** | 管理员能在 1 分钟内完成"新建用户 + 设置密码"的完整操作。 |
| **SC-002** | 用户以正确账号密码登录，从打开登录页到进入聊天工作台在 3 秒内完成。 |
| **SC-003** | 100% 的未登录访问被拦截——访问聊天页被重定向、调用受保护接口返回未认证错误，且不泄露任何业务数据。 |
| **SC-004** | 100% 的错误凭据被拒绝并返回统一提示，不泄露账号是否存在。 |
| **SC-005** | 登录后用户仅能访问自己被分配的数字人、会话与文件，跨用户数据隔离达到 100%（任何用户都无法读取或操作他人数据）。 |
| **SC-006** | 密码明文在任何响应、列表、详情、日志、审计记录中的出现次数为 0。 |
| **SC-007** | 凭据验签对受保护请求的额外耗时 P95 ≤ 5ms，不造成用户可感知延迟；登录、进入聊天页、登出等操作满足项目既有"非推理类反馈 ≤ 100ms、非流式接口 P95 ≤ 500ms"口径（具体测量口径在计划阶段记录）。 |
| **SC-008** | 同一账号后一次登录成功后，先前会话在 ≤ 2 秒内失效：其后续受保护请求返回"已在其它设备登录"，前端引导重新登录。 |

## 6. 假设

- **账号即业务使用者标识**：登录账号 = 数字人管理平台的"用户标识"，而非平台管理员（`zyw_admin`）。
- **凭据载体**：采用服务端下发、浏览器自动携带的方式（方案 A 的 HttpOnly 会话凭据），以兼容聊天前台的流式与状态推送通道。
- **登录态有效期**：采用行业常见默认（如 7 天），具体数值在计划阶段确定并做成可配置。
- **单会话**：同一账号同时只允许一个有效会话；新登录使旧会话失效（后登踢前登），被踢端收到明确提示。
- **密码管理范围**：本期仅"新建用户时设置密码 + 登录 + 登出"；重置密码、用户自助改密不在本期范围。
- **管理台保护范围**：本期仅保护聊天前台；管理台自身的登录保护不在本期范围（既有契约已为其预留错误码，后续可平滑叠加）。
- **存量用户迁移**：存量用户无密码，默认不可登录，由管理员按需补设；不发起对存量用户的批量迁移专项。
- **运行环境不新增密码依赖**：运行环境只做凭据验签与身份解析，不感知密码存储。
- **运行环境降级口径**：运行环境未配置凭据校验密钥时，按**内部单用户模式**放行（回退既有 `admin`），用于回滚与存量单机部署；该降级路径为有意设计（对应宪章原则九），不视作对 `FR-008` 的违反，且启动日志 MUST 显式告警。
- **会话内省降级**：运行环境校验会话有效性依赖平台的会话内省接口；平台暂不可达时按"放行 + 告警"降级（单会话保证在平台故障窗口内临时放宽），不因平台短暂故障锁死所有用户。
