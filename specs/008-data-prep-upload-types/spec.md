## 用户场景与测试 *(必填)*

### 用户故事 1 - 为每个数据准备目录配置可上传文件类型（优先级：P1）

管理员在数字人设计的「文件空间 →「数据准备」二级目录清单」里，看到每个目录行末尾的「字段」与「移除」两个按钮；
现在这两个按钮**之间**多出一个「文件类型」入口。管理员点开它，勾选该目录允许上传的文件类型（候选 10 项），
至少保留 1 项；新建的目录默认已勾选 `.csv` 与 `.xlsx`。保存设计后，重新打开该数字人时勾选状态一致回显。

**为什么是这个优先级**：没有配置入口就无从谈起"配置生效"；它是整个特性的最小可用切片，
且完全在管理端内闭环、可独立演示。

**独立测试**：在管理端数字人设计页新增一个二级目录 → 断言新行出现「文件类型」入口且位于「字段」「移除」之间 →
打开入口 → 断言 9 个候选可见、默认勾选 `.csv` 与 `.xlsx` → 取消全部勾选 → 断言被拒绝并提示至少选一项 →
勾选 `.csv`/`.xlsx`/`.txt` 保存 → 重新打开该数字人 → 断言回显一致。

**验收场景**：

1. **Given** 管理员在数字人设计的「数据准备」目录清单中，**When** 查看任一行目录，**Then** 该行在「字段」与「移除」之间出现「文件类型」入口。
2. **Given** 打开某目录的「文件类型」入口，**When** 查看候选，**Then** 恰好提供 `.xlsx`、`.xls`、`.csv`、`.txt`、`.pdf`、`.json`、`.html`、`.zip`、`.jpg`、`.png`、`.jpeg` 十一项，且新建目录默认已勾选 `.csv` 与 `.xlsx`。
3. **Given** 已勾选若干类型，**When** 管理员取消全部勾选并确认，**Then** 保存被拒绝，并给出"至少选择一种文件类型"的可读提示，勾选状态不变。
4. **Given** 管理员为目录 A 勾选 `.csv`/`.xlsx`/`.txt`，**When** 保存设计并重新打开该数字人，**Then** 目录 A 的入口回显与保存前一致。
5. **Given** 平台预定义目录「算法规则」，**When** 查看其行，**Then** 同样具备「文件类型」入口，且可配置。
6. **Given** 某目录已配置文件类型，**When** 管理员移除该目录，**Then** 该目录的文件类型配置一并移除（不留孤儿配置）。
7. **Given** 键盘用户，**When** 用 `Tab`/`Enter`/`Space` 操作该入口，**Then** 可完整打开、勾选、确认；选中状态有文本可读，MUST NOT 仅以颜色区分。

### 用户故事 2 - 配置生效后，前台按目录限定可上传类型（优先级：P1）

部署后，用户在聊天前台点「+」上传文件并进入某个数据准备目录时，文件选择器只呈现该目录已配置的类型；
若用户绕开选择器的类型过滤（例如手工选到其他类型的文件），该文件会被拒绝，并给出"该目录允许的类型"的可读提示。
前台提示与服务端判定必须一致：不存在"界面允许但服务端拒绝"或反之的错配。

**为什么是这个优先级**：这是本特性对用户可见的价值兑现点（配置是否真的生效），且它决定上传链路的正确性。

**独立测试**：把目录 A 配为 `.csv`/`.xlsx`/`.txt` 并部署 → 前台进入 A 目录上传 → 断言选择器只显示这三类 →
断言提交 `.pdf` 被拒绝且提示列出允许类型 → 断言提交 `.txt` 成功落盘，且目录内文件与其他目录互不影响。

**验收场景**：

1. **Given** 目录 A 配置为 `.csv`/`.xlsx`/`.txt` 且已部署，**When** 用户在前台 A 目录点「+」上传，**Then** 文件选择器只显示这三类文件。
2. **Given** 同上，**When** 用户提交一个 `.pdf` 文件，**Then** 上传被拒绝，且界面提示说明"该目录允许的类型"，MUST NOT 只抛出错误码。
3. **Given** 同上，**When** 用户提交一个 `.txt` 文件，**Then** 上传成功，文件出现在 A 目录下。
4. **Given** 目录 A 与目录 B 配置不同，**When** 分别在 A、B 上传同一类型的文件，**Then** 各自按本目录的白名单判定，互不影响。
5. **Given** 目录的白名单在界面上已生效，**When** 服务端判定同一文件，**Then** 两端结论一致（双端一致拒绝或一致放行）。

---

### 用户故事 3 - 共享空间与临时空间行为不变（优先级：P1）

无论数据准备目录如何配置，共享空间与临时空间的可上传类型与今天完全一致；管理员也无法在本次入口中改动这两个空间。

**为什么是这个优先级**：这是本特性的"不越界"约束——越界即回归缺陷，必须在规格里与功能本体同级。

**独立测试**：把数据准备目录配置为最窄集合（仅 `.csv`）并部署 → 在前台共享空间与临时空间上传改造前允许的类型 → 断言全部照常成功；
断言管理端不存在针对这两个空间的文件类型入口。

**验收场景**：

1. **Given** 数字人的数据准备目录已配置任意白名单并部署，**When** 用户在共享空间上传改造前允许的类型，**Then** 行为与改造前完全一致。
2. **Given** 同上，**When** 用户在临时空间上传改造前允许的类型，**Then** 行为与改造前完全一致。
3. **Given** 管理端数字人设计页，**When** 查看共享空间与临时空间，**Then** MUST NOT 出现文件类型配置入口。

---

### 用户故事 4 - 字段约束只对表格类型生效（优先级：P2）

某数据准备目录既声明了字段约束、又允许了非表格类型（如 `.txt`）。用户上传 `.txt` 时，系统跳过表结构校验直接接受；
而上传 `.csv`/`.xlsx` 时仍按既有规则校验表头与取值类型。从未声明字段约束的目录则一律跳过表结构校验。

**为什么是这个优先级**：它决定"放宽类型"能否真正落地——若不跳过，声明了约束的目录上放宽等于无效，
且会给出与文件实际形态不符的误导性拒绝理由。

**独立测试**：目录 A 声明必填字段并允许 `.csv`/`.xlsx`/`.txt` → 上传 `.txt` → 断言成功且不出现表头相关错误 →
上传缺必填表头的 `.csv` → 断言仍被拒绝并列出缺失表头 → 目录 B（无字段约束）上传任意允许类型 → 断言不做表结构校验。

**验收场景**：

1. **Given** 目录 A 声明了字段约束且允许 `.txt`，**When** 上传 `.txt`，**Then** 不做表结构校验，上传成功。
2. **Given** 目录 A 声明了字段约束且允许 `.pdf`/`.json`/`.zip`/图片，**When** 上传其中任一类型，**Then** 均跳过表结构校验，MUST NOT 出现"缺少必填表头"之类的表结构拒绝理由。
3. **Given** 目录 A 声明了必填字段，**When** 上传缺少该表头的 `.csv`（或 `.xlsx`），**Then** 仍被拒绝，并逐条列出缺失的表头与不合规的行。
4. **Given** 目录 B 未声明任何字段约束，**When** 上传任意允许类型，**Then** 一律跳过表结构校验（与改造前一致）。
5. **Given** 前台上传界面，**When** 用户查看某目录的字段提示，**Then** 该提示只作说明用途；判定 MUST 以服务端结论为准（前端 MUST NOT 自行判定）。

---

### 用户故事 5 - 未配置的存量数字人行为不变（优先级：P2）

从未打开过该入口（或未配置）的存量数字人，在数据准备目录上能上传的类型与今天完全一致（`.csv` 与 `.xlsx`），
不需要任何数据迁移或人工干预。

**为什么是这个优先级**：它是"升级不改变既有行为"的保证；优先级低于功能本体，但决定上线风险。

**独立测试**：取一个未配置该字段的存量数字人 → 部署 → 断言数据准备目录只接受 `.csv` 与 `.xlsx`；
断言管理端打开该数字人时入口显示为默认状态（`.csv` 与 `.xlsx`）。

**验收场景**：

1. **Given** 某数字人从未配置过目录文件类型，**When** 部署该数字人，**Then** 其数据准备目录的可上传类型等价于 `.csv` 与 `.xlsx`。
2. **Given** 同上，**When** 管理员打开该数字人设计，**Then** 各目录入口显示默认勾选 `.csv` 与 `.xlsx`，且未产生额外的持久化内容。
3. **Given** 已部署的存量数字人，**When** 本特性上线，**Then** MUST NOT 需要任何数据迁移或重新配置。

### 边界情况

- **空间根目录上传**：运行环境对「数据准备」**强制要求二级目录**（根目录上传返回 `400`），因此不存在"根的白名单"；目录级配置只作用于被配置的二级目录（见 FR-015）。
- **配置随部署覆盖**：平台是配置的唯一权威，部署语义为整体覆盖；平台侧未配置的目录 MUST NOT 在运行环境残留旧的白名单。
- **运行环境配置不可解析/非法**：某一目录的白名单在运行环境无法解析时，该目录 MUST 降级为平台默认（`.csv` 与 `.xlsx`），上传功能 MUST NOT 整体不可用，且降级原因 MUST 落结构化日志。
- **候选写法归一**：候选集中出现大小写混写或重复（如 `.XLSX`、重复的 `.csv`）时，MUST 归一为小写并去重后再比较。
- **声明了字段约束却允许非表格类型**：这是合法配置；此时非表格类型跳过表结构校验（见用户故事 4），MUST NOT 被判定为配置错误。
- **压缩包类文件不可预览**：本次候选中的 `.zip` 在预览区不可预览时，按"仅下载"处理（沿用既有文件类型分派），MUST NOT 呈现为错误态。
- **目录清单为空或缺少平台预定义目录**：沿用既有保存校验（由后端拒绝），本特性 MUST NOT 变更该口径。
- **用户手工绕过选择器**：文件选择器的类型过滤在部分操作系统上仅为"建议"，因此服务端拒绝是权威路径（见用户故事 2 验收场景 5）。

## 需求 *(必填)*

### 功能需求

**A. 管理端配置（数字人设计）**

| 编号 | 需求 | 验证方式 |
|---|---|---|
| **FR-001** | 数字人设计的「数据准备」二级目录清单中，**每个目录行** MUST 提供「文件类型」入口，位置 MUST 在「字段」与「移除」之间 | 组件测试：断言入口存在且 DOM 顺序位于两者之间 |
| **FR-002** | 该入口 MUST 提供 **11 项候选**多选：`.xlsx`、`.xls`、`.csv`、`.txt`、`.pdf`、`.json`、`.html`、`.zip`、`.jpg`、`.png`、`.jpeg`（`.xls` 为 2026-10-14 新增，`.html` 为 2026-10-20 新增）；候选集 MUST 由平台单一来源定义，MUST NOT 在多处各写一份 | 组件测试：候选集合与顺序一致；代码审阅：候选常量为唯一来源 |
| **FR-003** | 每个目录 MUST **至少选中 1 项**；尝试全部取消 MUST 被拒绝并给出可读提示，且 MUST NOT 产生"0 项"的持久化配置 | 组件测试：取消全部后确认被拒；后端测试：提交空数组被拒 |
| **FR-004** | 新建二级目录时，其文件类型 MUST **默认选中 `.csv` 与 `.xlsx`**（与今天数据准备的实际可上传集合一致） | 组件测试：新增目录后入口显示默认勾选两项 |
| **FR-005** | 文件类型 MUST 按**目录**粒度随数字人设计保存，并在重新打开该数字人时**一致回显** | 组件/接口测试：保存后重新读取，逐目录一致 |
| **FR-006** | 移除某个二级目录时，其文件类型配置 MUST 一并移除（MUST NOT 留下孤儿配置） | 组件/接口测试：移除目录后配置中不再含该目录键 |
| **FR-007** | 入口 MUST 可键盘到达与操作（`Tab` 可达、`Enter`/`Space` 触发、`Esc` 关闭），选中状态 MUST 有文本可读（MUST NOT 仅以颜色区分），并 SHOULD 显示已选数量或摘要 | 键盘与读屏验证；组件测试：摘要随勾选变化 |
| **FR-008** | 保存时 MUST 由管理端后端做权威校验：候选集合法、每目录非空、去重、忽略大小写差异再比较 | 单元测试：非法候选 / 空数组 / 重复项 / 大小写混写各 1 例 |

**B. 下发与生效（运行环境与前台）**

| 编号 | 需求 | 验证方式 |
|---|---|---|
| **FR-010** | 保存并经**部署**后，运行环境 MUST 按目录读取该白名单，并将其作为该目录唯一的"可上传类型"来源（单一实现，MUST NOT 在多处各实现一套判定） | 集成测试：部署产物含按目录的配置；代码审阅：判定唯一来源 |
| **FR-011** | 前台在某数据准备目录上传时，文件选择器 MUST 只呈现该目录已配置的类型 | 组件测试：按目录生成的类型过滤参数等于配置集合 |
| **FR-012** | 前台与服务端 MUST 一致地拒绝白名单之外的文件，并给出**可读提示**（说明该目录允许的类型）；MUST NOT 出现两端结论不一致，MUST NOT 只抛错误码 | 集成测试：同一文件两端口径一致；组件测试：提示文案含允许类型 |
| **FR-013** | 该白名单 MUST NOT 改变数字人的工具可用性或文件写入权限——它只约束"用户上传"，MUST NOT 放宽或收紧 agent 对目录的写入策略 | 回归测试：上传无关的权限行为与改造前一致 |
| **FR-014** | 未配置的目录 MUST 沿用平台默认（`.csv` 与 `.xlsx`） | 集成测试：未配置目录的可用类型等于默认集合 |
| **FR-015** | 「数据准备」**空间根**（不带二级目录）**不支持上传**：沿用既有 `400` 判定（"数据准备需指定二级目录"），因此不存在"根的白名单"；目录级配置只在被配置的二级目录上生效（2026-10-13 修订，见「修订记录」v1.2） | 集成测试：数据准备根上传返回 `400`；目录级配置不改变该判定 |

**C. 字段约束的适用范围**

| 编号 | 需求 | 验证方式 |
|---|---|---|
| **FR-020** | 上传校验时，字段约束 MUST **只对 `.csv` 与 `.xlsx` 生效**；其他任何类型 MUST 跳过表结构校验 | 集成测试：允许 `.txt`/`.pdf`/`.json`/`.zip`/图片的目录上传各自类型均通过，且无表结构相关拒绝 |
| **FR-021** | 目录**未设置**字段约束时 MUST 跳过表结构校验（维持既有行为） | 集成测试：无约束目录上传 `.csv` 不做表结构校验 |
| **FR-022** | 上述跳过 MUST NOT 削弱对 `.csv`/`.xlsx` 的既有校验：缺必填表头、取值类型不符、文件损坏等仍 MUST 被拒绝，且拒绝理由 MUST 为逐条可读清单 | 集成测试：四类失败各 1 例 |
| **FR-023** | 该规则的判定 MUST 在服务端权威执行；前端 MAY 提示但 MUST NOT 自行判定（避免双实现漂移） | 代码审阅 + 契约文档登记 |

**D. 不受影响的边界**

| 编号 | 需求 | 验证方式 |

### 关键实体 *(涉及数据)*

- **数据准备二级目录**：数字人设计态中「文件空间 → 数据准备」下的可见目录项；可被配置者：字段约束、可上传文件类型。
- **可上传文件类型（目录级）**：某目录允许用户上传的文件扩展名集合，取值来自固定 10 项候选，至少 1 项，默认 `.csv` 与 `.xlsx`；缺省即"沿用平台默认"。
- **平台默认可上传类型**：数据准备空间的既有默认集合（`.csv` 与 `.xlsx`），同时作为空间根与未配置目录的兜底。
- **字段约束**：目录级的上传表结构约束（必填表头 + 取值类型），仅适用于表格类型。

## 假设

1. **白名单粒度＝每个「数据准备」二级目录各自一份**（**已由用户于 2026-10-13 确认**，见「修订记录」）。依据是需求给定的入口位置——目录行的「字段」与「移除」按钮**之间**，即入口挂在每一行目录上；与既有「字段约束」的目录级粒度一致。因此同一数据准备空间下的不同目录可有各自不同的白名单，配置的下发与前台过滤都必须区分到**目录级**。
2. **候选集固定为 11 项**（`.xlsx`、`.xls`、`.csv`、`.txt`、`.pdf`、`.json`、`.html`、`.zip`、`.jpg`、`.png`、`.jpeg`），不随配置变化；其中 `.zip`（2026-10-13）、`.xls`（2026-10-14）与 `.html`（2026-10-20）是**新引入**的可上传类型（改造前任何空间都不允许）。
3. **未配置＝沿用平台默认**（`.csv` 与 `.xlsx`），因此无需数据迁移；"未配置"与"显式配置为 `.csv`+`.xlsx`"在**生效结果**上等价。
4. **类型比较按扩展名、大小写不敏感**；不接受无扩展名文件（沿用既有上传校验口径）。
5. **数据准备空间根不支持上传**（运行环境强制要求二级目录，见 FR-015）；只有被配置的二级目录才改变行为。
6. **`.zip` 不可预览时按"仅下载"处理**，沿用既有文件类型分派，不新增预览能力。
7. **候选类型清单由平台侧唯一定义**，运行环境与前台一律消费下发值，MUST NOT 各自硬编码（宪章原则七）。
