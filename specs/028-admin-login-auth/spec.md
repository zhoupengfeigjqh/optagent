# 特性规格：数字人管理平台登录授权入口（2026-11-23）

**特性编号**：028　**特性目录**：`specs/028-admin-login-auth`　**状态**：Draft
**影响侧**：`admin-frontend`（登录页、登录态守卫、退出入口）、`admin-backend`（登录态端点、认证中心中转与管理接口未认证拦截）；`gateway` **无需改动**（新增端点沿用既有 `/api/admin/` 分发）；`frontend` / `agent-backend` 本期不改。
**输入**：用户描述——"新增一个数字人管理平台的登录授权入口。用户输入数字人管理平台的后台地址，先跳出一个登录页面；登录页原型见 `数字人注册原型.html` 的「管理员登录」；登录后端接口已由认证中心提供（`POST /api/auth/admin/login`，演示账号 `admin/123456`），不重复开发；功能须高内聚、低耦合且严谨。"

## 1. 目标

为数字人管理平台（管理界面）增加**统一登录入口**：任何人访问管理平台地址时，**先看到登录页**，通过管理员账号密码校验（由既有认证中心判定）后才能进入管理功能；未登录或登录态失效时，页面与管理接口一并拒绝访问。

**范围边界**：

- 本期解决"**谁能进入管理平台**"，即认证（登录）与登录态守卫；**不含**管理员注册、找回/修改密码、角色与细粒度权限划分（认证中心已注册的 admin 账号即视为全功能管理员）。
- 登录校验的唯一权威源是既有认证中心，本平台**不新增**账号体系、**不重复实现**密码校验逻辑，只做登录入口、登录态承载与守卫。
- **不影响**既有聊天前台的业务使用者登录（`024-user-login-auth`）：两者面向不同人群（管理员 / 业务使用者），入口、凭据与会话**相互独立、互不覆盖**。
- 登录页视觉与交互以原型 `数字人注册原型.html` 的「管理员登录」为准；原型的演示性内容（演示账号、普通用户入口、"原型说明"等）**不进入实现**。

## 2. 用户场景与测试

### 用户故事 1 - 打开管理平台先见登录页（优先级 P1）

使用者（管理员）在浏览器输入数字人管理平台的后台地址（或刷新、或从书签/历史记录进入任意管理页面），在尚未登录的情况下，看到的是登录页面而非管理内容。

**为何此优先级**：这是本特性的直接诉求——"输入后台地址，先跳出一个登录页面"；没有它，后续登录与守卫都无从谈起。

**独立测试**：清除浏览器登录态后直接访问管理平台地址与任一管理子页面，确认都停在登录页。

**验收场景**：

1. **Given** 使用者未登录，**When** 打开管理平台根地址，**Then** 展示登录页，不渲染任何管理功能区内容。
2. **Given** 使用者未登录，**When** 直接输入某一管理子页面地址（或刷新该地址），**Then** 同样展示登录页，且登录成功后回到其原本想访问的页面。
3. **Given** 使用者已登录，**When** 访问登录页地址，**Then** 不再要求登录，直接进入管理平台首页。

---

### 用户故事 2 - 管理员用账号密码登录（优先级 P1）

管理员在登录页输入账号与密码，校验通过后进入管理平台，并可正常使用全部既有功能。

**为何此优先级**：登录是进入平台的唯一通道，是 P1 的核心闭环。

**独立测试**：以已注册的管理员账号（演示：`admin` / `123456`）完成一次登录，确认进入管理平台且各功能区可正常打开。

**验收场景**：

1. **Given** 登录页已打开，**When** 输入正确账号与密码并提交，**Then** 进入管理平台（或原本要访问的页面），并显示当前登录的管理员标识。
2. **Given** 账号或密码为空，**When** 提交，**Then** 在对应输入框处给出可读的字段级提示，不发起登录请求。
3. **Given** 已登录，**When** 刷新页面或在新标签页打开管理平台地址，**Then** 保持登录态，无需重复输入密码（直至登录态过期或主动退出）。

---

### 用户故事 3 - 登录失败与认证服务异常有明确反馈（优先级 P1）

账号或密码错误、认证服务不可达或返回异常时，使用者看到明确提示并停留在登录页，绝不"看起来登录成功"。

**为何此优先级**：登录是最容易暴露安全与体验缺陷的入口；错误口径不确定会造成账号枚举与误放行。

**独立测试**：分别用错误密码、不可达的认证服务地址各试一次登录，确认均无法进入管理平台且提示可读。

**验收场景**：

1. **Given** 输入了错误的密码或不存在账号，**When** 提交，**Then** 停留在登录页，提示"账号或密码不正确，请重新输入"（**不区分**账号是否存在），已填账号保留、密码清空。
2. **Given** 认证服务不可达或超时，**When** 提交，**Then** 提示"认证服务暂不可用，请稍后重试"，**不进入**管理平台。
3. **Given** 认证服务返回"HTTP 成功但业务码表示失败"，**When** 提交，**Then** 按失败处理：业务码表明凭据错误时提示"账号或密码不正确"，其它非成功业务码按"认证服务暂不可用"处理（判定规则见 FR-004 与契约 §2.1）。

---

### 用户故事 4 - 未登录不得取用管理数据（优先级 P1）

不仅页面被挡，直接调用管理平台接口同样拿不到任何业务数据。

**为何此优先级**：只挡页面等于没有防护；"必须严谨"要求服务端不信任前端。

**独立测试**：在无登录态的情况下直接请求任意管理接口，确认被拒绝且响应中无业务数据。

**验收场景**：

1. **Given** 未持有有效登录态，**When** 请求任一管理接口，**Then** 返回统一的"未认证"错误，且不含任何业务数据。
2. **Given** 登录态已过期或已失效，**When** 在页面内继续操作（如切换功能区、保存配置），**Then** 明确提示"登录状态已失效，请重新登录"并回到登录页，该次操作**不产生副作用**（不写入半成品数据）。
3. **Given** 未登录，**When** 使用浏览器后退/前进回到管理页面，**Then** 仍被要求登录，无法通过历史记录绕过。

---

### 用户故事 5 - 退出登录与登录态过期（优先级 P2）

管理员可主动退出；登录态过期后继续操作会被引导重新登录。

**为何此优先级**：完整登录闭环的必要收尾；离开工位而未退出是最常见的安全缺口。

**独立测试**：登录后执行退出、以及模拟登录态过期，分别验证"回到登录页且不能后退返回"与"被提示重新登录"。

**验收场景**：

1. **Given** 已登录，**When** 点击退出登录并在二次确认中确认，**Then** 回到登录页，且再次访问管理页面需重新登录。
2. **Given** 已在某标签页退出，**When** 在另一标签页继续操作，**Then** 在下一次操作时被要求重新登录。
3. **Given** 登录态已过期，**When** 打开管理平台地址，**Then** 展示登录页（不出现"空白页 + 无提示"）。

---

### 边界情况

- **认证中心"HTTP 200 + 业务码"约定**：该中心约定接口始终返回 HTTP 成功，成功与否由响应体业务码表达；只按 HTTP 状态判断会把失败当成功——必须按业务码判定。
- **凭据不可被前端脚本读取**：任何页面脚本、错误上报、日志都不得持有或输出凭据明文；凭据存储损坏时一律视为"未登录"。
- **密码不回显**：密码明文不得出现在任何提示、日志、审计记录、接口响应中；登录表单提交后清空密码。
- **原型与实现的差异**：原型内置的演示账号、"以普通用户身份体验"、"原型说明"文案均不得进入实现；登录页不得展示任何真实账号或密码（包括 `admin/123456`）。
- **与聊天前台并存**：同一浏览器同时登录管理平台与聊天前台时，两者的登录态不得互相覆盖或互相清除。
- **管理员账号在认证中心侧被删除/停用**：既有登录态在下一次服务端校验时失效并回到登录页；不得因为"本地缓存了登录态"继续放行。
- **多标签页并发**：一个标签页退出后，其他标签页最迟在下一次操作时失效。
- **重复提交**：登录请求进行中重复点击不得产生多次登录尝试。
- **认证中心地址配置错误或部署后未连通**：登录必须失败并给出"认证服务暂不可用"的可读提示；不得因"暂时连不上"降级放行。地址有既定缺省值，故"未配置"不构成单独场景；连通性由部署冒烟步骤确认。

## 3. 需求

### 功能需求

| 编号 | 需求 |
|---|---|
| **FR-001** | 未持有有效登录态时，访问数字人管理平台的**任何**页面地址（根地址、子页面、刷新、书签、历史记录）MUST 先呈现登录页，MUST NOT 先渲染任何管理内容。 |
| **FR-002** | 登录页 MUST 与原型「管理员登录」一致：平台品牌区、标题"管理员登录"、账号输入、密码输入（含显隐切换）、登录按钮、失败提示区；文案为中文。 |
| **FR-003** | 登录校验 MUST 以认证中心的 `POST /api/auth/admin/login` 为**唯一权威源**；本平台 MUST NOT 自行比对密码、MUST NOT 存储任何管理员密码。 |
| **FR-004** | 登录结果 MUST 以认证中心响应体中的**业务码**判定成功/失败；HTTP 成功但业务码非成功 MUST 视为登录失败。 |
| **FR-005** | 登录成功后，使用者 MUST 进入其原本要访问的页面（无明确目标时进入管理平台默认首页）；刷新或在新标签页打开 MUST 保持登录态。 |
| **FR-006** | 登录凭据 MUST 由服务端下发、以浏览器自动携带的方式保存并具备有效期；前端脚本 MUST NOT 读取、写入、持久化或记录凭据明文。 |
| **FR-007** | 未登录或凭据无效时，对管理平台任何管理接口的请求 MUST 在服务端被拒绝，返回统一的"未认证"错误且不含业务数据；MUST NOT 仅依靠前端隐藏页面来实现保护。 |
| **FR-008** | 登录失败 MUST 返回统一提示，MUST NOT 区分"账号不存在"与"密码错误"；提示、日志与响应中 MUST NOT 出现密码明文。 |
| **FR-009** | 认证中心不可达、超时或返回非预期内容时，登录 MUST 失败并提示"认证服务暂不可用，请稍后重试"；MUST NOT 以任何形式放行；原始错误 MUST 落入结构化日志（含可关联的请求线索）。 |
| **FR-010** | 登录与鉴权相关错误 MUST 使用项目统一的错误响应格式与全局唯一、语义稳定的错误码；"未认证（含过期）"、"登录失败（账号或密码错误）"、"认证服务不可用" MUST 各自语义确定且互不混用。 |
| **FR-011** | 管理平台 MUST 提供明确的退出登录入口；退出 MUST 经二次确认，退出后当前登录态立即失效并回到登录页，浏览器后退 MUST NOT 回到已登录页面。 |
| **FR-012** | 管理平台新增的登录 MUST 与既有业务使用者登录（`024-user-login-auth`）**互不影响**：入口、路径、登录态与会话相互独立；MUST NOT 改变既有业务使用者登录、会话内省与聊天前台登录的对外行为。 |
| **FR-013** | 登录页与登录态守卫 MUST 满足无障碍：全流程可仅用键盘完成（Tab 顺序合理、Enter 提交、焦点可见）、字段错误以文本并与对应输入框建立 `aria-*` 关联、密码显隐按钮有可读标签、错误提示可被读屏播报。 |
| **FR-014** | 登录请求 MUST 有界超时；请求进行中登录按钮 MUST 禁用并显示进行中状态，MUST NOT 允许重复提交；等待期间 MUST 向使用者显示当前状态。 |
| **FR-015** | 登录页 MUST NOT 展示任何真实账号或密码；原型的演示账号、"以普通用户身份体验"入口与"原型说明"区块 MUST NOT 进入实现。 |
| **FR-016** | 登录成功后，管理平台既有的全部功能区（MCP 服务、本体管理、SKILL 管理、数字人设计、数字人部署等）MUST 保持原有功能与行为不变；本期只新增登录入口与守卫，MUST NOT 改动既有业务语义。 |
| **FR-017** | 登录态失效 MUST 以可感知方式告知使用者（明确的过期提示 + 回到登录页），MUST NOT 出现静默跳转或空白页面。 |
| **FR-018** | 登录入口相关实现 MUST 高内聚：登录页、登录态判定、退出等职责 MUST 各自只有一处实现并被复用，MUST NOT 在多个功能区各自重复实现守卫逻辑。 |

### 关键实体

- **管理员账号**：认证中心侧已注册的管理员身份（本期只读，不新增、不修改、不提供注册入口）；演示账号 `admin` / `123456`。
- **认证中心访问凭据**：认证中心在登录成功后签发、限定管理员范围且带有效期的令牌。本平台**只在登录请求内使用**（据其有效期确定会话上限），**不留存、不下发给浏览器、不用于后续请求校验**。
- **控制台会话**（本平台侧，即"管理平台登录态"）：登录成功后由本平台自签的、浏览器自动携带的会话凭据（管理员标识 + 独立受众 + 有效期），用于页面守卫与服务端接口拦截；退出或过期后立即失效，不提供服务端撤销。

| **SC-009** | 同一浏览器中管理平台登录与聊天前台登录互不干扰：任一侧登录/退出，另一侧登录态保持有效（用例覆盖）。 |

## 5. 假设

- **"数字人管理平台"即管理界面**：指管理侧前端（对外经网关以 `/admin/` 提供），本期只保护管理平台；聊天前台与其业务使用者登录沿用既有方案。
- **认证中心为唯一权威源**：管理员账号由认证中心维护，`admin/123456` 为已注册演示账号；本平台不提供管理员注册、改密、找回密码。登录成功响应包含访问凭据与有效期；本平台据有效期确定会话上限后**即丢弃**该凭据（不保存、不下发）。
- **同源中转**：浏览器只访问管理平台的同源地址，由平台服务端中转认证中心的登录请求并承载登录态，避免跨域直连与凭据暴露；认证中心地址为可配置项（当前为 `192.168.0.156:8999/dh-auth-center`）。
- **双层防护**：采用"服务端强制校验 + 前端引导"（用户故事 4）。仅前端拦截无法满足"必须严谨"，故本平台管理接口在未认证时一律拒绝。
- **登录态有效期**：取"认证中心签发的有效期"与"本平台策略上限"的较小值；具体数值在计划阶段确定并做成可配置。
- **单管理员多端**：本期**不**引入"后登踢前登"——认证中心接口清单中未提供管理员会话撤销/内省能力，多端登录可并存；该能力待认证中心侧补齐后再评估。
- **失败次数限制**：登录失败次数限制与账号锁定由认证中心负责，本期前端不做额外锁定。
- **既有约定不改**：`024` 的业务使用者登录端点（`/api/admin/auth/*`）、其契约与运行侧会话内省保持不变；新增的管理端登录使用**独立**的入口与登录态，不与既有路径复用或冲突。
- **部署形态**：本地开发经开发代理、容器部署经网关，两种形态都只暴露同源路径；认证中心不可达时的行为一致（登录失败 + 可读提示）。
- **视觉基准**：登录页布局、字段标签、失败提示措辞以原型「管理员登录」为准；原型中与本期无关的演示内容一律剔除。
