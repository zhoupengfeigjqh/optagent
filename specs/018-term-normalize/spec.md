# 特性规格：术语替换与发送前确认（Term Normalize）

- **特性标识**：`018-term-normalize`
- **创建日期**：2026-11-06
- **状态**：实施中
- **影响范围**：`agent-backend` + `frontend`（两侧同改）；`admin-backend` / `admin-frontend` 零改动
- **上游依据**：`specs/017-ontology-term-mapping/spec.md`（术语字典的生成侧）、
  `specs/016-ontology-skill-focus/spec.md`（意图聚焦开关）

## 原始输入（用户需求，逐字保留）

> 新增一个新需求，关于term_mapping.json的消费。
> 1 若开启意图聚焦，此时提取当前数字人的所有本体术语表，合并为一张，key相同则value合并，用 或 连接
> 2 整个术语表作为输入1，用户输入作为输入2
> 3 采用Trie（前缀树）+ 单遍最长优先匹配（Longest Match First），将用户输入2中的命中术语，替换为术语表中对应的value
> 4 计算完后，若发生输入替换，则弹窗提示用户是否保留替换，或者直接原话继续

## Clarifications

### Session 2026-11-06

- Q: 多义值（`A或B`）替换进句子时怎么处理？ → A: **原样保留**（用户原话："多义值保留（其实基本上不存在多义）"）。
- Q: 是否设最小命中长度？ → A: **≥2**（单字术语噪声太大，直接不建进树）。
- Q: 弹窗何时出现？ → A: **只在手动输入时**（卡片、重试、跳过聚焦的轮次不参与）。
- Q: 历史里留原话还是替换文？ → A: **保留原话**（模型看替换文，用户看自己说的话）。
- Q: 意图聚焦按哪一版判定？ → A: **替换后**（替换发生在发送前，服务端只见到最终文本）。

## 术语与口径

| 术语 | 定义 |
|---|---|
| **术语表** | 当前数字人**全部本体**的 `term_mapping.json` 合并结果（`term → value`）。 |
| **最长优先匹配** | 同一位置能匹配多个术语时取最长者（`供应商编号` 优先于 `供应商`）。 |
| **单遍** | 从左到右扫一次，替换结果不再参与本轮匹配（`A→B`、`B→C` 只走一步）。 |
| **发生替换** | 至少一处 `value !== term`；"替换成自己"不算，不弹窗。 |

**合并口径**：同名 key 的 value 用 `或` 连接（与 017 一致），候选去重，顺序 = 本体目录名排序 → 文件内原序。
**开关口径**：意图聚焦开关（`isIntentFocusEnabled`）是唯一判定源，关闭时**不读任何术语文件**。
**位置口径**：替换发生在**发送之前**，落盘/摘要/意图聚焦看到的都是同一条最终文本。

## 需求

### 功能需求

| 编号 | 需求 | 验收 |
|---|---|---|
| **FR-001** | 意图聚焦开启时，系统 MUST 合并当前数字人**全部本体**的术语表；同名 key 的 value MUST 用 `或` 合并并去重 | 两个本体同 key → `A或B或C` |
| **FR-002** | 匹配 MUST 采用 Trie + **单遍最长优先**；替换 MUST NOT 递归（替换结果不再参与本轮匹配） | `物料→原材料` 不会继续变 `钢材` |
| **FR-003** | 命中长度 MUST ≥ 2 个字符（按码点计）；更短的术语 MUST NOT 参与匹配 | 单字术语不命中 |
| **FR-004** | `value` MUST 原样插入（含 `A或B` 形态），MUST NOT 在匹配层拆分 | 替换结果为 `供应商或供应商编号` |
| **FR-005** | 只有 `value !== term` 才算"发生替换"；未发生替换时 MUST NOT 弹窗、MUST NOT 增加往返 | 同值命中 → `applied:false` |
| **FR-006** | 发生替换时 MUST 先向用户确认，出口：**使用替换后的表述发送**（表述 MAY 由用户手工编辑，编辑结果 MUST 非空）/ **按原话继续发送**；未确认 MUST NOT 发送；编辑为空（含纯空白）时 MUST 阻止发送并给出可读原因 | 弹窗未选择 → 无发送请求；清空编辑框 → 主按钮禁用、无请求 |
| **FR-007** | 弹窗 MUST 只在**手动输入**链路出现：首屏问题实例卡片、下一步动作卡片、重试/重新生成、定时任务 MUST NOT 触发 | 点卡片 → 无弹窗 |
| **FR-008** | 用户选择"替换后"时，提交给模型的 MUST 是**用户最终确认的那一版**（模型替换文，或用户在弹窗里编辑后的文本），落进历史与气泡的 MUST 是**同一段文本**（所见即所发） | 历史 jsonl 与气泡 = 提交正文；手改后三处一致 |
| **FR-009** | 意图聚焦与后续轮次的上下文 MUST 基于**替换后**文本（即用户最终确认的那一版） | Laya 判定输入 = 替换文 |
| **FR-010** | 预检 MUST 可降级：超时（1.5s）/ 请求失败 / 无字典 / 开关关闭 → 一律按原话继续发送，MUST NOT 阻断对话 | 断网时仍能发出 |
| **FR-011** | 关闭的形态 MUST 保持"用户无感"：`applied:false` 时不弹窗、不提示、不改变请求序列 | 无替换时与未上线一致 |
| **FR-012** | 服务端 MUST NOT 自己改写用户文本（无隐式替换）；替换只由用户确认后随请求体提交 | 请求体里 `content` 即发送文本 |

### 关键技术需求

| 编号 | 需求 |
|---|---|
| **TR-01** | 术语表的文件名、合并分隔符、跨本体合并口径 MUST 有**唯一落点**（`domain/term-normalize/tables.ts`），其余模块只消费其结果 |
| **TR-02** | 匹配 MUST 是纯函数（`domain/term-normalize/matcher.ts`）：无 IO、无时钟、同输入同输出；返回下标 MUST 是 UTF-16 偏移（前端可直接切片高亮） |
| **TR-03** | 端点 MUST 是薄编排（开关 → 读表 → 匹配 → 组响应），业务判断不得下沉到路由以外的重复实现 |
| **TR-04** | 请求体 MUST 严格：未知字段 400（默认 ajv 的 `removeAdditional` 会静默丢弃，不可接受） |
| **TR-05** | 预检端点 P95 ≤ 500ms（本地读几 KB + 建树，实测毫秒级） |
| **TR-06** | 降级 MUST 有结构化日志：`term_normalize.gate`（开关读取失败）、`term_normalize.degraded`（字典不可用） |
| **TR-07** | 契约 MUST 同步：新增端点文档 + 发消息 `original_content` 字段说明（2026-11-07 起标注"已停用、仅兼容保留"） |

### 不可破坏的不变量

| # | 不变量 | 落点 |
|---|---|---|
| **I-1** | 平台仍是唯一权威源；运行环境只读 `term_mapping.json`，不生成、不回写 | `tables.ts` 只读 |
| **I-2** | 意图聚焦的开关语义不变：关闭 = 不调 Laya、不读术语 | 复用 `isIntentFocusEnabled` |
| **I-3** | 历史与用户所见一致：气泡里的文本必须等于历史里的文本 | `displayContent` 单点决定 |
| **I-4** | 发送链路仍唯一：确认弹窗只是"发送前的一次路由"，不新增第二条发送路径 | `useChatPanel.onSend` |

## 边界情况

- **术语表为空 / 全部本体都没有 `term_mapping.json`**：`applied:false`，正常发送。
- **某个本体字典损坏**：跳过该本体 + warning，其余照常合并（不整体降级）。
- **同一 term 在本体内已是 `A或B`，跨本体又出现 `C`**：合并为 `A或B或C`（保持原序、去重）。
- **文本中包含 `@文件名` 引用标记**：先按既有规则剥离引用文本，再做替换（替换不触碰引用）。
- **术语命中跨越 emoji / 生僻字**：下标按 UTF-16 计算，前端切片高亮不偏移。
- **替换后文本与原话相同**（如仅命中同值项）：不弹窗。
- **用户在弹窗期间修改输入**：输入区被禁用，关闭弹窗后可编辑；弹窗关闭 = 按原话继续。
- **用户在弹窗里清空替换结果**：视为暂不可发送（主按钮禁用 + 行内 `role="alert"` 说明），弹窗保留；改回非空即可继续发送。
- **发送被本地拦下**（未选数字人、引用失效）：弹窗保留，用户可改选或关闭。
- **连续点击"使用替换后"**：只发一次（`termSending` 期间忽略）。
- **定时任务 / 重试轮**：不参与预检（无确认环节，文本已定型）。

## 成功标准

- **SC-001**：术语替换准确率 **100%**（同一输入下最长优先、单遍、去重均可复现）。
- **SC-002**：未发生替换时**零打扰**：不弹窗、不多一次确认；请求数与上线前一致（预检本身是唯一新增往返）。
- **SC-003**：确认后**提交正文、气泡、历史**三处同一段文本，**一致率 100%**（断言在测试里）。
- **SC-004**：预检端点 P95 ≤ 500ms；超时率不影响发送成功率（超时即按原话继续）。
- **SC-005**：降级路径可观测：开关读取失败、字典损坏各有独立事件名。

## 非目标

- 不做术语的同义词自动扩展、模糊匹配、繁简/大小写归一。
- 不做**存量**历史消息的改写：2026-11-07 之前已落盘的轮次保持原样，不做回填迁移。
- 不做全局术语表（跨数字人共享）。
- 不做英文术语的大小写折叠（按原文精确匹配）。
