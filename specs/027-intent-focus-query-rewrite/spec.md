## 原始输入（用户需求，逐字保留）

> 新增一个需求。
> 1 如果数字人管理平台开启了意图聚焦，则在对话发送时，先用laya进行一个 need rewrite 的判断（输入从后向前截断200字）。
> 2 该判断为一个单条的 true or false的判断：判断当前用户输入中是否有明确的代指内容。若用户输入中有明显的代指信息（如请根据上述结果分析，这个怎么计算等这类问题），则需要 进行 need rewrite。
> 3 若进入need rewrite，则调用当前LLM模型，输入前3轮历史的query输入和LLM输出（不含工具）以及当前输入query，让LLM重写当前的输入 rewrite query，且尽可能简洁清晰，不要啰嗦（不超过100字）。
> 4 然后，拿这个重写的query，去计算与skill、本体skill、本体行为等意图的聚焦计算
> 5 注意，这个重写的query仅作为意图聚焦使用，不作为本轮发送到大语言模型的输入，本轮输入依旧为原话。
>
> 整个功能是依赖于意图聚焦的，若意图聚焦未开启，则没有这个功能。
>

## Clarifications

### Session 2026-11-19

- Q: 改写输出是否必须被转换为问句？ → A: **不强制问句**。改写产物只需简洁、清晰、自洽（可独立理解），陈述句、指令、问句均可；判定只看"是否含明确代指"，不改变句类。
- Q: 是否新增数字人粒度开关？ → A: **新增复选框「输入重写」**（SOUL 布尔开关，缺省关闭）；只有「意图聚焦」与「输入重写」**同时开启**时才执行判断与改写，任一关闭即零调用。
- Q: 判定与改写相对术语替换、意图聚焦计算的时序？ → A: **术语替换之后、意图聚焦计算之前**；判定素材与改写素材中的"当前输入"一律为术语替换并确认后的文本，不重复替换、不回退替换前文本。
- Q: 「意图聚焦」关闭时，「输入重写」复选框如何表现？ → A: **置灰不可编辑但保留已选值**；重新开启意图聚焦后恢复可编辑与原值（与 `019`「聚焦阶数」同口径，不静默清空）。
- Q: 术语替换是否仍由「意图聚焦」开关直接控制？ → A: **新增独立开关「术语替换」**（SOUL 布尔开关 `term_normalize`，位于意图聚焦配置区，缺省关闭）；只有「意图聚焦」与「术语替换」**同时开启**才执行替换，关闭时不读术语表、不替换、不弹确认弹窗。
- Q: 界面如何说明「术语替换」的前置条件？ → A: 在复选框旁给出**固定说明文案**：仅当该数字人**拥有本体术语映射集**（`term_mapping.json`）时，开启后才会生效；不做实时检测、不因缺失而禁用控件。
- Q: 新增「术语替换」开关的缺省值？ → A: **存量与新建统一默认关闭**；升级后"原本意图聚焦开即替换"的行为变化 MUST 在部署说明中登记，由管理员显式开启。

## 术语与口径

| 术语 | 定义 |
|---|---|
| **意图聚焦开关** | 数字人设计态既有布尔开关（SOUL `intent_focus`），缺省关闭；是本特性与术语替换的**共同前置**。 |
| **输入重写开关** | 数字人设计态布尔开关（SOUL `input_rewrite`，缺省关闭）；与「意图聚焦」是**逻辑与**关系：两者皆为真才执行判断与改写。 |
| **术语替换开关** | 数字人设计态布尔开关（SOUL `term_normalize`，位于意图聚焦配置区，缺省关闭）；与「意图聚焦」是**逻辑与**关系：两者皆为真才执行术语替换。 |
| **指代型输入** | 语义依赖上文才能理解、且以代指词承接上文的用户输入，如「请根据上述结果分析」「这个怎么计算」「它还能再降吗」。判断只看是否存在**明确的代指**，不看输入是否简短、是否模糊。 |
| **指代判断（need rewrite）** | 一轮一次的**单条 true/false** 结构化判定（Laya `noul`），输入为本轮输入的**尾部 200 字符**；为真即进入改写。 |
| **判定素材** | 送入指代判断的文本：本轮输入（**经术语替换与用户确认后的那一版；替换开关关闭时为用户输入原文**）**从后向前截断 200 字**（沿用 `013` 既有 `prepareState` 口径，含句首对齐与「已截断」标注）。 |
| **改写结果（rewrite query）** | 由本轮生效的对话模型依据「最近 2 轮问答 + 本轮输入」生成的简洁自洽文本，**不强制问句**（陈述句 / 指令 / 问句均可），长度 ≤ 100 字。 |
| **原话（original query）** | 本轮用户最终提交、并落进历史的文本：术语替换开关开启且命中并确认时为其替换版；否则为用户输入原文。它同时是发给主模型的唯一用户输入。 |
| **聚焦计算** | `016` / `019` 的技能评分、本体行为评分与发散，其结果影响聚焦提示与下一步动作卡片。 |
| **聚焦轮** | 一次用户输入触发的完整意图聚焦（含本特性的判断与改写，以及后续技能 / 行为聚焦）。 |

**五条硬口径**：

1. **双重前置（本特性）**：意图聚焦与输入重写**同时开启**才存在判断与改写；任一关闭即零判断、零改写、零历史读取、零新增留档字段。
2. **术语替换独立前置**：术语替换只在其开关与意图聚焦**同时开启**时执行；关闭时不读术语表、不替换、不弹确认弹窗。
3. **时序固定**：术语替换（仅开关开启时）与用户确认 → 指代判断 → 改写 → 聚焦计算；本特性 MUST NOT 再触发一次术语替换，MUST NOT 以替换前文本冒充替换后文本。
4. **用途唯一**：改写结果只作为**聚焦计算的判定素材**；发给主模型的用户消息、系统补充素材、聚焦提示正文、卡片与界面一律使用原话。
5. **不落历史**：改写结果与其生成过程 MUST NOT 写入 `history.jsonl`、滚动摘要、记忆或任何后续轮次素材。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 指代型输入先改写再聚焦（优先级：P1）

某数字人已同时开启「意图聚焦」与「输入重写」。用户在多轮对话后发送「请根据上述结果分析」。系统先做一次单条指代判断，判为真后调用本轮对话模型，把最近 2 轮问答与本轮输入一起交给它，改写出一段简洁、自洽、无须依赖上文的文本（≤ 100 字，**不要求写成问句**）。随后用这段改写文本去做技能与本体行为聚焦，聚焦提示与下一步动作卡片因而更贴合真实意图；而主模型收到的用户消息仍然是原话「请根据上述结果分析」。

**为什么是这个优先级**：这是功能本体。指代型输入里没有技能名、没有业务对象名，直接用原文判分只能靠噪声命中；改写是让聚焦"看懂上文"的唯一入口。

**独立测试**：以桩实现固定「判断=真」「改写=某自洽陈述句」，跑一轮指代型输入，断言：

- 判定与改写发生在技能评分之前，且各一次；
- 技能 / 行为评分收到的判定素材等于改写结果（截断后），不等于原话；
- 主模型收到的用户消息、`systemExtra` 中的聚焦提示、落盘的 `history.jsonl` 用户行均为原话；
- 改写结果未出现在任何用户可见文本中；且改写为陈述句时链路照常（不因"不是问句"回退）。

**验收场景**：

1. **Given** 两个开关均开启且存在历史，**When** 用户发送「请根据上述结果分析」，**Then** 系统依次执行指代判断（1 条命题）与改写（1 次模型调用），聚焦计算使用改写结果。
2. **Given** 上述轮次，**When** 检查发给主模型的素材，**Then** 用户消息正文逐字等于「请根据上述结果分析」，改写结果只影响聚焦。
3. **Given** 改写结果为陈述句 / 指令而非问句，**When** 用于聚焦计算，**Then** 正常使用，不重写、不报错。
4. **Given** 改写结果长度超过 100 字，**When** 用于聚焦计算，**Then** 按 100 字截断并标注「已截断」，改写内容仍只用于聚焦。
5. **Given** 本轮为指代型输入且用户点击「重新生成」，**When** 重发本轮，**Then** 判断与改写各再执行一次（不视为跳过、不复用上一轮结果），聚焦结果独立留档。
6. **Given** 用户输入含术语表命中的说法且已确认替换，**When** 本轮执行，**Then** 判定与改写使用替换后的文本，且本轮不再触发第二次术语替换。
7. **Given** 术语替换开关关闭但两个前置开关开启，**When** 用户发送含术语的输入，**Then** 不读术语表、不弹确认，判定与改写直接基于用户输入。

### 用户故事 2 - 非指代输入零改写（优先级：P1）

用户发送自洽的独立问句（如「查询原材料库存的可用量」）。指代判断返回 false，系统**不调用**改写模型，直接用原话的尾部 200 字做技能与本体行为聚焦，行为与改造前逐字一致。

**为什么是这个优先级**：绝大多数轮次是非指代的。若在 false 分支仍做一次改写调用，等于给所有对话凭空增加一次模型调用与延迟——这是必须避免的回归。

**独立测试**：桩实现令判断为 false，断言改写模型调用次数为 0、聚焦判定素材等于原话截断、提示与卡片与改造前逐字一致。

**验收场景**：

1. **Given** 用户发送完整独立问句，**When** 指代判断返回 false，**Then** 不做改写调用，聚焦计算使用原话（尾部 200 字）。
2. **Given** 判断为 false 的轮次，**When** 查看留档，**Then** 记录含 `need_rewrite=false`、判定分数与原因，改写字段为空。
3. **Given** 判断为 false，**When** 观察本轮耗时，**Then** 只多出一次单条 Laya 判定，无模型改写等待。

---

### 用户故事 3 - 开关、转发入口与无技能短路（优先级：P2）

意图聚焦关闭、输入重写关闭、由预置动作入口（下一步动作卡片 / 首屏问题实例卡片 / 显式 `/技能名`）发起的轮次，以及该数字人没有可聚焦技能或本体的轮次，判断与改写整体不执行；术语替换关闭则单独使替换链路不执行（不读术语表、不弹确认），但判断与改写仍照常。

**为什么是这个优先级**：它不产生新能力，却决定"能否安全上线"——在本来就该跳过的轮次里多发两次调用，是纯损失且难以解释。

**独立测试**：六种情形各跑一轮（意图聚焦关闭 / 输入重写关闭 / 术语替换关闭 / 卡片入口 / 显式技能 / 无技能），断言：前两种与后三种的判断、改写调用均为 0；术语替换关闭时术语表读取与弹窗为 0，而判断与改写照常执行（判定素材为输入原文）。

**验收场景**：

1. **Given** 数字人「意图聚焦」关闭，**When** 用户发送消息，**Then** 不判定、不改写、不读历史、不新增记录（与 `013` FR-032 一致）。
2. **Given** 「意图聚焦」开启但「输入重写」关闭，**When** 用户发送消息，**Then** 不判定、不改写、不读历史；聚焦结果与 `016` / `019` 现有行为逐字一致。
3. **Given** 「意图聚焦」开启但「术语替换」关闭，**When** 用户发送消息，**Then** 不读术语表、无确认弹窗，判定与改写基于用户输入原文（`018` 关闭态）。
4. **Given** 用户点击下一步动作卡片或显式 `/技能名` 发送，**When** 本轮执行，**Then** 判断与改写均不执行，留档仍只有一条 `skipped`。
5. **Given** 该数字人已关联技能为空，或全部本体技能都匹配不到本体文件，**When** 本轮聚焦短路，**Then** 判断与改写调用次数为 0（短路先于本特性）。

### 用户故事 4 - 降级、留档与可分析（优先级：P3）

指代判断或改写失败（超时、不可达、响应非法、返回空）时，本轮照常聚焦并照常回答：判断失败按"不改写"处理，改写失败回退原话。每轮的判断结论、判定素材、改写结果、是否截断与耗时都留档在线程目录的既有侧车记录中，供事后分析。

**为什么是这个优先级**：它不改变用户可见行为，却是"不拖累对话"和"可分析"两项硬约束的落点。

**独立测试**：判定超时 / 改写超时 / 改写返回空三种情形各跑一轮，断言：

- 回答正常、无错误提示；
- 聚焦计算回退到原话，提示与卡片结构正常；
- 记录含处置原因与耗时，且记录不进入任何上下文组装路径。

**验收场景**：

1. **Given** 指代判断超时或 Laya 不可达，**When** 本轮继续，**Then** 不做改写、按原话聚焦，留档 `need_rewrite=null` 并记原因。
2. **Given** 判断为真但改写调用失败，**When** 本轮继续，**Then** 回退原话聚焦，留档 `rewrite_query` 为空并记原因。
3. **Given** 改写返回空白或只有引号 / 复述，**When** 归一后为空，**Then** 视为改写失败并回退原话，不做二次改写。
4. **Given** 留档写入失败，**When** 本轮继续，**Then** 回答与聚焦均不受影响，原始错误进入结构化日志。

### 边界情况

- **意图聚焦关闭**：本特性与术语替换整体不存在（含管理台置灰），0 判断、0 改写、0 读表。
- **输入重写关闭（意图聚焦开启）**：0 判断、0 改写、0 历史读取；聚焦与 `016` / `019` 改造前逐字一致。
- **术语替换关闭（意图聚焦开启）**：0 术语表读取、0 确认弹窗；判定与改写基于用户输入原文，行为与 `018` 关闭态一致。
- **术语替换开启但无本体术语映射集**：预检 `applied:false`，无弹窗；判定与改写照常；界面固定说明即为此情形（FR-057）。
- **术语表存在但全部未命中**：同"无命中"，无弹窗，判定与改写照常。
- **首轮对话（无历史）**：开关均开启时判断照常执行；判为真时改写只依据本轮输入（无可参考上文），允许结果与原话接近。
- **历史不足 2 轮**：取实际存在的全部完整轮次，不补空、不报错。
- **历史超过 2 轮**：只取最近 2 个完整问答轮（至多 2 条 user + 2 条 assistant），更早轮次不参与。
- **历史中含失败轮（`status=failed`）或空正文**：该条跳过，不参与改写素材，不视为失败。
- **历史中含附件轮次**：只使用文本正文，附件路径与文件名不进入改写素材。
- **历史中含工具调用**：`history.jsonl` 本身不保存工具消息；改写素材 MUST NOT 读取 `tool-events.jsonl`。
- **输入为空或仅空白**：沿用既有发送校验，不发起判断与改写。
- **输入极短（如「这个呢」）**：判为指代型，按改写链路处理；判定素材过短不作为跳过理由。
- **判定素材被截断**：判定仍只用尾部 200 字，留档标注「已截断」；不因截断放弃判断。
- **术语替换未命中**：当前输入 = 用户输入，判定与改写照常；留档无需额外标记。
- **术语替换后文本极长**：仍按尾部 200 字构造判定素材；改写素材可使用完整替换后文本（受模型上下文约束）。
- **用户在术语替换确认弹窗中取消**：本轮不发送，不产生判断、改写与留档（与 `018` 既有口径一致）。
- **改写结果为陈述句 / 指令 / 祈使句**：正常使用，不因"不是问句"视为失败或触发重写。
- **改写结果含解释性文字 / Markdown / 引号包裹**：归一为纯文本；归一后为空按失败处理。
- **改写结果仍含代指**：不递归改写、不二次调用，按一次改写结果使用。
- **改写结果超 100 字**：截断到 100 字并标注，不重试。
- **Laya 未配置（`intent_focus` 块缺失）**：与 `013` 同口径 fail-closed——本轮不聚焦，判断与改写均不执行。
- **并发发送**：同一线程两轮各自独立判断、改写与留档，不共享、不串写。
- **重新生成 / 重试本轮**：经同一发送链路重发即视为新一轮，判断与改写重新执行。
- **改写期间本轮被用户中止**：改写调用随阶段预算中止，本轮按既有中止收尾，不额外报错。
- **数字人切换后的历史**：只使用**本轮生效数字人**所属线程的历史；无历史按首轮处理。
- **三开关组合矩阵**（意图聚焦 × 输入重写 × 术语替换）：判断与改写仅在「聚焦 + 输入重写」为真时执行；术语替换仅在「聚焦 + 术语替换」为真时执行；其余组合均不产生对应调用，且不新增平台产物键。

### 关键实体

- **输入重写开关（Input Rewrite Switch）**：数字人设计态布尔值，随 SOUL 物化，缺省关闭；与意图聚焦为逻辑与关系。
- **术语替换开关（Term Normalize Switch）**：数字人设计态布尔值，位于意图聚焦配置区，随 SOUL 物化，缺省关闭；与意图聚焦为逻辑与关系；至少拥有一个本体术语映射集时开启才有实际效果。
- **指代判断结论（Need Rewrite Decision）**：单轮结论。属性：结论（真 / 假 / 未执行）、分数、判定素材是否截断、原因、耗时。
- **判定素材（Judgment Material）**：送入判断的尾部 200 字符文本（替换生效时为替换版）。属性：文本、来源（替换后 / 用户输入原文）、是否截断。
- **改写素材（Rewrite Material）**：最近 2 个完整问答轮（`role` + `content`）与本轮输入。属性：轮次列表、轮次数。
- **改写结果（Rewrite Query）**：改写产物。属性：文本（≤ 100 字，不限句类）、是否截断、来源（模型 / 回退原话）、耗时。
- **聚焦判定素材（Focus State）**：实际送入技能 / 行为评分与发散的文本。属性：文本、来源（改写结果 / 原话）、是否截断。

### 不可破坏的不变量

| # | 不变量 | 落点 |
|---|---|---|
| **I-1** | 发给主模型的用户消息、历史文件与用户可见界面中 MUST NOT 出现改写结果（原话唯一） | 上下文组装与消息渲染 |
| **I-2** | 意图聚焦关闭 / 输入重写关闭 / 跳过轮 / 无技能短路轮 MUST 保持零判断、零改写、零新增字段；术语替换关闭 MUST 保持零术语表读取、零替换、零弹窗（判断与改写仍照常） | 意图聚焦编排与开关读取 |
| **I-3** | 聚焦产物（提示格式、卡片 wire、留档既有字段）MUST NOT 因本特性改变 | 提示铸造与卡片装配 |
| **I-4** | 失败一律静默降级：判断失败按不改写、改写失败回退原话，回答优先 | 降级链路 |
| **I-5** | 术语替换仍是发送前一次性确认，且闸门只有一处（预检端点）；本特性 MUST NOT 在运行期重复替换 | 术语替换链路 |
| **I-6** | 平台是配置唯一权威源；运行环境 MUST NOT 反向写回平台 | 部署物化 |

## 假设

- **判断模型**：指代判断用 **Laya**（既有唯一判定出口、单条 `noul`），不由主对话模型判断——避免"多一次模型调用"与不可控输出。
- **判断阈值**：缺省沿用产品口径 **0.8**（与 `016` 技能 / 行为同值），但因候选只有一条、语义与"本轮是否使用某技能"不同，保留独立可配旋钮（FR-050）。
- **「2 轮」口径**：2 个完整问答轮 = 最多 2 条 user + 2 条 assistant，只取正文；`history.jsonl` 本身不含工具消息，故"不含工具"天然成立。
- **改写模型**：即本轮生效的对话模型（请求级模型选择优先于 `config.yaml` 默认模型），失败时不降级到其它模型。
- **改写句类**：不强制问句；陈述句、指令、问句均可，只要求简洁清晰、可独立理解、长度 ≤ 100 字（字符数，与既有 200 字符截断同口径）。
- **改写调用形态**：以非流式方式收集一次输出（`streamChat` 聚合），不展示、不推送、不写历史；不挂任何工具。
- **术语替换时序**：`018` 的术语替换发生在**发送前**并由用户确认，确认后的文本即本轮 `userMessage` 并落历史；因此本特性天然位于其之后，只需保证不再触发第二次替换。
- **术语替换闸门**：新增独立开关后，"有本体术语映射集"只是生效条件，不是开关条件；无映射时预检自然 `applied:false`，故界面只做固定说明、不做动态检测或禁用。
- **开关默认与沿用**：输入重写与术语替换均**默认关闭**（存量与新建一致）；管理台在意图聚焦关闭时置灰但不清空取值（与 `019`「聚焦阶数」同口径）。术语替换的默认关闭改变了现状行为，须由部署说明显式告知。
- **性能预算**：判断（1 条命题，单批）约 0.3~1 秒，改写（短输入短输出）约 1~3 秒，共享既有 10 秒阶段预算。
- **范围边界**：涉及 `agent-backend`、`admin-backend`、`admin-frontend`、`specs/018` 契约与文档；不涉及 `gateway` / `ocr-service` / `jev-service`；聊天前台接口字段不变（关闭术语替换后自然无弹窗）。
- **用户前提**：单用户工作台上下文，具备稳定本站连接（网络中断按降级处理）。

## 非目标（本次明确不做）

- 不把改写结果作为本轮提问发给模型，不替换用户原话，不做"改写后回显/确认"交互。
- 不做指代消解的持久化状态机、跨轮改写追踪或会话级改写缓存。
- 不做改写结果的人工纠正、反馈学习或标注后台。
- 不做二次改写、递归改写或"改写后再判断"的自循环。
- 不强制把改写结果转换为问句，也不按句类做通过 / 拒绝判定。
- 不做多模型对比选型，不新增改写专用模型或按数字人的模型配置。
- 不改 `013` / `016` / `019` 的阈值语义、候选上限、发散口径与提示格式。
- 不改 `018` 的术语表来源、合并口径、匹配算法与确认交互；只新增其开关闸门。
- 不做"是否拥有术语映射集"的实时检测、自动禁用或自动开启。
- 不把改写结果或判断结论写入记忆、画像、摘要或下一步动作卡片。
- 不读取工具调用记录、工具结果、思考内容作为改写素材。
- 本期仅新增「输入重写」与「术语替换」两个数字人开关，不新增其它开关或平台字段；不在聊天前台新增控件。
- 不对存量数字人做回溯性配置改造或批量开启。
