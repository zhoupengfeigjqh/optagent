## 1. 背景与目标

**问题**：一轮回答结束后，用户面对输入框不知道"还能让它做什么"。

**为什么是"模型直接产出"**：最初设想由 jev（TypeSafe System One）预测下一步工具，但
`jev` 的三个 primitive **只回数值、不产文本**——`choice` 的结果形状恒为
`{status, type, choice, confidence, probabilities}`（`jev-service/jev_core.py:371-378`），
`noul` / `score` 同样是数值型。因此"卡片名（人话）"与"jev 排序"必须拆成两次调用：
模型写候选文案 → jev 排序。评审认定其净收益不足（概率只用一次来排序；`choice` 的语义是
"互斥且覆盖全部可能"的择一，而"下一步能做什么"既不互斥也不穷尽，校准的解释性打折；
代价却是每轮两次调用、预算被瓜分、两处失败面）——**遂去掉 jev**：

> **模型一次调用，直接产出有序 Top3 建议（每条含自然语言动作文案 + 绑定的工具）**，渲染成卡片，
> 用户点卡片即发起下一轮对话。

**目标**

- G1 成功回合结束后，回答正文下方出现 1–3 张可点卡片（固定标题「您接下来可以做如下操作：」），
  文案是模型按本轮上下文现写的自然语言动作；**只在会话最新一条 assistant 消息下方出现**（`C9`）
- G2 点击卡片 = 直接发送该文案作为下一轮用户消息，并携带**隐藏 guidance** 提高对应工具的命中率
- G3 建议随 assistant 消息落盘（`GET /api/threads/{id}` 原样下发），**刷新页面后仍在**（在最新一条上）
- G4 任一失败路径**零影响**：对话正常完成、无卡片、有一条结构化告警

## 2. 目标与非目标

**非目标**

- **不自动执行**建议的动作：点击仍是一轮普通对话（由模型决定是否真的调用该工具，guidance 只提高概率）
- **不把 `next_tools` 回灌进下一轮上下文**（它是给用户看的建议，不是模型素材；引导靠 `guidance`）
- **不做建议的事后重算 / 修订**（落盘即定稿，append-only 语义不变）
- **不显示任何排序依据**：无概率、无置信度、无"匹配度"——顺序只是模型的优先级建议（`NT-08`）
- **不改平台侧**（`admin-backend` / `.platform-data/mcp-services.json` / 数字人部署流程）；
  jev 相关配置（`allowed_tools:["noul"]`）与数字人挂载方式**零变更**
- **不在主回答里顺带输出建议**（被否决方案的理由见 §10.3 R6）
- **不追溯**存量缺口（`useChatStream.ts` 未达 80%、`POST /api/threads/:id/messages` 无端点级集成测试、
  全仓 lint/typecheck 存量报错）——宪章「治理 § 适用范围与不追溯」

## 3. 术语

| 术语 | 含义 |
|---|---|
| **候选工具清单** | 送进模型 prompt 的"可建议能力"清单：本轮 LLM 实际可调用的工具集减去平台内部服务（`NT-01`） |
| **建议** | 模型直接产出的有序条目：`{工具暴露名, 动作文案}`（§5.1）；顺序 = 模型给出的优先级 |
| **显示名** | 工具的界面名：内置 = `label`；MCP = `{服务名}: {工具名}`（与 `mcp-tool-adapter.ts:121` 同口径） |
| **暴露名** | 工具的模型可调用名（内置 = `read_file`；MCP = `{服务名}__{工具名}`） |
| **降级** | 任一失败路径下的行为：不出卡片、对话完全不受影响、只落一条 `next_tools.degraded` warn |

## 4. 功能需求

### 4.1 候选工具清单

| 编号 | 需求 | 验收 |
|---|---|---|
| **NT-01** | 候选工具清单 = **本轮 LLM 实际可调用的工具集**：内置工具 = `TOOL.json` 的 `enabled` ∩ `BUILTIN_TOOL_CATALOG`；MCP 工具 = 每个**已连接** server 的 `listTools` 经 `scopeToolsByAllowlist` 过滤后的结果。MUST 与装配 LLM 工具表复用**同一套**三段式判据（`isAvailable` + `listTools` + `scopeToolsByAllowlist`；抽为共享函数，唯一来源） | 单测断言：候选清单的工具名集合 == 装配出的工具表名集合 − 被排除服务（同一 fake 配置下两侧一致） |
| **NT-02** | 清单 MUST 排除 `NEXT_TOOLS_EXCLUDE_SERVERS`（默认 `jev`）所列服务的**全部工具**（按 server 名判定，MUST NOT 用字符串前缀猜测）。理由：它们是平台内部能力，对业务用户无意义（`jev__noul` 之类不该长成一张卡片） | 单测：默认配置下候选清单不含 `jev__*` |
| **NT-03** | 清单项含 `{暴露名, 显示名, 简介}`；清单**为空** → 跳过本功能（没有可建议的能力）；数量 > `NEXT_TOOLS_TOOLS_MAX`（40）→ **取前 40**（顺序 = 装配顺序）并登记为已知限制 | 边界单测 0 / 1 / 40 / 41 |
| **NT-04** | `listTools` 失败 / 未连接的 server → **该服务的工具不进清单**，但 MUST NOT 阻断（其余服务照常） | 单测：一个 server 抛错时仍产出其余工具 |

### 4.2 建议生成（单次 LLM 调用）

| 编号 | 需求 | 验收 |
|---|---|---|
| **NT-05** | 用 `LlmProvider.streamChat({tools: [], thinking: false, signal})`（**默认模型**，与 `summary` 同口径；请求级模型不回退到本功能），配独立 `AbortController`；MUST NOT 复用对话流、MUST NOT 挂进 run 的事件总线 | 单测：fake provider 收到 `tools: []` / `thinking: false`；对话流未被本调用污染 |
| **NT-06** | prompt 为固定模板（唯一来源常量，含五段 + 输出要求）：① **数字人角色摘要**（该数字人 System Prompt 前 **500** 字——同一套工具箱，生产计划数字人与采购数字人该建议的下一步完全不同）② 用户输入（截 **2000** 字）③ 本轮 LLM 回答 `run.buffer`（截 **2000** 字，天然不含工具结果）④ 本轮已用工具名列表 ⑤ 候选工具清单（暴露名 + 显示名 + 简介）⑥ 输出要求：JSON 数组 `[{tool, action}]`，**0–3 条**、按可能性从高到低、宁少不多，并**显式允许返回 `[]`**（没有明确且不重复的下一步时）；MUST 显式要求"**本轮已执行过的动作不要重复建议**"；`action` 是可直接交给数字人执行的下一步动作中文短句（引导 ≤40 字，硬上限见 §5.2），`tool` 只能取自清单。**提示词全文（systemPrompt 逐字稿、user 模板、五段来源与截断规则、每条工具简介截 `NEXT_TOOLS_TOOL_DESC_MAX_CHARS`(80) 字）以 [prompts.md](./prompts.md) 为准，实现时逐字照抄** | 单测：五段内容齐备、角色摘要已截断、各截断标记出现、清单里没有被排除服务的工具、输出要求含"允许空数组"与"不重复建议"（完整断言清单见 `prompts.md` §8） |
| **NT-07** | 解析 MUST 容忍代码围栏与前后噪声（取首个合法 JSON 数组）；形状校验：`tool` 在白名单内、`action` 非空（> `NEXT_ACTIONS_ACTION_MAX_CHARS`(120) 截断）、按 `tool` **去重**（首次出现者胜）、**保持模型给出的顺序**、> 3 条截断。**两种"零条"必须区分**：模型明确返回 `[]` = **正常的"无建议"**（MUST NOT 计为降级、MUST NOT 落 warn，只记 `next_tools.skip`）；**非 JSON / 有条目但被校验全部丢弃** = 降级 | 单测 10 例：正常 / 围栏包裹 / 前后噪声 / 非法 JSON（降级）/ 越界 tool 丢弃 / 空 action 丢弃 / 重复 tool 去重 / 条目全被丢弃（降级）/ **返回 `[]`（正常空结果，无 warn）** / >3 条截断且顺序不变 |
| **NT-08** | **顺序即模型的优先级建议**，MUST NOT 被后端重排；同时 MUST NOT 在任何界面或文档中暗示该顺序含有概率/置信度含义（去掉 jev 后**没有**独立校准来源——这是明确登记的代价，见 §8.2） | 单测：乱序输入 → 输出顺序与输入一致；前端可见文本与 `title` 中无任何数值指标 |
| **NT-09** | 本调用 MUST NOT 计入会话 usage（与 `summary` 同口径）；日志记 `next_tools_ms` 与候选条数 | 单测：`usage` 未被写入；日志字段存在 |

### 4.3 降级与超时

| 编号 | 需求 | 验收 |
|---|---|---|
| **NT-10** | 超时 `NEXT_TOOLS_TIMEOUT_MS`（默认 4000）用 `AbortController` 施加（`streamChat` 接受 `signal`）；超时后 MUST NOT 影响 `history.append`、MUST NOT 影响 `done`；本调用 MUST NOT 依赖任何 `McpManager` 的超时（本功能**不调 MCP 工具**） | 单测：注入恒挂起的 fake provider → 到点中止并降级、`done` 正常 |
| **NT-11** | 仅**成功轮**触发（钩子只挂 `finalizeDone`，`run-manager.ts:405`）；失败轮（`finalizeError`）/ 中断轮（`finalizeAborted`）MUST NOT 调用 | 单测：error / abort 轮无 LLM 调用、无事件 |
| **NT-12** | 跳过的场景（任一命中 → 不出卡片，对话完全不受影响）：**正常跳过**——开关关闭 / 候选工具清单为空 / 模型返回 `[]` / 失败轮·中断轮；**降级**——生成超时 / 生成失败或抛错 / 输出非 JSON / 有条目但被校验全部丢弃 | 每行一个单测 |

### 4.4 落盘与事件时序

| 编号 | 需求 | 验收 |
|---|---|---|
| **NT-15** | 建议 MUST 在 `history.append(assistantMessage)` **之前**产出（`finalizeDone` 既有次序是"**先落盘后广播**"，`run-manager.ts:419-450`）：`next_tools` 作为该行的一部分一次写入，**MUST NOT** 事后改写既有历史行（append-only 语义） | 断言：读到历史行时字段已在；无"二次写历史"的代码路径 |

## 5. 数据模型

### 5.1 assistant 历史行（`threads/{thread_id}/history.jsonl`，新增可选字段）

```jsonl
{"id":"m_abc_0002","role":"assistant","content":"9 月计划已导入 3 个车间…","ts":"2026-10-12T09:12:03.120Z","status":"completed",
 "usage":{"input_tokens":1200,"output_tokens":300},"duration_ms":2480,"agent_name":"production",
 "next_tools":[
   {"name":"grep_files","text":"把计划量低于 500 的车间挑出来看看","toolLabel":"检索文件内容",
    "guidance":"用户希望下一步使用工具 检索文件内容（grep_files）完成「把计划量低于 500 的车间挑出来看看」，如适用请直接调用该工具"},
   {"name":"raw_inventory_purchase_action__QueryPurchaseRecords","text":"查一下这些物料的在途采购单还有多少未到货","toolLabel":"采购库存本体行为: QueryPurchaseRecords","guidance":"…"}]}
```

- `next_tools` **可选**：无建议（或降级）时**不写该键**（`NT-19`）；1–3 项，**数组顺序 = 展示顺序 = 模型给出的优先级**
- 元素 `NextToolSuggestion`（前后端同名同形）：

```ts
{ name: string        // 工具暴露名（后端产出）
  text: string        // 动态动作文案：卡片主文案 + 点击发送的用户消息正文
  toolLabel: string   // 工具显示名：卡片次行（弱化；空串 = 不渲染该行）
  guidance: string }  // 点击携带的隐藏引导（后端拼装，前端不推断；≤500 字符）
```

- **不含任何数值指标**（无概率 / 置信度 / 匹配度）
- **与 `tool_calls` 的差异（登记）**：工具记录因体积与生命周期落**独立文件**（002 §5.1）；
  `next_tools` 只有 ≤3 项、与消息同生命周期，故随消息一行写入（与 `usage` / `duration_ms` 同类）

### 8.1 原则九判定（登记）

**争点**：原则九②要求"降级 MUST 让用户可感知当前状态"。本功能的降级是**不出卡片**——
用户无法分辨"本轮没有可建议的动作"与"生成失败被跳过"。

**判定：不构成违规，不额外提示。** 理由三条：

1. **它不是用户请求的动作**：建议是平台主动提供的一层增强；其缺席不改变本轮结果——回答完整、
   信息未被隐藏或替换、没有"看起来正常的错误状态"（同 002 §4.7/§4.8"无入口 ≠ 降级"的先例）。
2. **"无建议"与"生成失败"在界面上本就不该区分**：开关关闭、候选工具为空（合法配置）、
   模型认为"没有明确可建议的下一步"都会收敛到同一个"无卡片"结果；为此提示会把可选增强变成噪音，
   并暴露内部实现（用户既不知道也不该知道后台做了几次调用）。
3. **可观测性由日志承担**：每次降级一条 `next_tools.degraded`（含 `reason`），满足原则九③；
   超时有界满足④；降级路径逐场景有测试满足⑤。

**若评审要求"可感知"**：唯一语义正确的表述是"本次未生成建议"，但它会污染**正常态**
（关闭开关的数字人每次都显示一行废话）——**不推荐**。

### 8.2 已知风险（登记）

| 风险 | 说明 | 处置 |
|---|---|---|
| **顺序无独立校准** | 去掉 jev 后，1–3 条的顺序只是模型的优先级自述，没有概率/置信度支撑（这正是删掉第二段的代价） | `NT-08`：MUST NOT 在界面或文档中暗示其含概率含义；顺序不影响卡片的可用性（三张卡都可点） |
| **影响面扩大：不再依赖 MCP 挂载** | 原先"只有挂 jev 的数字人才有卡片"；现在**任何数字人**（开关开 + 有可用工具）每轮都多一次 LLM 调用（默认开）——成本与延迟是全平台的，不是少数数字人的 | `NT-30` 显式登记；全局开关兜底；`next_tools_ms` 与调用次数落日志长期观测；后续若成本敏感，可按数字人粒度做开关（**本次不做**，登记为观察项） |
| **`done` 最长被推迟一个超时（默认 4s）** | 期间输入框不可用（`useChatStream.ts:170-172`、`ChatPanel.vue:218`） | 超时可调；`next_tools_ms` 观测；用户已明确接受"与 done 同批" |
| **模型输出不可靠** | 越界工具名 / 空动作 / 重复 / 非 JSON 都可能出现 | 全部走白名单与形状校验（`NT-07`）；`[]` 与"全被丢弃"在日志上**分级**（`skip` vs `degraded`，`NT-13`） |
| **每轮都尝试 → 连续追问时的噪音与成本** | 触发范围已定为"每个成功回合都尝试"（`C8`）：覆盖最全（纯问答轮也有引导），代价是每轮一次 LLM 调用；噪音侧由"只渲染最新一条"（`C9`/`NT-25`）压住 | 模型可主动返回 `[]` 自我收敛（`NT-06`/`NT-07`）；成本侧兜底 = 全局开关 + `next_tools_ms` 观测；进一步手段（**本次不做**）：仅工具轮生成 / 会话级节流 / 按数字人开关 |
| **只渲染最新一条 → 历史建议不可见** | 往上滚时看不到"当时建议过什么"（数据仍在存盘，只是不渲染） | 用户明确选择（`C9`）；渲染规则收窄不影响任意一条卡片可用 |
| **建议可能"建议一件已经做过的事"** | prompt 只带"本轮用了哪些工具"（工具**名**），不带工具**结果正文**——模型看不到结果内容，可能重复建议 | 有意如此（注入结果正文会带来 token 与预算失控，与 002 `TR-18`/`TR-21` 的"上下文有界"取向一致）；`NT-06` 要求 prompt 显式说明"已执行过的动作不要重复建议"；登记为已知限制 |
| 工具极多时只取前 40 | `NEXT_TOOLS_TOOLS_MAX` | 防病态上限；顺序 = 装配顺序，被截断者不进入候选（登记） |
| 动作文案 >120 字符被截断 | `NEXT_ACTIONS_ACTION_MAX_CHARS` | prompt 引导 ≤40 字，硬上限 120 兜底；登记 |

| **成本**：每轮都调一次 LLM？ | a 每轮都试（靠模型 `[]` 收敛）／b 只在本轮调用了工具的回合／c b + 会话级节流 | **a**：不牺牲覆盖，且 b 恰好砍掉"最需要引导"的纯问答轮；成本侧先用开关与日志观测，必要时再单独立项 |
| **噪音**：连续追问刷屏？ | 每条消息都渲染（现状）／只渲染最新一条 | **只渲染最新一条**：治噪音但不改数据（落盘与接口不变），且规则简单可测（`NT-25`） |

### 10.4 与前两版的差异（演进登记）

| # | 版本 | 改定后 | 原因 |
|---|---|---|---|
| R1 | v1（提交草稿）：jev `choice` 是唯一来源，卡片名 = 工具显示名 | 模型直接产出文案 | jev 三个 primitive 均无数值以外出口（`jev_core.py:371-388`），无法产文案 |

| R3 | v2：`options.value` = 工具暴露名、`criteria` = 文案 + 适用情形；`when` 字段 | 删除 `when`、删除 options 构造与 `choice` 结果解析（`parseChoiceTop3` / `mcpResultText`） | 这些存在的唯一目的是喂 jev |
