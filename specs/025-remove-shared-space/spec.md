# 特性规格：下线「共享空间」（2026-11-18）

**特性编号**：025　**状态**：已实现（v1.0）　**影响侧**：agent-backend（运行端契约 + 一次性清理脚本）、frontend（错误码与只读分支）、admin-backend（仅测试夹具）

## 1. 目标

文件空间原本是三个一级目录：`数据准备`（Agent 只读）、`共享空间`（Agent 只读）、`临时空间`（Agent 可读写）。其中**共享空间的价值最低**——它的上传白名单与临时空间**逐项相同**（csv/xlsx/xls/txt/json/html/pdf + 图片），也没有任何"共享"语义（它是**每个数字人各一份**，从不跨数字人共享），于是它唯一的差别只剩"只读"一条。

本特性把共享空间**整体摘除**，文件空间收敛为两个：`数据准备` 与 `临时空间`。摘除包括：运行端常量与白名单、HTTP 契约（`workspace` 的空间数、删除接口的只读分支）、模型可见的工具描述、前端错误码映射与只读渲染分支、以及磁盘上的存量目录（一次性脚本清理）。

## 2. 用户故事

**US1**：作为聊天前台用户，右侧文件树、上传菜单、`@` 面板里不应该再出现一个我从没用过的「共享空间」，我也不需要先理解"只读空间"和"临时空间"有什么区别。

**US2**：作为数字人使用者，我希望 agent 只围着我真正在用的两个空间工作——它不该再被告知"共享空间只读"这种不存在的规则。

**US3**：作为运维，我需要把磁盘上已经存在的 `共享空间/` 目录清掉，但**不能**在服务启动时自动删数据，也不能误删别的目录。

## 3. 功能需求

| 编号 | 需求 |
|---|---|
| **FR-001** | 运行端空间清单 MUST 收敛为 `['数据准备','临时空间']`；`SPACE_SHARED` 常量 MUST 删除，`SPACES` / `SPACE_POLICIES` / 场景清单 / 权限矩阵 / 迁移条目 MUST 全部由该数组派生（MUST NOT 出现第二份空间清单）。 |
| **FR-002** | `GET /api/files/workspace` MUST 只回两个空间，顺序固定为「数据准备 → 临时空间」；目录项 `deletable` 字段 MUST 保留在契约内且恒为 `true`（MUST NOT 删字段——删字段是契约减项且换不来用户可见收益）。 |
| **FR-003** | 「只读空间」概念 MUST 随之下线：`DELETE /api/files` 的 `403 FILE_READONLY` 分支 MUST 删除，错误码 MUST 从运行端与前端 `error-message.ts` 一并移除；前端 `WorkspaceFileList` 的 `deletable` 开关与 `useWorkspace.deletableOf` MUST 删除（删除入口恒渲染）。 |
| **FR-004** | 模型侧 MUST NOT 再看到该空间：`read_file` / `write_file` 工具描述 MUST 改为「数据准备/临时空间」与「数据准备为只读」；`listAvailableDirs()` 退化清单 MUST NOT 含该空间；`builtin-tools` 的空清单 fallback MUST 改为 `临时空间`。 |
| **FR-005** | 对已下线目录的请求 MUST 明确拒绝（`403 UPLOAD_DIR_FORBIDDEN`，message 含「不开放」），MUST NOT 返回空目录或静默成功——历史会话里的旧引用点开即落在此路径。 |
| **FR-006** | **不做能力替代**：原本放共享空间的文档/图片改传 `临时空间`；`临时空间` 的 **30 天未访问自动清理契约 MUST 原样不动**（`TMP_MAX_AGE_MS`、判据 `max(atime,mtime)` 均不改）。本特性 MUST NOT 因此放宽或取消清理。 |
| **FR-007** | 存量磁盘目录 MUST 由**一次性脚本** `agent-backend/scripts/remove-shared-space.ts` 清理，且：①默认 dry-run（打印目录、文件数、字节数，不动磁盘）；②`--apply` 才删；③删除走 `fs-safe`（Windows 非 ASCII 路径下 `fs.rm` 会静默失效）；④服务进程 MUST NOT 引用该模块（MUST NOT 在启动/请求路径上做不可逆删除）。 |
| **FR-008** | 脚本扫描面 MUST 覆盖两种布局：数字人级 `users/{uid}/user-data/{数字人}/共享空间` 与旧用户级 `users/{uid}/user-data/共享空间`；MUST NOT 做任意深度遍历（避免把 `threads/` 等卷进扫描）。 |
| **FR-009** | 迁移逻辑 MUST 同步收窄：`LEGACY_LAYOUT_ENTRIES` 去掉该条目后，用户级残留目录 MUST 被**忽略**（不搬、不删、不影响其余条目迁移），MUST NOT 被误判为数字人目录。 |
| **FR-010** | 规格回写 MUST 按宪章原则一执行：受影响旧条款（001 契约、002、008 FR-030/SC-003、009 FR-001/FR-002/关键实体、014 契约与数据模型）就地标注「2026-11-18 起作废，见 025」，**MUST NOT 删除原文**；示例级提及（023、012 的样例路径）MUST NOT 改动。 |
| **FR-011** | 测试 MUST 按功能删、按行为改挂：断言"共享空间只读/可列/删除 403/工具文案含共享空间"的用例整条删除；仅把"通用扁平空间行为"的覆盖改挂到 `临时空间`；管理端夹具的空间骨架改为两空间。FR-005 的降级行为 MUST 有专门用例钉住。 |

## 4. 契约变更（两侧同改）

| 面 | 变更前 | 变更后 |
|---|---|---|
| `GET /api/files/workspace` | `spaces` 3 项 | `spaces` 2 项；`dirs[].deletable` 恒 `true` |
| `DELETE /api/files` | 共享空间 → `403 FILE_READONLY` | 无该分支；两空间均可删 |
| 任意 `dir=共享空间` | 200（可列/可预览） | `403 UPLOAD_DIR_FORBIDDEN` |
| 内置工具描述 | 数据准备/共享空间/临时空间 | 数据准备/临时空间 |

## 5. 验收场景

1. 右侧文件树 / 上传菜单 / `@` 面板 → **只剩两个空间**，且界面文本中不出现「共享空间」。
2. 上传 pdf/png 到临时空间 → 成功（白名单未变）。
3. 对临时空间里的文件点删除 → 成功（证明删掉只读分支没误伤可删路径）。
4. 请求 `dir=共享空间` → `403 UPLOAD_DIR_FORBIDDEN`，message 含「不开放」。
5. 模型工具描述 / `listAvailableDirs` 输出中不出现该空间。
6. 清理脚本 dry-run → 只打印清单、磁盘不变；`--apply` → 目录连内容删除。
7. 全仓 grep：除本规格、历史规格的作废标注与清理脚本外，无该名字的运行期引用。

## 6. 明确不做

- 不做存量数据迁移到其他空间（**已决策：删除不要**）。
- 不新增"长期存放区"，不延长/取消临时空间 30 天清理。
- 不为旧引用新增专门文案映射（沿用 `UPLOAD_DIR_FORBIDDEN` 既有中文文案「该目录不允许访问」）。
- 不清理历史会话（`threads/*.jsonl`）中已有的旧路径文本——历史消息保持原样。

## 7. 风险与已接受的代价

| 风险 | 处置 |
|---|---|
| 传进临时空间的文档/图片 30 天后被清理，**没有长期存放区了** | 已由用户拍板接受（FR-006） |
| 历史会话里指向该空间的链接点开会报错 | 已由用户拍板接受（FR-005），文案走既有映射 |
| 清理脚本不可逆 | dry-run 默认 + 明细清单 + 先上代码后执行（脚本头注释写明顺序） |
| `FILE_READONLY` 下线影响外部调用方 | 仓内无外部消费方；契约文档已标注作废 |
