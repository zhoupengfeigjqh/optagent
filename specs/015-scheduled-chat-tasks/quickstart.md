## 3. 手工验收场景

### S1 入口位置与覆盖范围（`FR-001`~`FR-005`）

1. 在聊天区观察右上角按钮顺序：搜索 → 工作空间 → **闪电** → 铃铛。
2. 点击闪电。
3. **期望**：中栏被任务页铺满（含聊天头部与消息区），**左栏会话列表仍然可见可点**；右上角按钮自左至右为「运行记录」「创建定时任务」「×」。
4. 点「×」：回到进入前的聊天界面，原会话与输入框草稿未丢失。
5. 切到"未选数字人"状态后刷新：闪电入口为禁用态且有可读原因。

### S2 创建校验（`FR-023`~`FR-034`、`SC-006`）

逐项构造非法值，每次确认都被拦截且**已填内容不清空**：

| 构造 | 期望提示 |
|---|---|
| 名称为空 / 全空格 | 请填写任务名称 |
| 名称与已有任务重复 | 任务名称已存在 |
| 提示词为空 | 请填写任务提示词 |
| 开始时间 = 当前时间之前 | 开始时间必须晚于当前时间 |
| 截止时间 = 开始时间（或更早） | 有效截止时间必须晚于开始时间 |
| 频率 = 0 / 1.5 / 负数 | 执行频率必须是不小于 1 的整数秒 |
| 次数 = 0 / 1.5 / 负数 | 执行次数必须是大于等于 1 的整数 |

合法提交后：弹窗关闭、任务出现在**列表首位**、状态「未开始」、已执行次数 `0 / N`、三角按钮为关闭态。

### S3 到点自动执行（`FR-030`/`FR-035`~`FR-041`、`SC-003`/`SC-005`）

1. 创建任务：名称 `连通性验证`，提示词 `请用一句话回答：今天是几号？`，开始时间 = **当前 + 1 分钟**，间隔 `60` 秒，次数 `2`，截止 = 开始 + 10 分钟，**保持勾选「每次任务创建新对话」**。
2. 打开该行的三角按钮（状态转「执行中」，绿色 + 文字）。
3. **不要**停留在聊天页，切到任何其他会话（或保持任务页打开）。
4. **期望**（每轮检查）：
   - 界面**不会**自动跳转到新会话（`SC-009`）；
   - 左栏出现新会话，名称形如 `连通性验证 2026-10-30 09:00:00`，标题前有闪电标记；
   - 任务页的已执行次数变为 `1 / 2`、`2 / 2`，状态在次数用尽后回到「未开始」；
   - 打开这两个会话：历史完整（提问 + 回答），消息流顶部有"由定时任务「连通性验证」于 … 触发"。
5. 时间核对：实际触发时刻与计划时刻偏差 ≤ 5 秒。

### S4 停用与删除（`FR-013`~`FR-022`）

1. 对一个「执行中」的任务点行尾「×」→ **期望**：被拒绝并提示"请先停止任务"。
2. 关闭三角按钮（状态回「未开始」）→ 再点「×」→ 二次确认框**显示任务名称**。
3. 点取消 → 任务仍在且仍为停用状态。
4. 再点「×」→ 确认 → 任务从列表消失；确认其**已产生的会话仍在左栏**且能正常对话。
5. 打开运行记录：被删任务的记录不再出现（`FR-022`）。

### S5 运行记录与跳转（`FR-047`~`FR-052`）

1. 点「运行记录」→ 弹窗按触发时刻倒序，每条含会话名、任务名、触发时刻、结果。
2. 点一条成功记录 → 弹窗关闭并进入该会话。
3. 用任务筛选器选单个任务 → 仅显示该任务的记录。
4. 在左栏删掉某个由定时任务产生的会话 → 重开运行记录 → 该条标注"会话已删除"且**不可点击**。
5. 一个从未触发过的任务：筛选后显示空态文案（不是空白也不报错）。

### S6 上一轮未结束时到点（`FR-043`、`SC-003`）

1. 创建一个间隔 `1` 秒、次数 `3`、提示词为长任务的定时任务并启用（例如"请写 800 字说明…"）。
2. **期望**：长回答期间到点的轮次被跳过，运行记录出现 `跳过`（原因：上一轮仍在执行），**已执行次数不因跳过而增加**；同一任务不出现两个并发会话。

### S7 重启不补跑（`FR-045`、`SC-007`）

1. 创建一个开始时间为 **当前 + 3 分钟**、间隔 60 秒、次数 5 的任务并启用。
2. 记下 `tasks.json` 中的 `executed_count` 与 `next_run_at`，然后**停掉后端**（Ctrl+C）。
3. 等过 `next_run_at` 之后 2 分钟再 `npm run dev` 重启。
4. **期望**：任务、启用状态、已执行次数**原样保留**；重启后**不补跑**错过的那些时刻（下一次触发落在未来的下一个间隔点）；已停用的任务重启后仍为停用。

### S8 数字人切换与不可用（`FR-054`/`FR-055`）

1. 数字人 A 下创建任务；切到数字人 B → 任务页列表为空（作用域隔离）。
2. 切回 A → 任务仍在且状态不变。
3. 用平台侧或手工方式让 A 不可用（例如改名其配置目录）后重启后端 → 任务自动停用，列表标注"数字人不可用"，运行记录有一条对应 `跳过`。

### S9 键盘与读屏（`FR-001`/`FR-013`/`FR-019`）

1. 仅用键盘：Tab 到闪电入口，Enter 打开任务页；Tab 到行尾三角按钮，Space 切换启停；Tab 到「×」，Enter 弹确认，Esc 取消。
2. 用读屏（NVDA / 讲述人）确认：闪电入口有名称、三角按钮朗读开/关状态、状态列朗读"未开始 / 执行中"、二次确认朗读任务名。

### S10 会话复用模式与重建（`FR-059`~`FR-064`、`SC-011`）

1. 创建任务：名称 `复用验证`，提示词 `请用一句话回答：今天是几号？`，开始时间 = **当前 + 1 分钟**，间隔 `60` 秒，次数 `3`，截止 = 开始 + 10 分钟，**取消勾选「每次任务创建新对话」**。确认列表仍为 6 列、无异常。
2. 启用后等待三次触发。
3. **期望**：
   - 左栏只多出 **1 个**带闪电标记的会话，名称取**首次**触发时刻；
   - 打开该会话可看到 **3 轮**完整问答（每轮以任务提示词开问、模型能看到上一轮内容，例如第二轮回答"上面说的是…"）；
   - 运行记录里有 **3 条**记录，`会话名称` 相同、`触发时刻` 各不相同。
4. 在左栏删除该会话 → 等下一次执行。若剩余次数不足以触发下一次，**另建**一个"复用模式、间隔 1 分钟、次数 2"的任务并启用，删掉它的会话后等待（任务创建后不可修改，不能靠"调小间隔"验证）。
5. **期望**：下一次执行**自动新建**一个会话（名称取本次触发时刻），任务状态仍为「执行中」，运行记录新增一条标注「重建会话」的记录；任务**没有**被停用，次数正常递增。
6. 重命名该复用会话 → 再等一轮执行 → **期望**：标题保持用户改后的名称，新问答追加在同一个会话里。
7. 打开已有（升级前）任务的列表 → **期望**：行为与升级前一致（每轮新建会话）。

### S11 免误会核对（视觉与文案）

1. 复用任务的创建弹窗里，复选框默认**勾选**；不勾选时没有额外必填项。
2. 任务列表不出现"会话模式"列（列数仍为 6），也不出现无法解释的图标。
3. 同一条复用会话的多条运行记录，点击任一条都进入同一个会话。

## 5. 排障速查

| 现象 | 先查什么 |
|---|---|
| 到了时间不触发 | `tasks.json` 里该任务的 `enabled` / `next_run_at` / `executed_count`（是否已 `terminated`）；后端日志是否有 `scheduled_task.tick.*` |
| 触发了但没有会话 | 运行记录里该条 `result=skipped` 的 `reason`（`previous_run_active` / `busy_limit` / `agent_unavailable`） |
| 左栏没有闪电标记 | 该会话 `meta.json` 是否含 `source`；是否刷新过列表（SSE 断连时需重新打开任务页或切换数字人） |
| 任务页显示"加载失败" | 后端日志 `event: 'scheduled_task.list.failed'`；不要以空列表当作"没有任务" |
| 次数不增加 | `skipped` 不计次数是**预期行为**（见 [research.md](./research.md) D4） |
| 复用模式仍然每轮新建会话 | `tasks.json` 里该任务 `new_thread_per_run` 是否为 `false`；若为 `false`，看 `reused_thread_id` 是否为空（首轮写入失败） |
| 复用会话里看不到上一轮内容 | 比对运行记录中这些记录的 `thread_id` 是否相同（不同说明走了重建或新建模式） |
| 复用会话被删后任务停用了 | 不应发生：停用只由"数字人不可用"触发；检查日志 `event: 'scheduled_task.run.rebuild'` 与 `tasks.json` 的 `enabled` / `disabled_reason` |
| 服务重启后任务消失 | 确认 `optAgentRoot/users/{uid}/user-data/{agent}/scheduled-tasks/tasks.json` 是否存在；是否被误删 |
