## 用户场景与测试 *(必填)*

### 用户故事 1 - 回答正文按最小 Markdown 子集结构渲染（优先级：P1）

用户收到一段典型的 agent 回答：二级标题、条目列表、一张排产表、一个 SQL 代码块、若干行内粗体与行内代码。
渲染后他看到的是一份**能读的结构**——标题是标题、列表是列表、表格是表格，`##`、`| --- |`、`**` 这些标记本身
不出现在页面上；同时**原文一个字符都不丢**：解析只吃掉标记，正文可见字符的顺序与内容保持不变。

**为什么是这个优先级**：这是本次改动的核心价值，也是其余三项的前提——没有结构渲染，代码块与高亮都无处附着。

**独立测试**：挂载 `MessageContent`，传入含标题 / 列表 / 表格 / 围栏代码块 / 行内标记的正文，
断言 `h4`、`li`、`th`、`td`、`pre code`、`strong`、`em`、`code`、`a.message-content__link` 存在，
且 `wrapper.text()` 不含 `##`、`| ---`；再断言"分段拼回等于原文"（`buildSegments` 的既有不变式）。

**验收场景**：

1. **Given** 正文含 `## 结论`，**When** 渲染，**Then** 页面出现标题元素且文本为「结论」，标记 `##` 不出现；
   标题层级被压到 `h3`~`h6`（不与页面结构抢 `h1` / `h2`）。
2. **Given** 正文含 `- 甲\n- 乙`，**When** 渲染，**Then** 出现 2 个 `li`，文本分别为「甲」「乙」。
3. **Given** 正文含表头行 + 分隔行 + 数据行，**When** 渲染，**Then** 出现 `thead`/`th` 与 `tbody`/`td`，分隔行不出现。
4. **Given** 正文含 ```` ```sql ```` 围栏，**When** 渲染，**Then** 出现代码块且角标为「sql」，代码正文逐字一致（含换行）。
5. **Given** 正文含 `**可以** *也许* \`code\``，**When** 渲染，**Then** 分别渲染为 `strong` / `em` / `code`。
6. **Given** 正文含 `[文档](https://a.b/c)` 与 `[危险](javascript:alert(1))`，**When** 渲染，**Then** 前者渲染为链接
   （`href` 为原地址），后者**退化为纯文本**（不产生 `a` 元素，地址字符串也不出现）。
7. **Given** 正文含本子集**不支持**的语法（嵌套列表、图片 `![]()`、原生 HTML、`_斜体_`、脚注），
   **When** 渲染，**Then** 按纯文本原样输出（不丢字符、不误渲染成别的结构）。
8. **Given** 正文含手写换行 `第一行\n第二行\n\n另起一段`，**When** 渲染，**Then** 段落被空行切开、
   段内换行保留（`white-space: pre-wrap`），段落文本分别为「第一行\n第二行」与「另起一段」。
9. **Given** 正文含超长 URL 或超长标识符，**When** 渲染，**Then** 不撑破气泡（换行而不横向溢出）；
   表格与代码块超出宽度时**自身横向滚动**。

### 用户故事 2 - 代码块一等公民：等宽、横向滚动、一键复制（优先级：P1）

用户拿到一段 SQL 或命令，想直接复制走。他点代码块右上角的「复制」，剪贴板里得到的是**代码原文**——
不带高亮标记、不带行号、不带任何渲染产物；按钮短暂变为「已复制」后复原。

**为什么是这个优先级**：代码块是 agent 输出里最高频的"要拿走"的内容；不能复制的话，用户只能手工拖选
（在多行横向滚动的 `<pre>` 里几乎必然选错）。

**独立测试**：挂载 `MessageContent`（或 `MessageCodeBlock`）传入围栏代码块 + 关键词，
点击 `.message-code__copy`，断言 `navigator.clipboard.writeText` 收到**逐字等于代码原文**的字符串。

**验收场景**：

1. **Given** 代码块内容含搜索命中（已高亮成 `<mark>`），**When** 点击复制，**Then** 写入剪贴板的是
   分段拼接后的**原文**（含被高亮的字符本身，不含标记）。
2. **Given** 复制成功，**When** 立即观察按钮，**Then** 文案与 `aria-label` 变为「已复制」；**约 2 秒后**复原为「复制」。
3. **Given** 代码块内出现搜索关键词，**When** 渲染，**Then** 命中同样产生 `<mark>` 且带全局 `data-match-index`。
4. **Given** 剪贴板不可用（非安全上下文 / 权限被拒 / 写入抛错），**When** 点击复制，**Then** **静默不改文案**
   （MUST NOT 谎报"已复制"）。
5. **Given** 代码块正文为空，**When** 点击复制，**Then** 不写入空串到剪贴板（无操作）。
6. **Given** 组件带着一个待复原的复制定时器被卸载，**When** 卸载，**Then** 定时器被清除（无悬挂回调）。

### 用户故事 3 - 会话导出为 Markdown 文件（优先级：P2）

用户在左侧历史会话项上点「导出」，浏览器下载到一个 `.md` 文件：一级标题是会话标题，随后一行元信息
（数字人、导出时间、消息条数），每条消息以 `---` 分隔、带角色与时间的小标题；引用过的文件、工具调用与状态、
失败轮的错误码都留在稿子里。

**为什么是这个优先级**：agent 的输出本身就是 Markdown，原样带走能在文档工具里直接渲染；而"导出给人看"
的场景要求**非正文信息也不能丢**（少了"这一轮失败了"的说明，稿子里就是一段无解释的空白）。

**独立测试**：直接对纯函数 `threadToMarkdown(thread, messages, exportedAt)` 断言文本：标题、元信息、
`---` 分隔、角色标签（用户侧「我」、模型侧数字人名 / 缺省「助手」）、引用 / 工具 / 失败行、末尾换行；
对 `exportFilename(thread)` 断言非法字符净化与空标题兜底。

**验收场景**：

1. **Given** 一条标题为「生产计划复核」、含 1 条用户消息的会话，**When** 导出，**Then** 文本以 `# 生产计划复核`
   开头，含「数字人：demo」「共 1 条消息」「## 我 · <时间>」「---」，且以换行结尾。
2. **Given** 会话标题为 `null` 或全空白，**When** 导出，**Then** 标题行为「# 未命名会话」，且**不出现**空标题行 `# `。
3. **Given** 一条 `assistant` 消息带 `agent_name: 'demo'`，**When** 导出，**Then** 小标题为 `## demo · …`；
   缺 `agent_name` 时退回 `## 助手 · …`。
4. **Given** 消息带引用文件 / 工具调用 / 失败状态，**When** 导出，**Then** 稿中含 `> 引用：@plan.csv`、
   `> 工具：ocr_image（success）`、`> 状态：本轮失败（LLM_UNAVAILABLE）`。
5. **Given** 已完成的轮次（无引用 / 无工具 / 未失败），**When** 导出，**Then** 上述三类元信息行**一行都不出现**。
6. **Given** 标题含 `\ / : * ? " < > |`，**When** 取文件名，**Then** 这些字符替换为 `_` 并加 `.md` 后缀；
   标题为空时用 `会话-<thread_id 前 8 位>.md` 兜底。
7. **Given** 当前中栏只加载了一页历史（"加载更早的消息"未点过），**When** 导出，**Then** 导出稿**包含全部消息**
   ——MUST 以全量翻页重新拉取，MUST NOT 直接使用内存里的分页窗口。
8. **Given** 全量拉取失败，**When** 导出，**Then** 给出错误提示且**不产生任何文件**（MUST NOT 落一个空文件）。
9. **Given** 导出成功，**When** 观察下载动作，**Then** 内容经 `Blob` + 临时 `<a download>` 落地，
   对象 URL 在**下一轮任务**中撤销（立刻撤销会让部分浏览器来不及取数据）。

### 用户故事 4 - 长回答的流式渲染节流与滚动跟随（优先级：P2）

一段两千字的回答输出期间，页面不再发卡：状态本身仍逐 token 精确（中断、重试、落盘语义不变），
但"给渲染看的那一份"按 50ms 窗口合并；用户向上翻阅时视口不被打扰，回到近底部即恢复跟随；
非底部时右下角浮出「回到底部」；本端发消息时**强制**置底；切回旧会话恢复上次的阅读位置；
一轮回答落定后读屏只播**一句结论**（"回答已完成，共 N 字"）。

**为什么是这个优先级**：这是体验问题而非能力问题——不做也不会丢数据，但两千字的回答会让页面几乎不可用。

**独立测试**：用假定时器断言窗口内多次变化只落一次、文本变短（新一轮）立即落定、卸载清定时器；
用组件测试断言上翻后暂停跟随、回到近底部恢复、「回到底部」显隐与点击、本端发送强制置底、
「加载更早消息」只补偿高度不跳底部、切回旧会话恢复存档位置。

**验收场景**：

1. **Given** 流式文本在 50ms 窗口内连续变化 3 次，**When** 推进时间轴到窗口末尾，**Then** 渲染影子只落定**一次**
   且值为最后一次的内容；窗口内中间态**不落到界面**。
2. **Given** 上一轮正文非空、新一轮把累积文本清空（变短），**When** 文本变短，**Then** 影子**立即**对齐
   （不让上一轮内容在新气泡里闪现一个窗口）。
3. **Given** 组件被卸载且存在待落定时器，**When** 卸载，**Then** 定时器被清除。
4. **Given** 用户停在底部，**When** 新消息追加或流式增量到达，**Then** 视口跟随到最新。
5. **Given** 用户上翻（距底部 > 80px），**When** 流式增量到达，**Then** 视口**不被打扰**；`atBottom` 为假。
6. **Given** 非底部状态，**When** 观察消息区右下角，**Then** 出现「回到底部」按钮（`aria-label` 为「回到底部」）；
   点击后滚到最新且按钮消失；**贴底时 MUST NOT 渲染该按钮**。
7. **Given** 用户已上翻到很久以前，**When** 本端发送一条消息，**Then** **不看 80px 阈值**，立即强制置底
   （自己的消息必须马上可见）。
8. **Given** 会话 A 已上翻过、会话 B 贴底离开，**When** 从 B 切到 A，**Then** 恢复 A 的存档位置；
   切回 B 时仍然置底（"回来看到最新进展"语义不被破坏）。
9. **Given** 点「加载更早的消息」，**When** 前插一页，**Then** 只补偿新增高度、视口停在原内容上，**不跳到底部**。
10. **Given** 容器尺寸变化（右侧面板开合 / 窗口缩放），**When** 尺寸变化，**Then** 重新判定是否贴底
    （`ResizeObserver` 存在性守卫；jsdom 无该 API 时不影响测试与功能）。
11. **Given** 一轮回答落盘（新的 assistant 消息追加），**When** 落定，**Then** 隐藏播报区更新为
    「回答已完成，共 N 字」；**逐 token 不播报**（`aria-live="off"`）；失败轮与中断轮不播报。

### 用户故事 5 - 会话重命名与按会话分桶的草稿（优先级：P3）

用户双击历史项标题（或点编辑图标）就地改名，Enter / 失焦确认、Esc 取消——**Esc 只收编辑框，不会顺手掐掉正在输出的回答**；
在会话 A 打了一半去 B 问一句，那半句留在 A，B 的输入框是干净的，切回 A 那半句还在。

**为什么是这个优先级**：两者都是"顺手要有"的可用性细节，不阻塞上面四条主线。

**独立测试**：`HistoryItem` 组件测试（双击进入编辑、Enter / 失焦提交、Esc 取消且 `stopPropagation`、
空标题与未改动不发请求、`disabled` 时各入口均不发事件）；`useChatStream` 草稿用例（切会话存旧取新、
`null` 会话不建桶、桶上限淘汰）。

**验收场景**：

1. **Given** 一个已命名会话，**When** 双击标题，**Then** 变行内输入框并预填当前标题、获得焦点且文本全选。
2. **Given** 编辑中，**When** 按 Enter 或失焦，**Then** 提交新标题；标题为空或未改动时**不发请求、就地收手**。
3. **Given** 编辑中，**When** 按 Esc，**Then** 只退出编辑态，**MUST NOT** 触发"Esc 中断本轮"。
4. **Given** 某项被禁用（存在进行中会话），**When** 点击重命名 / 导出 / 删除 / 选择，**Then** 一律不派发事件。
5. **Given** 重命名请求失败，**When** 失败返回，**Then** 列表标题回滚为原值并给出提示（乐观更新的回滚）。
6. **Given** 会话 A 的草稿为「半句」，**When** 切到会话 B，**Then** B 的输入框为空；切回 A，**Then** 恢复「半句」。
7. **Given** 视图态新对话（`activeThreadId === null`）的草稿，**When** 离开再点「新建会话」，**Then**
   **不出现**幽灵草稿（`null` 会话不建桶）。
8. **Given** 思考开关被切换，**When** 会话内刷新页面，**Then** 开关状态被恢复；`sessionStorage` 不可用时静默降级。

### 边界情况

- 流式输出中途：围栏代码块**收尾缺失**时吃到文末（不丢内容、不误判为普通段落）。
- 表格判定：只有"本行含 `|` 且**下一行是分隔行**"才认定表格；正文里普通的含竖线句子不被误判。
- **已知取舍（有用例钉住）**：搜索命中若落在**被丢弃的标记里**（例如搜索 `**`、`---`、`# `），
  `useSessionSearch` 仍按**原文**计数，但页面上没有可高亮的节点（序号与节点数不相等，**不是 bug**）。
- Markdown 链接标签内部出现搜索命中：高亮与链接叠加为"可点的高亮"（`type='mark'` 且带 `href`）。
- `javascript:` / `data:` 等伪协议、`//host/…` 形态的链接一律**不产生可点元素**。
- 导出侧：0 条消息的会话仍应导出（标题 + 元信息，`共 0 条消息`）；分页接口 `total` 与实际条数不一致时
  以**空页**为终止条件（不死循环）。
- 滚动侧：`ResizeObserver` / `scrollIntoView` 在 jsdom 中缺失，MUST 做存在性守卫（测试环境不参与布局）。
- 复制侧：`navigator.clipboard` 缺失或写入抛错 → 静默不反馈。

### 关键实体

- **Piece / InlineRun / MarkdownBlock**（`utils/markdown.ts`）：块级与行内解析结果，每个片段带原文偏移 `start`。
- **ContentSegment**（`utils/segments.ts`）：渲染单元（`text` / `link` / `mark`），链接与高亮可叠加。
- **ViewBlock / ViewRun**（`MessageContent.vue`）：渲染态视图块，字段一律存在（不适用的留空），避免模板里对联合类型收窄。
- **ChatStreamStore**（`useChatStream.ts`）：本轮状态机契约（含 `draft` 的分桶语义、`lastRetryableTurn` 的不变式）。
- **Conversation / Message**（`api/types.ts`）：导出输入；`exportedAt` 为可注入时钟。

## 成功标准 *(必填)*

- **SC-001**: 结构渲染正确性——标题 / 列表 / 表格 / 代码块 / 行内标记在组件测试中各有断言，且标记本身不出现。
- **SC-002**: 高亮序号连续性——跨结构（标题 → 列表 → 表格 → 代码块）的命中序号与 `countMatches` 口径一致。
- **SC-003**: 导出稿零信息丢失——引用 / 工具 / 失败三类元信息在对应场景下必现，在无该事实时必不出现。
- **SC-004**: 导出完整性——中栏仅加载一页时，导出稿仍含全部消息（多页夹具验证）。
- **SC-005**: 三个超限文件拆至 ≤500 行，且拆分**零行为变化**（既有测试全绿，不修改断言口径）。
- **SC-006**: 新增 / 拆分产生的模块 100% 有同名测试，覆盖率 ≥ 80%，全局地板只上不下。
- **SC-007**: 前端全量本地门禁绿：`npm run test` / `npm run lint` / `npm run typecheck`。
- **SC-008**: 零新增依赖（`frontend/package.json` 依赖段 `git diff` 为空）。
- **SC-009**: 长回答（≥2000 字）期间渲染更新次数从"每 token 一次"降到"每 50ms 至多一次"（由 `useThrottledText` 用例度量）。

## 假设

1. **单用户工作台**（当前 `admin`），无并发多客户端场景；导出与滚动均为单页内行为。
2. 正文里的"标记未被完全消费"是**已知取舍**而非缺陷：宁可少渲染，不可渲染错，更不可引入注入面（原则四 / 九）。
3. 自研最小子集是**刻意选择**：引入"渲染器 + XSS 净化器"是**两个**新依赖，评审成本高于当前收益（原则六）。
4. 导出格式固定为 Markdown（agent 输出本就是 Markdown，原样带走可直接被文档工具渲染）；**不做** PDF / JSON / Word。
5. 本特性**不触碰**会话归属（009 的数字人作用域）与会话列表的"只返回有消息的会话"口径。
6. 移动端布局不在本次范围（与既有三栏工作台一致）。
