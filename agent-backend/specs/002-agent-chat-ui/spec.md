# 功能规范：Agent 前端交互页所需的后端能力补全

**Feature Branch**: `002-agent-chat-ui`

**Created**: 2026-09-10

**Status**: Draft

**Input**: User description: "根据前端功能规范（三栏 Agent 聊天页：流式对话、思考折叠、工具调用仅展示工具名、消息级 token/耗时/复制/点赞点踩、8 类空间文件上传与 @ 引用、数字人与 MCP 状态、模型切换、历史会话、tmp 内容右侧预览），评估并补全后端能力缺口。注意：历史会话不保存历史思考内容和工具返回的内容。"

**背景**：现有后端已具备核心对话闭环（SSE 流式对话、会话历史、文件上传/下载、数字人选择、usage 聚合），经差距分析识别出 10 项缺口。本规范定义支撑前端功能规范所需的全部后端能力增量，前端交互行为本身以《Agent 前端交互页面功能规范》为准，不在此重复。

**重要约束（用户已明确）**：会话历史 MUST NOT 持久化思考内容（reasoning/thinking）与工具调用结果；历史消息仅保留用户正文与助手最终回复正文。思考内容与工具调用信息仅在会话进行期间实时下发，不写入历史。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 流式对话事件补全：工具调用与耗时（优先级：P1）

前端在等待回复期间需要展示"仅工具名、不含调用结果"的工具调用提示，并在回复完成后展示本条消息的 token 数与执行耗时。后端在流式对话过程中向下游发送工具调用开始/结束事件（仅含工具名称与状态），并在完成事件中附带本轮耗时（秒）与 token 用量。

**优先级理由**：这是前端 P1 核心体验（思考中提示、工具名闪现、消息级用量反馈）的唯一数据来源，缺失则前端主流程无法交付。

**独立测试**：发起一条会触发工具调用的消息 → 验证事件流中出现工具开始/结束事件且仅含工具名 → 验证完成事件含 token 数与耗时（秒）。

**验收场景**：

1. **给定** 一轮对话正在进行且模型发起工具调用，**当** 工具调用开始，**则** 事件流中出现工具调用开始事件，仅包含工具名称，不包含入参详情与返回结果。
2. **给定** 工具调用已开始，**当** 工具调用结束（成功或失败），**则** 事件流中出现工具调用结束事件，前端可据此移除该工具名提示。
3. **给定** 一轮对话完成，**当** 完成事件下发，**则** 该事件包含本轮 input/output token 数与执行耗时（秒）。
4. **给定** 一轮对话中发生多次工具调用，**当** 各次调用交错进行，**则** 每次调用均有独立的开始与结束事件，且可区分不同调用。
5. **给定** 一轮对话未发生工具调用，**当** 对话完成，**则** 不出现工具调用事件，完成事件仍含 token 数与耗时。

### 用户故事 2 - 历史消息元数据补全（优先级：P1）

前端切换或刷新会话后，需要为每条历史消息展示 token 数与耗时，并能将用户消息与对应的助手回复配对呈现。后端在会话历史中，为每条消息提供稳定的消息标识、时间戳，并为助手消息记录其 token 用量与执行耗时；历史记录不包含思考内容与工具调用结果（含工具名）。

**优先级理由**：前端要求"100% 已完成消息展示 token 与耗时"，刷新后也必须可展示；同时用户明确要求历史不落思考/工具内容，需要以明确契约固化。

**独立测试**：完成一轮带工具调用的对话 → 重新获取会话历史 → 验证每条消息含消息标识与时间戳、助手消息含 token 与耗时 → 验证历史中不出现思考内容与工具调用信息。

**验收场景**：

1. **给定** 会话中已有完成的多轮对话，**当** 查询会话历史，**则** 每条消息包含唯一标识、角色、正文、时间戳。
2. **给定** 助手消息已完成，**当** 查询会话历史，**则** 该消息附带本轮 token 用量（input/output）与执行耗时（秒）。
3. **给定** 一轮对话曾包含思考输出与工具调用，**当** 查询会话历史，**则** 返回内容中不包含思考内容，也不包含工具名称、入参或返回结果。
4. **给定** 用户消息中包含 @ 文件引用，**当** 查询会话历史，**则** 该消息保留文件引用信息（文件名与文件地址），前端可还原"@文件名"展示。
5. **给定** 一条回复失败或超时的轮次，**当** 查询会话历史，**则** 该轮有明确的失败记录（状态与错误信息），前端可在聊天区正常展示错误。

### 用户故事 3 - 消息反馈（点赞/点踩）（优先级：P1）

前端为每条完成的助手消息提供点赞/点踩操作。后端提供提交消息反馈的接口，按消息标识记录反馈状态（无/点赞/点踩），同一消息的点赞与点踩互斥、可取消或改选；查询历史时返回各消息的当前反馈状态。

**优先级理由**：与核心对话共同构成最小可用产品（P1）；当前后端零支持。

**独立测试**：完成一轮对话 → 对该消息提交点赞 → 查询历史验证反馈状态 → 改选点踩验证互斥 → 再次点击取消。

**验收场景**：

1. **给定** 一条已完成的助手消息，**当** 提交点赞，**则** 该消息反馈状态记为点赞。
2. **给定** 某消息已为点赞状态，**当** 提交点踩，**则** 状态互斥切换为点踩。
3. **给定** 某消息已有反馈，**当** 提交取消反馈，**则** 状态恢复为无反馈。
4. **给定** 已提交过反馈的会话，**当** 查询会话历史，**则** 各消息返回其当前反馈状态。
5. **给定** 对不存在的消息标识提交反馈，**当** 请求到达，**则** 返回明确的错误（消息不存在）。

---

### 用户故事 4 - 数字人当前态查询与 MCP 服务状态（优先级：P2）

前端页面刷新后需要知道当前选中的数字人；聊天区正上方需要展示当前数字人名称及其挂载的 MCP 服务列表与每个服务的连接状态（正常/中断）。后端提供"当前数字人"查询接口，并在数字人信息中提供其 MCP 服务清单与实时连接状态；MCP 状态变化可在短延迟内被前端感知。

**优先级理由**：支撑前端 P2 的数字人展示与切换约束（会话进行中置灰），依赖后端状态可查。

**独立测试**：选择数字人 → 查询当前数字人 → 查询其 MCP 服务状态 → 模拟某 MCP 中断 → 验证状态在约定延迟内变为"中断"。

**验收场景**：

1. **给定** 已选中某数字人，**当** 查询当前数字人，**则** 返回其名称与明细信息；未选中时返回明确的"未选中"状态。
2. **给定** 当前数字人挂载了多个 MCP 服务，**当** 查询其服务状态，**则** 每个服务返回名称与连接状态（正常/中断）。
3. **给定** 某 MCP 服务由正常变为中断，**当** 再次查询，**则** 状态在 5 秒内反映为中断。
4. **给定** 会话进行中，**当** 尝试切换数字人，**则** 后端拒绝并返回明确错误（前端据此置灰）。
5. **给定** 无进行中的会话，**当** 切换数字人成功，**则** 下一轮对话按新数字人配置初始化执行。

---

### 用户故事 5 - LLM 模型列表与按会话切换（优先级：P2）

前端输入区提供模型选择。后端提供可选模型列表接口（含当前默认/选中项标识），发消息接口支持指定本轮使用的模型；未指定时使用默认模型。

**优先级理由**：影响"用哪个模型问"的核心选项，但可在核心对话之后交付。

**独立测试**：查询模型列表 → 选择非默认模型发送消息 → 验证该轮使用了所选模型（用量/响应记录可查）。

**验收场景**：

1. **给定** 系统配置了多个模型，**当** 查询模型列表，**则** 返回全部可用模型及默认模型标识。
2. **给定** 用户选择了某模型，**当** 携带该模型发送消息，**则** 本轮对话使用该模型。
3. **给定** 用户未指定模型，**当** 发送消息，**则** 使用系统默认模型。
4. **给定** 用户指定了不存在的模型，**当** 发送消息，**则** 返回明确错误且不开始本轮对话。

### 用户故事 6 - 文件能力补全：tmp 上传、内联预览与 @ 引用（优先级：P2）

前端上传入口包含 tmp（临时空间），且聊天区中 tmp 空间的链接需在右侧预览区内联展示；输入框 "@文件名" 引用在发送消息时需携带真实文件地址。后端：放开 tmp 目录上传；提供文件内联预览能力（可在线展示而非强制下载）；发消息接口支持结构化文件引用（文件名 + 所属目录/地址），并将会话中的文件引用随消息持久化，供历史还原展示。

**优先级理由**：上传与 @ 引用是前端 P2 精准提问能力；tmp 预览支撑 P3 右侧预览区。

**独立测试**：向 tmp 上传文件 → 通过预览接口在线获取内容 → 发送含文件引用的消息 → 查询历史验证引用可还原。

**验收场景**：

1. **给定** 上传入口包含 tmp，**当** 用户向 tmp 目录上传文件，**则** 上传成功（与其他业务目录一致的校验规则）。
2. **给定** tmp 或其他目录中存在文件，**当** 前端请求在线预览，**则** 内容以可内联展示的方式返回，而非强制附件下载。
3. **给定** 请求预览的文件不存在或已被清理，**当** 请求到达，**则** 返回明确错误，前端可在预览区展示错误提示。
4. **给定** 用户发送的消息包含 @ 文件引用，**当** 提交消息，**则** 请求中以结构化形式携带每个引用的文件名与文件地址（目录 + 文件名）。
5. **给定** 引用的文件不存在，**当** 提交消息，**则** 返回明确错误（引用了不存在的文件）。
6. **给定** 含文件引用的消息已完成，**当** 查询会话历史，**则** 该消息的文件引用（文件名与地址）完整返回。

---

### 用户故事 7 - 工作空间文件列表（优先级：P3）

前端右上角提供工作空间文件入口，展示当前用户自己的空间文件。后端提供跨目录的工作空间文件汇总查询（一次返回各空间目录下的文件清单，或按目录分别可查），文件项含名称、大小、更新时间。

**优先级理由**：效率增强功能；现有按目录列举接口可部分复用，仅需确认汇总形态。

**独立测试**：在多个目录各上传文件 → 查询工作空间文件 → 验证各目录文件齐全且含元信息。

**验收场景**：

1. **给定** 用户在多个空间目录下有文件，**当** 查询工作空间文件，**则** 返回各目录（含 tmp）的文件清单，每项含文件名、大小与更新时间。
2. **给定** 某目录为空，**当** 查询，**则** 该目录返回空清单而非错误。

---

### 边界情况

- 工具调用与思考内容交错时，事件流如何保证顺序与配对（同一次调用的开始/结束可关联）？
- 工具调用失败时，结束事件如何标识失败（仍不暴露结果内容，仅状态）？
- 助手消息由多次模型往返（含工具循环）组成时，token 与耗时按整轮聚合还是分次返回？（默认：按整轮聚合返回一次）
- 回复失败/超时的轮次，token 与耗时如何记录（已消耗部分照常记录，状态标记失败）？
- 历史消息量极大时，分页查询中消息标识的稳定性如何保证？
- 反馈接口的并发提交（用户快速连点赞/点踩）如何保证最终状态一致？
- MCP 状态查询的频率与缓存策略（状态滞后不超过 5 秒，同时避免对 MCP 服务造成探测压力）？
- tmp 空间文件被定时清理后，历史消息中的 @ 引用如何返回（引用信息保留、文件不可预览时前端提示）？
- 内联预览大文件（如 50MB Excel）时如何限制（大小上限、可预览类型白名单）？
- 模型列表变更（新增/下线模型）后，会话中已选模型的兼容性如何处理？
- 单用户固定 admin 的鉴权预留：本阶段接口如何为后续多用户隔离留出扩展（如所有查询隐式按当前用户过滤）？

## 需求 *(必填)*

### 功能需求

**流式对话事件**

- **FR-001**: 对话事件流 MUST 在工具调用开始时下发工具调用开始事件，且该事件 MUST 仅包含工具名称与调用标识，MUST NOT 包含工具入参详情与返回结果。
- **FR-002**: 对话事件流 MUST 在工具调用结束时下发工具调用结束事件（含调用标识与成功/失败状态），MUST NOT 包含工具返回内容。
- **FR-003**: 一轮对话中多次工具调用 MUST 各自独立成对（开始/结束），事件顺序 MUST 与实际发生顺序一致。
- **FR-004**: 对话完成事件 MUST 包含本轮的 input token 数、output token 数与执行耗时（秒）；多轮模型往返（工具循环）按整轮聚合返回。
- **FR-005**: 本轮回复失败或超时时，错误事件 MUST 携带错误码与错误信息；已消耗的 token 与耗时如可统计 MUST 一并提供。
- **FR-006**: 思考内容事件 MUST 仅在会话进行期间实时下发，MUST NOT 写入会话历史。

**会话历史**

- **FR-007**: 会话历史中的每条消息 MUST 具有唯一消息标识、角色、正文与时间戳。
- **FR-008**: 已完成的助手消息在历史中 MUST 附带本轮 token 用量（input/output）与执行耗时（秒）。
- **FR-009**: 会话历史 MUST NOT 包含思考内容，也 MUST NOT 包含工具调用信息（工具名、入参、结果）。
- **FR-010**: 历史中的用户消息 MUST 保留 @ 文件引用信息（文件名与文件地址），供前端还原"@文件名"展示。
- **FR-011**: 回复失败或超时的轮次 MUST 在历史中保留失败状态与错误信息。
- **FR-012**: 历史分页查询 MUST 保持消息标识稳定，分页行为与现有限制（limit≤200）一致。

**消息反馈**

- **FR-013**: 系统 MUST 提供按消息标识提交反馈的接口，反馈取值为：无 / 点赞 / 点踩。
- **FR-014**: 同一消息的点赞与点踩 MUST 互斥；重复提交同一反馈 MUST 视为取消（恢复为无反馈）。
- **FR-015**: 查询会话历史时，各消息 MUST 返回其当前反馈状态。
- **FR-016**: 对不存在的消息提交反馈 MUST 返回明确错误。
- **FR-017**: 反馈状态变更 MUST 持久化，且在并发提交下最终状态确定一致。

**数字人与 MCP**

- **FR-018**: 系统 MUST 提供"当前选中数字人"查询接口；未选中时 MUST 返回明确的未选中状态。
- **FR-019**: 系统 MUST 提供当前数字人挂载的 MCP 服务清单，每个服务含名称与连接状态（正常/中断/**未知**）；**2026-09-11 修订**：新增"未知"态表示尚未产生连接结果（实例未创建或首次建连进行中），MUST NOT 以"中断"兜底；状态与实际的滞后 MUST NOT 超过 5 秒。
- **FR-020**: MCP 服务中断时，接口 MUST 仅如实返回中断状态，MUST NOT 产生额外阻断行为。
- **FR-021**: 存在进行中会话时，切换数字人 MUST 被拒绝并返回明确错误；切换成功后，新数字人配置 MUST 在下一轮对话重新初始化生效（现有行为，需以契约固化）。

**模型**

- **FR-022**: 系统 MUST 提供可选 LLM 模型列表接口，返回全部可用模型并标识默认模型。
- **FR-023**: 发消息接口 MUST 支持指定本轮使用的模型；未指定时 MUST 使用默认模型。
- **FR-024**: 指定不存在或不可用模型时，MUST 返回明确错误且不开始本轮对话。

**文件与引用**

- **FR-025**: tmp（临时空间）目录 MUST 支持文件上传，校验规则与其他业务目录一致。
- **FR-026**: 系统 MUST 提供文件内联预览能力，使前端可在线展示文件内容（非强制附件下载）；预览 MUST 限制文件大小与类型，超限返回明确错误。
- **FR-027**: 预览不存在或已清理的文件时，MUST 返回明确错误。
- **FR-028**: 发消息接口 MUST 支持结构化文件引用列表（每项含文件名与文件地址：目录 + 文件名），与消息正文一并提交。
- **FR-029**: 消息引用的文件不存在时，MUST 返回明确错误。
- **FR-030**: 系统 MUST 提供工作空间文件汇总查询，返回各空间目录（含 tmp）下的文件清单，每项含文件名、大小与更新时间。

**质量与契约**

- **FR-031**: 所有新增/变更接口 MUST 遵循统一错误响应格式（code / message / details），并同步更新接口文档（OpenAPI 或等价物）后与前端确认契约。
- **FR-032**: 所有新增非流式接口的 P95 响应时间 MUST NOT 超过 200ms。
- **FR-033**: 新增能力 MUST 为后续多用户与鉴权预留扩展（所有数据查询隐式限定当前用户范围），v1 仍按单用户实现。
- **FR-034**: 新增持久化状态（消息元数据、反馈）的写操作 MUST 保证原子性：消息与其元数据/反馈状态不得出现部分写入。

### 关键实体

- **流式事件（Stream Event）**：对话进行期间实时下发的单次通知，包含类型（思考增量 / 正文增量 / 工具调用开始 / 工具调用结束 / 完成 / 错误）、负载与时间；不落历史。
- **消息元数据（Message Metadata）**：随历史消息持久化的附加信息，包含消息标识、时间戳、token 用量（input/output）、执行耗时（秒）、反馈状态与轮次状态（完成/失败）；不含思考内容与工具调用信息。
- **消息反馈（Message Feedback）**：用户对单条助手消息的评价记录，取值为无 / 点赞 / 点踩，按消息标识唯一。
- **文件引用（File Reference）**：消息中通过 @ 选择的文件指针，包含文件名、所属目录与文件地址；随消息持久化。
- **MCP 服务状态（MCP Service Status）**：数字人挂载服务的实时连接状态（正常/中断）及名称。
- **可选模型（Available Model）**：系统配置的可供选择的 LLM 模型，含标识与是否为默认。
- **预览资源（Preview Resource）**：以内联可展示形式返回的文件内容，受大小与类型白名单约束。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**: 发生工具调用的对话中，100% 的调用在事件流中产生成对的开始/结束事件，且任何事件中工具返回内容暴露次数为 0。
- **SC-002**: 100% 已完成的助手消息（含刷新后查询历史）均携带 token 数与耗时（秒），且与用量统计一致。
- **SC-003**: 会话历史查询结果中思考内容与工具调用信息出现次数为 0（抽样与自动化校验均通过）。
- **SC-004**: 消息反馈提交后，查询历史返回的反馈状态 100% 与最后提交一致（含互斥切换与取消）。
- **SC-005**: MCP 服务状态从实际中断到接口返回中断的滞后不超过 5 秒。
- **SC-006**: 前端刷新后可通过"当前数字人"接口恢复选中状态，准确率 100%。
- **SC-007**: 携带指定模型的消息 100% 由该模型执行；指定非法模型 100% 被拒绝且有明确错误。
- **SC-008**: tmp 目录上传成功率与业务目录一致（同等校验规则下无额外失败）；合法预览请求 100% 以内联方式返回。
- **SC-009**: 含 @ 文件引用的消息，历史查询 100% 可还原文件名与文件地址。
- **SC-010**: 新增非流式接口 P95 响应时间 ≤ 200ms；事件流中新增事件不引入可感知的下发延迟（事件产生到下发 < 100ms，网络传输除外）。
- **SC-011**: 回复失败/超时的轮次 100% 在历史中可查询到失败状态与错误信息。
- **SC-012**: 所有新增接口具备同步更新的接口文档，且错误响应 100% 符合统一错误格式。

## 假设

- v1 仍为单用户（固定 admin），无鉴权；接口设计为多用户预留但不在本期实现。
- 流式通道沿用现有 SSE；新增事件类型为对现有协议的向后兼容扩展（前端旧版本可忽略未知事件）。
- 工具调用事件仅需工具名与状态即可满足前端展示（仅工具名、调用后消失），无需透出参数与结果。
- token 与耗时按"整轮对话"（含工具循环的全部模型往返）聚合统计一次返回，与现有 usage 聚合口径一致。
- tmp 目录文件会被定时清理；历史消息中的 @ 引用信息保留，文件被清理后预览接口返回明确错误，前端据此提示。
- 内联预览的类型白名单与上传白名单一致（.csv/.xlsx/.txt/.json/.pdf），大小上限与上传上限一致（50MB），如需调小在计划阶段确定。
- 思考/快速模式为会话级前端设置，后端沿用现有 `thinking` 参数，无需变更。
- 历史会话默认 10 条 / 更多 100 条为前端分页参数选择，后端现有分页能力（limit≤200）已满足，无需变更。
- 前端搜索高亮、外部链接直接跳转、复制操作等纯前端能力不涉及后端变更，不在本规范范围内。
