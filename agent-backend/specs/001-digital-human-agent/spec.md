# Feature Specification: 数字人Agent对话后端

**Feature Branch**: `001-digital-human-agent`

**Created**: 2026-09-09

**Status**: Draft

**Input**: 来源：req_final.md（数字人Agent后端功能需求文档 v2.0 终版）

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 与数字人进行流式对话 (Priority: P1)

用户选择一个数字人进入对话，发送消息后以流式方式逐步看到数字人的回复；可开启思考模式查看推理过程（前端折叠展示）；可随时中断当前回复；切换页面或关闭浏览器不影响回复的最终保存。

**Why this priority**: 这是产品的核心价值——数字人对话能力。没有它其他功能（文件管理、监控、统计）都没有意义。

**Independent Test**: 选择一个数字人发送一条消息，观察流式回复完整返回并可在对话历史中查看，即交付了最小可用价值。

**Acceptance Scenarios**:

1. **Given** 用户已选择数字人，**When** 用户发送一条消息，**Then** 系统创建对话（thread）并逐步流式返回正式回复内容，回复完成后该轮问答可在历史中查看。
2. **Given** 用户开启思考模式，**When** 发送消息，**Then** 系统分别推送推理流与正式回复流，推理内容不进入对话历史。
3. **Given** 一轮回复正在输出，**When** 用户发送停止信号，**Then** 该轮输出与推理被中断，未保存内容丢弃，已保存历史不受影响。
4. **Given** 一轮回复正在输出，**When** 用户关闭浏览器（断开连接），**Then** 该条回复继续完成并保存，用户重连后可看到完整回复。
5. **Given** 用户在同一数字人下已有 3 个进行中的对话，**When** 再发起新对话，**Then** 系统拒绝并返回友好提示。
6. **Given** 数字人依赖的某个外部服务不可用，**When** 用户发起对话，**Then** 对话仍可正常进行，仅涉及该外部服务时提示"当前服务不可用，请稍后尝试"。

---

### User Story 2 - 管理对话（Thread 生命周期） (Priority: P2)

用户可以查看、重命名、删除自己的历史对话；对话列表按最近更新排序，标题自动取首条消息前 20 字；长对话通过滚动摘要保持上下文连贯。

**Why this priority**: 对话管理是多轮使用的基础体验，但单轮对话（P1）已可独立交付价值。

**Independent Test**: 创建多个对话、重命名、删除，验证列表顺序与删除后的连带清理。

**Acceptance Scenarios**:

1. **Given** 用户有多个对话，**When** 查看对话列表，**Then** 按更新时间倒序展示，标题为首条用户消息的前 20 个字。
2. **Given** 一个对话，**When** 用户重命名，**Then** 列表中显示新标题。
3. **Given** 一个对话及其产生的临时文件，**When** 用户删除该对话，**Then** 对话历史、摘要及该对话的全部临时文件一并删除。
4. **Given** 一个超过 20 条消息的长对话，**When** 继续提问，**Then** 数字人仍能利用更早对话的要点作答（滚动摘要生效），即使某次摘要生成失败对话也不中断。

---

### User Story 3 - 上传文件供数字人使用 (Priority: P2)

用户将生产计划、产线信息等业务文件上传到数据准备空间的对应业务子目录或共享空间，数字人在对话中可读取这些文件作答，并可将输出文件写入临时空间供用户获取。

**Why this priority**: 业务文件是数字人回答专业问题的数据来源，但对话功能本身不依赖上传。

**Independent Test**: 上传一个合规文件后向数字人提问相关内容，验证数字人能引用文件内容回答。

**Acceptance Scenarios**:

1. **Given** 用户上传一个 ≤50MB 的合规格式文件到数据准备业务子目录，**When** 上传完成，**Then** 文件名自动追加时间戳保存，不与已有文件相互覆盖。
2. **Given** 数据准备子目录中已有文件，**When** 用户提问相关问题，**Then** 数字人读取文件内容并据此作答。
3. **Given** 数字人在回答中产出文件，**When** 写入临时空间，**Then** 文件名带对话标识前缀，不同对话的产出互不冲突。
4. **Given** 数字人尝试写入数据准备或共享空间，**When** 写入发生，**Then** 系统拒绝该写入、记录日志，对话流程不中断，用户得到提示。
5. **Given** 临时空间中存在 7 天未访问的文件，**When** 定期清理执行，**Then** 这些文件被自动清除。

---

### User Story 4 - 数字人配置查询 (Priority: P3)

用户/前端可查询可用数字人列表与详情（人格设定、已启用工具与技能），数字人配置的创建与下发由设计平台负责，本期后端只读。

**Why this priority**: 支撑前端选择数字人的入口，但不改变对话核心链路。

**Independent Test**: 查询数字人列表与单个数字人详情，返回其人格设定与能力清单。

**Acceptance Scenarios**:

1. **Given** 系统中已下发若干数字人配置，**When** 用户请求数字人列表，**Then** 返回全部可用数字人。
2. **Given** 一个数字人，**When** 请求详情，**Then** 返回其人格设定、启用的内置工具与技能描述。

---

### User Story 5 - 运维监控与用量统计 (Priority: P3)

运维人员可查看存活实例、系统健康状态；管理人员可按对话、数字人、时间范围查询 Token 用量，用于成本控制。

**Why this priority**: 运营支撑能力，不直接影响终端用户对话体验。

**Independent Test**: 调用监控接口查看实例与健康信息；进行若干轮对话后按维度查询 Token 用量汇总。

**Acceptance Scenarios**:

1. **Given** 系统正在运行，**When** 运维调用监控接口，**Then** 返回存活实例明细（用户、数字人、活跃对话数、空闲时长、降级状态）与进程/内存/磁盘健康信息。
2. **Given** 已发生多轮对话，**When** 按对话或数字人或时间范围查询用量，**Then** 返回对应的输入/输出 Token 汇总。

---

### Edge Cases

- 数字人依赖的外部服务连接失败：实例以降级状态就绪，调用到该服务时友好提示，不影响其余能力。
- 对话历史文件存在损坏行：跳过损坏行加载；整体损坏时自动重建（清空历史）并告警。
- Agent 实例运行中崩溃：自动销毁并记录崩溃日志，用户下次发消息时自动重建实例。
- 实例池已满且无可淘汰的空闲实例：拒绝新请求并友好提示，不排队、不中断在用对话。
- 外部服务调用超时（30 秒，重试 1 次）：返回超时错误，数字人以"当前服务不可用，请稍后尝试"回应。
- 临时空间写入失败：返回友好错误（如"临时空间不足，请稍后重试"）。
- 用户上传超限文件（>50MB 或格式不符）：拒绝上传并提示原因。
- 摘要生成失败：本轮对话使用旧摘要，不阻塞回复。

## Requirements _(mandatory)_

### Functional Requirements

**用户与认证**

- **FR-001**: 系统 MUST 支持多用户数据隔离，用户数据目录包含用户维度。
- **FR-002**: 本期所有请求 MUST 归属内置 `admin` 用户；接口与数据访问 MUST 按"当前用户"抽象编写，以便后续接入账号密码 + JWT 认证时不改动业务逻辑。

**文件管理**

- **FR-003**: 系统 MUST 为每个用户提供三个文件空间（**2026-09-13 修订**，取代原"7 业务目录 + tmp/shared"模型）：`数据准备/`（Agent 只读，按 scenario 定义的业务子目录组织，如"生产计划"）、`共享空间/`（Agent 只读，扁平无子目录）、`临时空间/`（Agent 唯一可写）。目录初始化仅创建三个空间（+ threads + agents）；数据准备子目录由 scenario 加载时惰性创建。
- **FR-004**: 用户 MUST 能上传文件到数据准备子目录、共享空间与临时空间；数据准备 MUST 带子目录（`数据准备/{业务子目录}`），共享空间与临时空间 MUST NOT 带子目录。
- **FR-005**: 上传文件名 MUST 自动追加时间戳（`_YYYYMMDD_HHMMSS`）避免覆盖；单文件 ≤ 50MB；扩展名按空间区分——数据准备仅 `.csv`/`.xlsx`，共享空间与临时空间允许 `.csv/.xlsx/.txt/.json/.pdf` 及图片（`.jpg/.jpeg/.png/.bmp/.webp/.gif/.tif/.tiff`）；扩展名不符时错误消息 MUST 指明该空间支持的格式。
- **FR-006**: `临时空间/` 内 Agent 产出文件 MUST 以 `{thread_id}_{timestamp}_{filename}` 命名；7 天未访问的文件 MUST 被定期自动清除。
- **FR-007**: `共享空间/` 目录 MUST 对 Agent 只读，用于跨对话、跨数字人共享资料；**用户也不可删除其中文件**（删除请求返回 403 `FILE_READONLY`）。
- **FR-007a**（**2026-09-13 新增**）: 用户场景 MUST 由 `users/{user_id}/scenario.json` 预定义（形如 `{"scenario": "生产调度", "data_prep_dirs": ["生产计划", "产线信息", ...]}`）；目录名 MUST 校验（不允许 `/`、`\`、`..`，长度 ≤64，去重）；后端 MUST 按 mtime 缓存并热加载（改文件无需重启），加载成功时惰性创建数据准备子目录；scenario 缺失或损坏时进程 MUST NOT 退出，业务 API（files/workspace/chat 附件校验等）MUST 返回 503 `SCENARIO_NOT_CONFIGURED`（"用户未设置场景信息，请联系管理员"）。

**对话管理**

- **FR-008**: 每个对话 MUST 由后端生成 UUID 作为 thread_id，包含 `history.jsonl`（对话历史）与 `summary.json`（滚动摘要）。
- **FR-009**: 对话历史 MUST 采用 JSONL 追加写、不分片；仅保存 user 与 assistant 消息；不保存 thinking、工具调用日志、system prompt 与中间过程。
- **FR-010**: 系统 MUST 提供对话创建、列表（按更新时间倒序，标题取首条 user 消息前 20 字）、重命名、删除接口；删除对话 MUST 连带删除其历史、摘要及 `临时空间/` 下该对话前缀的全部文件。

**数字人配置**

- **FR-011**: 数字人配置 MUST 包含 `SOUL.md`（人格，追加到 System Prompt）、`MCP.json`（外部服务声明）、`TOOL.json`（内置工具启用声明）、`skills/{skill_name}/SKILL.md`（技能，YAML frontmatter 头部追加到 System Prompt）。
- **FR-012**: 本期后端对数字人配置 MUST 只读，仅提供列表与详情查询；创建、编辑、下发由数字人设计平台直接写目录。

**Agent 生命周期**

- **FR-013**: Agent 实例 MUST 以 (user_id, agent_name) 为键，实例只固化数字人配置（System Prompt、工具、外部服务连接、模型配置），MUST NOT 持有对话历史；每轮请求由业务层按 thread_id 拼装历史与摘要注入。
- **FR-014**: Agent 实例 MUST 在用户首次发送消息时创建并驻留内存复用；并发额度为 1 用户 : 最多 3 个并发对话（**2026-09-10 修订**：额度按 **userId** 统计、**跨数字人累计**，退出/切换数字人不释放已有进行中 run 的额度）。用户同一时刻只有一个"当前选中数字人"，但 `select` 为**覆盖式**——切换数字人**无需先退出**，也不校验会话是否进行中；退出/切换不销毁实例。**会话不绑定数字人**：同一会话内可切换数字人，本轮由当前选中数字人执行并在**下一轮消息**生效（每条消息记录 `agent_name`）。
- **FR-015**: 全局最多驻留 5 个 Agent 实例（可配置），空闲超时 10 分钟（可配置）自动销毁；LRU 仅淘汰无进行中推理的空闲实例；池满且无空闲可淘汰时 MUST 拒绝请求并友好提示，不排队、不淘汰在用实例。
- **FR-016**: 系统 MUST 提供监控接口：存活实例明细（用户、数字人、活跃对话数、空闲时长、降级状态）与健康信息（进程存活、内存、`.opt-agent` 磁盘可用空间），只读、内网调用。

**对话与历史策略**

- **FR-017**: 上下文注入 MUST 采用"最近 20 条消息完整保留 + 更早消息并入滚动摘要（作为 System Prompt 一部分注入，不设上限）"的策略。
- **FR-018**: 窗口外每新增满 20 条消息 MUST 异步触发一次增量摘要重写（旧摘要 + 新归档消息 → 新摘要）；摘要生成失败 MUST NOT 阻塞对话，本轮使用旧摘要。
- **FR-019**: 每轮对话结束后 MUST 异步追加写入 user 与 assistant 消息到历史文件，不等待写盘完成即返回响应。

**输出与思考模式**

- **FR-020**: 对话输出 MUST 采用 SSE 流式输出，事件分为 thinking（推理流，不落盘）、content（正式回复流）、done、error 四类；不输出工具调用日志、中间推理链（thinking 除外）、外部服务请求日志。
- **FR-021**: 用户 MUST 能按轮开启/关闭思考模式；默认模型为 `deepseek-v4-flash-vision-exp`（全局单模型，重启可切换；2026-09-09 由 `deepseek-v4-flash` 修订）。

**文件读写权限控制（核心安全策略）**

- **FR-022**: Agent 的全部文件读写 MUST 经过显式文件访问代理层（路径规范化 + 白名单校验）；写操作仅限 `临时空间/` 且强制 thread_id 前缀；违规写入 MUST 抛出权限错误并记录日志，不中断对话流程。
- **FR-023**: 系统 MUST 提供 5 个内置工具：`read_file`（读数据准备与共享空间，单文件默认截断 32KB，超出提示分段读）、`write_file`（仅写临时空间）、`list_dir`、`grep_files`（限可读目录，经同一代理）、`calculator`（安全表达式求值）；工具由 `TOOL.json` 声明启用。`read_file`/`list_dir` 的目录说明 MUST 由 scenario 动态生成（数据准备各子目录 + 共享空间 + 临时空间）；scenario 缺失时降级为仅共享空间/临时空间。
- **FR-024**: 外部服务（MCP）超时统一 30 秒、重试 1 次；建连失败 MUST NOT 阻断 Agent 启动，实例降级就绪并标记该服务不可用，调用时友好提示并告警；若外部服务自身有写能力，其权限边界 MUST 在注册配置中声明。

**异步与中断**

- **FR-025**: 对话记录写入、文件保存等 I/O MUST 异步执行；切换页面、新建对话、关闭浏览器 MUST NOT 影响进行中的输出与历史保存。
- **FR-026**: 客户端断开时，正在输出的回复 MUST 继续完成并落盘，后续步骤就此收尾不开启新步骤。
- **FR-027**: 用户 MUST 能基于 thread_id 发送停止信号，系统中断该对话的流与推理、丢弃本轮未保存消息，MUST NOT 销毁 Agent 实例，已保存历史不受影响。

**Token 用量统计**

- **FR-028**: 每轮对话 MUST 记录一条用量：user_id、thread_id、agent_name、input_tokens、output_tokens、时间戳，存储于 SQLite；提供按 thread_id、agent_name、时间范围过滤的汇总查询；按日切分的日志文件仅作审计备份。

**异常与容灾**

- **FR-029**: 历史文件存在无法解析的行时 MUST 跳过加载；整体损坏时自动重建（清空历史）并告警。
- **FR-030**: Agent 实例因未知异常崩溃时 MUST 自动销毁并记录崩溃日志；用户下次发消息时自动重新初始化。
- **FR-031**: 所有操作（文件读写、Agent 初始化、外部服务调用、错误）MUST 记录结构化日志。

### Key Entities

- **用户（User）**: 系统使用者；本期固定为内置 admin；拥有独立的文件空间、对话与数字人实例。
- **数字人（Agent 配置）**: 由设计平台下发的只读配置，含人格（SOUL.md）、技能（SKILL.md 头部）、内置工具启用（TOOL.json）、外部服务声明（MCP.json）。
- **Agent 实例**: (user_id, agent_name) 键的内存运行时，固化数字人配置，不持有对话历史；受实例池容量与空闲超时管理。
- **对话（Thread）**: 一次独立对话，UUID 标识，含历史（JSONL）与滚动摘要；标题取首条用户消息前 20 字。
- **消息（Message）**: user/assistant 角色内容，JSONL 逐行追加保存。
- **滚动摘要（Summary）**: 窗口外历史的派生物，含摘要文本与已覆盖消息序号。
- **文件**: 分属三个空间——数据准备（只读，按 scenario 业务子目录组织）、共享空间（只读共享、扁平、用户不可删）、临时空间（可写、按对话前缀、7 天未访问清理）。
- **场景配置（Scenario）**: `users/{user_id}/scenario.json` 预定义的场景名与数据准备子目录清单；后端按 mtime 热加载；缺失/损坏时业务 API 返回 503 `SCENARIO_NOT_CONFIGURED`。
- **Token 用量记录**: 每轮对话一条，含用户、对话、数字人、输入/输出 Token 与时间戳。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 用户发送消息后 5 秒内看到回复开始输出（首字延迟，模型自身推理时间不计）。
- **SC-002**: 非对话类接口 95% 的请求在 200ms 内返回。
- **SC-003**: 核心对话服务可用性达到 99.9%。
- **SC-004**: 系统支持单机同时驻留 5 个数字人实例、单用户 3 个并发对话（跨数字人累计），超限请求 100% 收到友好拒绝提示而非排队或失败。
- **SC-005**: 客户端断开后，进行中的回复 100% 完成保存，用户重连后可看到完整内容。
- **SC-006**: 超过 20 条消息的长对话中，数字人仍能引用更早对话要点作答（滚动摘要生效），摘要失败时对话成功率 100% 不受影响。
- **SC-007**: 数字人对数据准备与共享空间的写入尝试 100% 被拦截且不中断对话。
- **SC-008**: 管理人员可按对话、数字人、时间范围查询 Token 用量，每轮对话 100% 有对应用量记录。

## Assumptions

- 本期单机部署，不引入 Redis 等外部中间件；实例池与会话状态抽象为接口，预留分布式扩展点。
- 本期不实现认证，所有请求归属内置 admin 用户；JWT 认证为后续迭代。
- 数字人配置的创建、编辑、下发由数字人设计平台负责（直接写目录），后端只读。
- 全局单模型 `deepseek-v4-flash-vision-exp`，通过 `config.yaml` 的 models 列表指定（默认取第一项），重启生效；模型提供方抽象为接口，多模型扩展本期不实现。
