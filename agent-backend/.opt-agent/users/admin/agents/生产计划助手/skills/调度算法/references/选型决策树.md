# 调度算法选型决策树

按约束逐层判定，走到叶子节点即得到推荐策略。**先问约束，再选算法**。

## 第一层：是否有硬截止时间？ 

- **有（实时/强时效）** → 走第二层 A
- **没有（批处理/后台）** → 走第二层 B

### 第二层 A（有截止时间）

- 任务可抢占、截止时间严格 → **EDF（最早截止时间优先）**
  - 必须搭配**准入控制**：新任务进入前判断系统是否仍可调度，否则过载时全体超期。
- 截止时间较松、还要兼顾吞吐 → **EDF + 优先级/权重** 混合，或按松弛时间排序（最小松弛优先）。

### 第二层 B（无截止时间）

- **任务同质、无所谓谁先谁后** → **FCFS**（实现最简单）
- **能预估任务耗时** → **SJF / SRTF**（平均周转最优）
  - 加 aging 防止长任务饥饿。
- **有明确重要级差异** → **优先级调度**
  - 必须加 aging 或最低配额，避免低优先级永远不执行。
- **多租户共享、要求按比例公平** → **WFQ**
  - 明确空闲资源的借用与回收规则。
- **交互式、要求响应速度** → **RR**
  - 时间片按"切换开销 vs 响应延迟"权衡取值。
- **规模很大、约束复杂（NP 难）** → **贪心/启发式**
  - 定义解质量下限，必要时做局部搜索改进。

## 第三层：规模与工程约束

| 约束 | 影响 |
|---|---|
| 单机 vs 分布式 | 分布式需额外处理一致性（锁/租约）与分片，避免重复调度 |
| 任务耗时是否可预估 | 不可预估时 SJF 退化为启发式，需按历史统计估计 |
| 是否允许抢占 | 不允许抢占时，长任务会阻塞队列，需拆批或预留槽位 |
| 峰值/过载策略 | 必须有降级与准入，否则系统整体退化 |

## 常见误区

1. **一上来就选"最优算法"**——没有目标函数就没有最优；
2. **忽略饥饿**——优先级/SJF 不做 aging，低优先级任务会长期得不到执行；
3. **忽略可观测**——没有排队时长等指标，后续无法调优；
4. **忽略幂等**——调度系统必然会遇到重复触发，不做幂等就是数据事故。
