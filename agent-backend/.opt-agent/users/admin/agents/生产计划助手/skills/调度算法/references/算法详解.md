# 调度算法详解

按"思路 → 伪代码 → 复杂度 → 失效边界"展开，供选型后查阅实现细节。

## 1. 先来先服务（FCFS）

- **思路**：按任务到达顺序取任务，非抢占。
- **伪代码**：`while queue: task = queue.pop_oldest(); run(task)`
- **复杂度**：入队出队 O(1)（队列结构），无排序开销。
- **失效边界**：一个长任务会阻塞后面所有短任务（队头阻塞），平均等待时间随任务耗时差异剧烈上升。

## 2. 最短作业优先（SJF）

- **思路**：每次选预计耗时最短的任务；有抢占版（SRTF）。
- **伪代码**：`queue.sort_by(estimated_cost); run(queue.pop_first())`
- **复杂度**：用最小堆 O(log n)；预估耗时不准时退化为启发式。
- **失效边界**：长任务可能长时间得不到执行（饥饿），常配合 aging 使用。

## 3. 优先级调度

- **思路**：按优先级取任务，同优先级按到达时间。
- **伪代码**：多级队列，从高到低扫描，非空即取；`effective_priority = base + aging(waited_time)`
- **复杂度**：O(1)~O(log n)（按是否用堆）。
- **失效边界**：低优先级饥饿——必须加 aging 或最低配额兜底。

## 4. 时间片轮询（RR）

- **思路**：每个任务分配固定时间片，用完放回队尾。
- **伪代码**：`for t in queue: run(t, slice); if not t.done: queue.push(t)`
- **复杂度**：O(1) 每次取任务；切换开销随时间片变小而增大。
- **失效边界**：时间片过小 → 上下文切换吃掉吞吐；过大 → 退化成 FCFS。

## 5. 加权公平（WFQ）

- **思路**：按权重分配资源配额，长期按比例分配，短期允许借用。
- **伪代码**：维护每个租户的虚拟完成时间 `finish_time += cost / weight`，取最小者。
- **复杂度**：O(log n)（优先队列）。
- **失效边界**：权重配置是治理问题，配错会长期不公平；空闲资源需定义借用/回收规则。

## 6. 贪心 / 启发式

- **思路**：按局部最优规则排序（最早截止、最小松弛、最大收益…），用于 NP 难排程的近似解。
- **伪代码**：`while pending: pick = argmax(score(task)); assign(pick, free_slot)`
- **复杂度**：通常 O(n log n) ~ O(n²)，取决于评分与冲突检测。
- **失效边界**：局部最优不等于全局最优；需定义可接受的解质量下限并做随机重启/局部搜索改进。

## 7. 最早截止时间优先（EDF）

- **思路**：截止时间越早越先执行，可抢占。
- **伪代码**：`queue.sort_by(deadline); run(queue.pop_first())`
- **复杂度**：O(log n)（堆）。
- **失效边界**：系统过载时几乎所有任务都会超期（没有优雅降级），因此必须配合**准入控制**（新任务先判断可调度性）。

## 通用实现检查表

- [ ] 是否定义了明确的**目标函数**与度量方式？
- [ ] 硬约束（截止/资源/依赖）是否强制满足？
- [ ] 是否有**防饥饿**机制（aging / 最低配额）？
- [ ] 是否**幂等**（重复调度不会产生重复副作用）？
- [ ] 是否有**可观测**指标（排队时长、执行时长、等待原因）？
- [ ] 过载时是否有**降级/准入**策略？
