# 生鲜订单识别

流程：订单图片 + SKU 清单 → `fresh_order_parse` → 一句总览 → 仅对 `review_rows` / `error_rows` 做 AI 审查 → 最终推荐表 → 一份 Excel（单 sheet `识别结果`）。

## 铁律

1. **每次解析必出 Excel**：调过 `fresh_order_parse` 就必须 `write_file` 出 `.xlsx`；只有 1 行、三组行全空（只留表头）也要出。
2. **最终推荐覆盖全部行**：`auto_rows` + `review_rows` + `error_rows` 一行不漏，逐行给 `是否需要审核`（`是`/`否`）；表固定五列，不加列。
3. **只留一张表**：对话只给「一句总览 + AI 审查结论 + 最终推荐表」，不输出「表一/表二/表三」明细，不贴原始 JSON；Excel 也只有 `识别结果` 一张 sheet。
4. **顺序固定**：总览 →（必要时）AI 审查 → 最终推荐 → Excel；Excel 未产出不得结束回复。

## 一、前置条件

| 输入 | 必需 | 说明 |
|---|---|---|
| 订单图片 | 是 | 单张 `.png` / `.jpg` / `.jpeg`，用户上传到 `数据准备/生鲜订单图片` |
| SKU 清单 | 是 | `.xlsx`，含「SKU清单」表（SKU编码、商品名称、别名、品类、规格、单位、是否启用） |

- 缺任一文件 → 先索取，不调用工具、不编造结果。
- 文件名不确定 → `list_dir` 查真实文件名，禁止猜名。
- 多图：逐张调用、每张各出一份 Excel（文件名带该图名）；全部完成后另出合计 `_汇总_生鲜订单.xlsx`，覆盖所有图全部行。

## 二、调用工具

`fresh_order_parse`（MCP 服务 `fresh-parse`）：

| 参数 | 必填 | 取值 |
|---|---|---|
| `image_path` | 是 | 图片相对路径，如 `数据准备/生鲜订单图片/订单1.png` |
| `sku_path` | 是 | SKU 清单相对路径，如 `数据准备/生鲜sku表/SKU清单.xlsx` |
| `noise_path` / `synonyms_path` | 否 | 留空，用服务内置默认 |
| `layout` | 否 | 留空（`auto` 自动判别表格/手写）；仅当版面解析错乱且用户同意重试时填 `table` / `list`，`off` 退回旧逐行 OCR |
| `reader` | 否 | 留空（`auto`：表格走 OCR、手写走 LLM）；未配 LLM Key 时 `auto` 自动按 OCR 处理 |

- 只写文件空间相对路径（`数据准备/...`），禁止 http(s) 与盘符路径。
- 一张图一次调用，不为「再确认」重复调。
- 报错（直链、OCR、文件不存在）→ 如实说明并给出下一步，不得假装成功。
- 本技能只读：不改 SKU 清单、不写回订单、不生成新 SKU。

## 三、结果展示：一句总览

工具返回 `auto_rows`（高度匹配）、`review_rows`（待审核）、`error_rows`（异常）。正文只写：

> 共识别 N 行：高度匹配 a 行、待审核 b 行、异常 c 行。

- 计数为 0 也照写，N = a + b + c。
- 不输出三组行的明细表、不贴原始 JSON（明细不落正文、不落文件）。
- 待审核或异常非空 → 先做第四节；都为 0 → 直接第五、六节。

## 四、AI 审查（只针对待审核与异常）

触发：`review_count > 0` 或 `error_count > 0`；都为 0 则跳过本节，最终推荐全部写 `否`。
范围：只有 `review_rows` 与 `error_rows`；`auto_rows` 不审、不改写，工具结果即最终结果。

1. `read_file` 读 `sku_path`（xlsx 自动转文本）。
2. 按「原始行 / 标准化名称 / 候选名称」检索商品名称、别名、品类、规格；没命中换更短的核心词；被截断用 `offset` / `limit` 续读。
3. 每条给推荐 + 证据：SKU 侧（编码、名称、别名或规格、单位、是否启用）、订单侧（原始行、数量）、一句判断依据。
4. 清单确实没有 → 写「SKU 清单中未找到」+ 已检索关键词，请用户确认；不得臆造编码或名称。

## 五、最终推荐表（五列，必给）

| 序号 | 商品名称 | 数量 | SKU编码 | 是否需要审核 |
|---|---|---|---|---|
| 1 | 土豆 | 2斤 | VEG-002 | 否 |
| 2 | ==番茄== | ==3斤== | ==VEG-001== | ==是== |
| 3 | ==西兰花== | ==5斤== | ==—== | ==是== |

- 覆盖三组行全部行，序号连续，一行不漏。
- 商品名称：直接写商品名本身（`auto_rows` 取命中名，其余取审查结论），**前后不加任何符号或前缀**；查无时写最可能的品种名（如 `西兰花`）。
- 是否需要审核：`否` = `auto_rows`；`是` = 待审核/异常。只两种值，不留空。
- 标红：`是` 的行**整行标红**——该行五个单元格都用 `==内容==` 包裹（内侧不留空格）；`否` 的行、表头与合计行不标红。
- 表尾 `合计 N 行：无需审核 a、需审核 b`，a + b = N。
- 数量取 `quantity`（含单位），缺失写 `—`。
- 本表与 Excel `识别结果` sheet 逐条一致，不多不少行。

## 六、Excel（单表）

`write_file(filename="<会话标识>_<图片名称>_生鲜订单.xlsx", content=<CSV>)`

- 文件名三段：会话标识原样 + 原图名去扩展名（非法字符与空白换 `_`，同名加 `_2`、`_3`）+ `_生鲜订单.xlsx`，如 `a1b2c3_订单1_生鲜订单.xlsx`。
- 取不到图名时用相对路径末段，再不行用 `订单1`、`订单2`。
- **第一行必须是 `# Sheet: 识别结果`**，第二行才是表头；漏写会落成 `Sheet1`（最常见错误）。
- 只有这一张 sheet，不再写明细表；含逗号或换行的单元格用双引号包裹，内部双引号写两个。
- 只能写临时空间顶层；文件名须以会话标识加 `_` 开头。
- 单元格一律文本：不写公式、不写 `==...==`。
- 上限约 20 万单元格；超了拆 `_1.xlsx` / `_2.xlsx`，或改 `.csv` 并说明。
- 自检：①首行 `# Sheet: 识别结果`、表头五列；②行数 = 识别总行数且与第五节逐条一致；③`是否需要审核` 只有 `是`/`否`，SKU 列非空（查无写 `—`）。
- 正文只写「Excel 已生成，可在右侧面板查看或下载」，不贴路径、不拼链接。

## 七、HTML 报告（仅在用户明确要求时）

1. `read_skill(skill="fresh-order-parse", path="references/report-template.html")`，沿用其结构与样式，不自创版式、不引外部资源。
2. `write_file(filename="<会话标识>_生鲜订单_报告.html", content=<HTML>)`；用模板 `class="hl"` 表示需人工确认，不写 `==...==`。
3. 正文只写「报告已生成，可在右侧面板查看」。
