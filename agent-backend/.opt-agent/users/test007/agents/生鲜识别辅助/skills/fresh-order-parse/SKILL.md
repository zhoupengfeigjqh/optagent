# 生鲜订单识别

一句话流程：拿到「订单图片 + SKU 清单」→ 调用 `fresh_order_parse` → 三张表展示 → 有候选或异常就 `read_file` 复核 → 最终推荐表收口 → `write_file` 输出**一份标准 Excel**。

HTML 报告不是默认产物（只有用户明确要求时才出，见第七节）。

## 一、前置条件

| 输入 | 必需 | 说明 |
|---|---|---|
| 订单图片 | 是 | 单张 `.png` / `.jpg` / `.jpeg`，用户上传到文件空间的原图 |
| SKU 清单 | 是 | `.xlsx`，含「SKU清单」工作表（列：SKU编码、商品名称、别名、品类、规格、单位、是否启用） |

1. 任一文件缺失（只给图、只给表，或只在对话里念商品名）→ **先向用户索取，不调用工具、不编造结果**。
2. 提示上传位置：订单图片 `数据准备/生鲜订单图片`；SKU 清单 `数据准备/生鲜sku表`。
3. 文件名不确定 → 先 `list_dir` 拿到真实文件名，**禁止猜名**。
4. 多张图 → 逐张调用、各自成表，最后给合计。

## 二、调用工具

工具 `fresh_order_parse`（MCP 服务 `fresh-parse`）：

| 参数 | 必填 | 填什么 |
|---|---|---|
| `image_path` | 是 | 图片的文件空间相对路径，如 `数据准备/生鲜订单图片/订单1.png` |
| `sku_path` | 是 | SKU 清单的相对路径，如 `数据准备/生鲜sku表/SKU清单.xlsx` |
| `noise_path` | 否 | 留空，用服务内置默认噪声词表 |
| `synonyms_path` | 否 | 留空，用服务内置默认映射表 |

1. 一律写**文件空间相对路径**（`数据准备/...`）；禁止 http(s) 地址、禁止盘符绝对路径。
2. 一次一张图；同一张图不要为“再确认”重复调用。
3. 工具报错（直链铸造失败、OCR 失败、文件不存在）→ 如实说明并给下一步（是否已上传、图片是否空白/模糊），不得假装成功。
4. 本技能只读：不改 SKU 清单、不写回订单、不生成新 SKU。

## 三、结果展示（三张表）

工具返回三组行：`auto_rows`（**高度匹配**，已确定命中）、`review_rows`（**匹配但待审核**）、`error_rows`（**有异常**）。

先给一句总览：「共识别 N 行：高度匹配 a 行、待审核 b 行、异常 c 行。」

**表一 · 高度匹配（`auto_rows`）**

| 原始行 | 标准化名称 | 数量 | 匹配商品 | SKU编码 | 置信度 |
|---|---|---|---|---|---|

**表二 · 待审核（`review_rows`）**

| 原始行 | 标准化名称 | 数量 | 最高分 | 候选列表 |
|---|---|---|---|---|

候选列表取 `candidates`，按「名称（分数）」用 ` / ` 连接，最多 3 个。

**表三 · 异常（`error_rows`）**

| 原始行 | 标准化名称 | 数量 | 异常类型 | 最高候选 | 最高分 | 说明 |
|---|---|---|---|---|---|---|

1. 三张表都要出现，某张为空写「无」并保留计数 0，不要省掉整张表。
2. 分数统一取整；保持工具返回行序，不排序、不合并、不去重。
3. 必须保留「原始行」列——它是复核与人工修正的唯一锚点。
4. 多单/多图时保留 `订单编号`、`来源` 两列。
5. 不要把工具返回的原始 JSON 整段贴出来。

## 四、二次分析（`review_count > 0` 或 `error_count > 0` 时必做）

触发条件只有这一条：**待审核或异常非空**。两者都为 0 → 跳过本节，直接出 Excel。

复核范围**只覆盖表二、表三的行**；表一（高度匹配）不参与，`read_file` 的结论不得用来改写工具给出的匹配。

1. `read_file`，`path` 与 `sku_path` 相同（xlsx 会自动转 CSV 文本）。
2. 用「原始行 / 标准化名称 / 候选名称」的关键词检索：商品名称、别名、品类、规格；没命中就换更短的核心词（去掉规格、单位、修饰词）再查。返回被截断时用 `offset` / `limit` 续读。
3. 每条给「推荐 + 证据」，证据三要素缺一不可：SKU 侧（SKU编码 / 商品名称 / 别名或规格 / 单位 / 是否启用）、订单侧（原始行、标准化名称、数量）、一句判断依据（别名一致、规格吻合、仅差噪声词等）。
4. 清单里确实没有 → 写「SKU 清单中未找到」+ 已检索的关键词，请用户确认；**不得臆造 SKU 编码或商品名称**。

## 五、最终推荐表（与第四节同条件，必给）

`review_count > 0` 或 `error_count > 0` 时，复核完 MUST 用一张表收口：

| 序号 | 原始行 | 数量 | 最终商品 | SKU编码 | 判定 | 依据 |
|---|---|---|---|---|---|---|
| 1 | 蕃茄3斤 | 3斤 | ==番茄== | ==VEG-001== | 模型推荐 | 别名一致，SKU 启用 |

- **行覆盖**：表二 + 表三的全部行，序号连续；表一行不进本表（已在表一里）。
- **判定**只有两种：`模型推荐`（第四节结论）、`待确认`（查无或仍有歧义）。
- **标红**：`模型推荐` / `待确认` 两行的「最终商品」「SKU编码」用 `==内容==` 包裹，内侧不留空格；表头与合计行不标红。`待确认` 行写 `==待确认：<最可能品种>==` 与 `==—==`，依据里列出已检索关键词。
- 表尾补一行：`合计 N 行：模型推荐 a、待确认 b`。
- 「数量」取 `quantity`（含单位），缺失写 `—`。

## 六、标准 Excel 输出（每次解析必做一次）

`write_file(filename="<会话标识>_生鲜订单.xlsx", content=<CSV 行数据>)`

写法（`.xlsx` 的 content 就是 CSV 文本，服务端编码成工作簿）：

- 第一行是表头；多个工作表用**独占一行**的 `# Sheet: 名称` 分隔（名称 ≤31 字符，不含 `[]:*?/\`）。
- 含逗号或换行的单元格用双引号包裹，内部双引号写两个。
- 只能写**临时空间顶层**；数据准备、共享空间只读。文件名必须以工具说明里的会话标识加 `_` 开头。

工作表（顺序固定，前三张恒建，只有表头也算一张表）：

| Sheet | 列 |
|---|---|
| `高度匹配` | 订单编号、原始行、标准化名称、数量、匹配商品、SKU编码、置信度、来源 |
| `候选审核` | 订单编号、原始行、标准化名称、数量、最高分、候选列表、来源 |
| `异常记录` | 订单编号、原始行、标准化名称、数量、异常类型、最高候选、最高分、说明、来源 |
| `最终推荐` | 序号、原始行、数量、最终商品、SKU编码、判定、依据 |

- `最终推荐` sheet 仅在第四节触发时写入（恒为最后一张）。
- 所有单元格都是**文本**：分数写取整后的数字文本，数量写原文（如 `2斤`），不要写公式、不要用 `==...==`（Excel 里会原样出现两个等号，人工确认改由「判定」列表达）。
- 上限约 20 万单元格：超出则拆成 `_1.xlsx` / `_2.xlsx`，或降级写 `.csv` 并说明。
- 写完做三条自检：表头与列顺序一致、行数 = 三张表合计、最终推荐行与第五节逐条对应。
- 正文只写一句「Excel 已生成，可在右侧面板查看或下载」，不贴路径、不拼链接。

## 七、可选：HTML 报告（仅用户明确要求时）

用户明确说要看 HTML/网页报告时才执行；默认不产出。

1. `read_skill(skill="fresh-order-parse", path="references/report-template.html")`，沿用其结构与样式，不自创版式、不引外部 CSS/JS/字体/图片。
2. `write_file(filename="<会话标识>_生鲜订单_报告.html", content=<完整 HTML>)`；报告里用模板的 `class="hl"` 表示需人工确认的单元格，**不要**写 `==...==`。
3. 正文只写一句「报告已生成，可在右侧面板查看」。
