设计细则

  • 取值：该条消息 tool_calls[].view_urls（后端抽取的 sidecar），不读模型正文。
  • 去重：先按消息内跨工具去重，再按解析后的 href 去重（同一目标只留一个）。
  • 顺序：按工具调用顺序、首次出现顺序。
  • 上限：直接显示前 3 个 + 「另有 N 个」展开；不静默丢弃（宪章原则九）。
  • 归一化：单个 / 开头 → 拼当前页面入口；已带 http(s):// → 原样；其余形态不产生链接。唯一实现仍是 utils/view-link.ts。
  • 空态：没有合法链接 → 整行不渲染（v-if），不留空行、不留间距。
  • 无障碍：原生 <a> 可 Tab；链接文本是地址原值（不只念“打开视图”）；新窗口带 rel="noopener noreferrer"；「另有 N 个」带 aria-expanded。
  • 不可用态：running（本轮仍在跑）或正文被截断时不会有值 —— 该行自然不出现，无需额外分支。
  • 与卡片头入口的区别：卡片头那个是「这一次调用」的入口（固定取该次调用的第一个地址）；本行是「这条回答」的入口（并集 + 去重）。两者语义不同，都保留。
  • 已知限制：结果 >256K 字符不解析、嵌套深度 >8 不抽取 → 没有入口（登记为已知限制）。
