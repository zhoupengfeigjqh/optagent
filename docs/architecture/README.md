### 图的口径分层（2026-10-08）

图中内容按**可核程度**分三层，MUST 分清：

| 层 | 内容 | 出处 |
|---|---|---|
| **A · 代码/配置可核** | 端口、技术栈与版本、协议、三层目录（`routes → domain → infra`）、存储载体、降级机制、端点能力 | 可直接在源码与编排文件里核对 |
| **B · 规格/文档口径** | 权威源单向、只读投影、部署整体覆盖、HITL 语义、白名单不可改、令牌掩码 | `specs/001-digital-human-platform/spec.md` 的 FR / SC |
| **C · 归纳命名** | "业务能力域"的分组与命名、分区带的划分、价值与边界措辞 | 本目录的表达方式，**不是代码事实** |

> **术语口径**：事务型 / 在线事务处理写作 **OLTP**，分析型 / 在线分析处理写作 **OLAP**；两者的闭环统一称 **OLTP-OLAP 闭环**——业务图焦点区按「**OLAP 侧 → 确认闸门 → OLTP 侧 → 状态回流**」呈现，闸门是两种范式之间唯一的通道。

## 图形约定

- 画布宽统一 **1600**，高按内容自适应；中文字体族 `Microsoft YaHei, PingFang SC, Segoe UI, sans-serif`
- 线型语义（四张图一致）：
  - **实线箭头** = 调用 / 数据流
  - **虚线箭头** = 只读 / 不落盘 / 可扩展（虚线框同理）
  - **粗橙箭头** = 配置下发（权威源单向）或闭环关键路径
- 术语口径与 [根 README](../../README.md) 一致；行为细节与验收标准以 `specs/` 为准
- 图内**尽量不出现**具体文件名与类名（应用架构图只用到层名与能力名），目的是让图**不随代码漂移**

## 编辑与导出

- 直接用文本编辑器改 SVG（纯文本、可 diff）；改宽高时请同步 `viewBox`
- 导出 PNG / PDF：浏览器打开 → 打印为 PDF；或用 `rsvg-convert`、Inkscape 命令行
- 改图时请保持四张图的**配色与线型语义一致**；新增同族图请沿用 `NN-<name>.svg` 命名
