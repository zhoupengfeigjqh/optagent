## 0. 复盘方法

先立**可判定的判据**，再拿现状对账。判据只从系统的不可变职责推导——**把人的意图变成对业务系统的读写，并保证可解释、可追责、可恢复**——不掺技术偏好。

| # | 判据 | 违反时的典型症状 |
|---|---|---|
| **A1** | **信任边界**：跨信任级的调用必须可验证身份与权限；不能把"网络位置"当权限 | 谁能访问端口，谁就是管理员 |
| **A2** | **状态所有权唯一**：每份可变状态有唯一所有者；**要能恢复的就必须可重放**，不能只存内存 | 重启丢在途任务、丢挂起确认 |
| **A3** | **单向流水线 + 幂等收敛**：配置/数据/事件方向唯一；重复执行必须收敛于**内容级**判据 | 静默用旧配置跑 |
| **A4** | **失败是一等公民**：每个跨边界动作都要定义"部分失败"的形状、可见性与修复路径 | 孤儿数据、永久"进行中" |
| **A5** | **契约 > 实现**：跨进程契约必须显式版本化，否则只能"同时升级" = 不可演进 | 改一个字段要全量停机 |
| **A6** | **复杂度预算**：新机制必须换到可度量的风险；不为"将来可能"付费，也不把已知风险留给运气 | 过度设计，或裸奔 |
| **A7** | **可观测即正确性的一部分**：一次业务动作必须能被**串起来**看到 | 排查靠时间戳猜因果 |

**级别定义**：`P0` = 与自身业务承诺直接矛盾；`P1` = 会显著抬高事故处理成本；`P2` = 容量与成本，当前不痛但有到期日。

## 1. 结论摘要

**在"单机、单用户、内网受信"的快乐路径上，这套系统做得相当扎实**：

- 部署物化是**目录级原子改名 + 备份 + 失败回滚 + 先预检后写入**（`admin-backend/src/infra/opt-agent-writer.ts:101-173`）；
- 文件回源走**无状态 HMAC 签名直链**，读/写两个方向的 payload 刻意不同以防权限放大（`agent-backend/src/infra/file-sign.ts:55-89`）；
- 工具事件落盘失败**有意不阻断对话**（`TR-24`，`agent-backend/src/domain/run-manager.ts:372`）；
- 事件日志有**坏行告警 + 整体损坏备份重建**（`domain/history.ts:75-84`、`domain/tool-events.ts:322-339`）。

**但它有三处与自身业务承诺直接矛盾的结构性缺口**——不是代码质量问题，而是架构层面的：

| 缺口 | 承诺（图上/规格里写的） | 实现事实 |
|---|---|---|
| **① 无身份** | 业务图承诺"人工确认在环 + 过程可审计" | 运行端固定单用户、管理端操作者是**常量字符串**；网关只按路径分发，`/api/*` 与 `/api/admin/*` 无鉴权差异 |
| **② 运行态不可恢复** | 承诺"多轮对话 + 在途确认" | 一轮运行、SSE 订阅、HITL 挂起项**全在进程内存**，无快照、无重放 |
| **③ 变更无判据、契约无版本** | 承诺"配置权威源唯一 + 局部可演进" | 配置感知靠 `size:mtime`；物化契约与 SSE 事件**无版本字段** |

其余为 P2 容量项与已登记的有意取舍（见 §4）。

## 2. 逐视图诊断

### 2.1 业务架构（判据 A1 / A7）

| 问题 | 机制（证据） | 触发 → 后果 | 级别 |
|---|---|---|---|
| **身份不存在** | 运行端固定单用户 `BUILTIN_ADMIN`（`agent-backend/src/domain/current-user.ts:12,17`）；管理端操作者常量 `PLATFORM_OPERATOR = 'zyw_admin'`（`admin-backend/src/domain/error-codes.ts:97`，每行日志固定此人 `logging.ts:118`）；前端**不携带任何身份**（`frontend/src/api/http.ts:101`，全仓 `Authorization`/`Bearer`/`credentials` 零命中）；网关仅路径分发（`gateway/nginx.conf:26,46`）；CORS 全开（`agent-backend/src/server.ts:289`） | 任何能访问 :82 的人 → 可改 MCP 配置（含把**明文令牌**下发到运行端）、可读全部会话（运行端只有一个用户）→ **审计里的"谁"是常量，等于不可追责** | **P0** |
| **写操作工具无需确认即可落库** | 本体侧自建发布服务 `raw_inventory_purchase_action` 的白名单含 `CreatePurchaseRecord` / `CancelPurchaseRecord` / `ReceiveRawMaterial`，而该服务 `confirmation = never`（实测 `GET /api/admin/mcp/services/raw_inventory_purchase_action`） | 装配给数字人后，模型可**无确认写业务系统**，与"人工在环闸门"的业务承诺相反 | **P0** |
| 审计缺"主体 + 因果链" | 同上；动作有记录，主体是常量，且无跨服务 trace | 出问题无法回答"是谁、因为哪次提问" | P1 |

> **有意取舍**：单用户是**明示的设计**（`current-user.ts:4-6` 注释"本期固定返回 admin；接口按 JWT 预留"）。取舍本身成立，但必须承认：**图上的"人工确认 + 过程可审计"目前没有技术兑现**。要么补身份（推荐），要么把承诺降级（把"可审计"改为"终端可追溯"）——两者都行，**不能又承诺又不兑现**。

### 2.2 数据架构（判据 A2 / A3 / A4）

| 问题 | 机制（证据） | 触发 → 后果 | 级别 |
|---|---|---|---|
| **"一轮运行"只活在内存里** | run 表是进程内 `Map`（`agent-backend/src/domain/run-manager.ts:99`）；SSE 订阅绑定创建它的进程（`routes/chat.ts:194-198`）；HITL 挂起项在内存（`domain/interaction-gate.ts:105`）；选中态 / MCP 客户端表 / 实例池同为内存（`domain/current-agent.ts:12`、`infra/mcp/mcp-manager.ts:158`、`domain/agent-pool.ts:36`）；事件总线是 `EventEmitter`（`domain/mcp-events.ts:18`、`domain/produced-events.ts:16`）；`stop` 只查本进程（`routes/chat.ts:206`）；落盘的 `history.jsonl` 只记**已完成**的轮（`domain/history.ts:31`） | 崩溃/重启 → 在途回答丢失、**用户刚点的"确认"蒸发**；起第二个实例 → 中断/确认/HITL 打不到另一个实例 | **P0** |
| **配置变更判据是 `size:mtime`** | `config-fingerprint.ts:57-61` `statSignature = ${size}:${mtimeMs}`；只覆盖 4 个关键文件（`:23`） | 同秒改配置、时间戳精度不足或保留时间戳的同步方式 → **静默继续用旧配置**（与"权威源唯一"承诺冲突） | **P1** |
| **部分失败有形状，但没有修复路径** | 后台产出**先写正文、后写 sidecar**，而列表**以 sidecar 为存在判据**（`domain/produced.ts:126,141,175`）→ 正文写了 meta 没写 = **不可见孤儿**；`files-put` 仅 `PermissionError → 400`（`routes/files-put.ts:118-123`）；无任何"扫孤儿 / 补终态 / 报漂移"的任务 | 一旦发生只能人肉排查 | **P1** |
| **清理判据依赖 atime** | 临时空间按 `max(atimeMs, mtimeMs)` 判"7 天未访问"（`domain/tmp-cleanup.ts:13,65-66`） | 若卷以 `noatime` 挂载（容器 / Windows bind mount 常见），**读取不更新 atime** → "7 天前写过、昨天刚读过"的产出被清掉。**⚠ 需在本机实测确认后再定性** | **P1（待实测）** |
| 容量：目录即索引、无归档 | 线程列表遍历目录（`domain/thread-store.ts:150-163`）；产出列表扫描目录（`domain/produced.ts:166-181`，注释即"目录即索引"）；无大小上限；日志 3 天（`logging.ts:20`）与 MCP 事件 1 年（`infra/usage-db.ts:31`）口径不一 | 会话/产出上千后列表与备份成本线性上涨 | P2 |

> **有意取舍**：**共享同一份用户数据目录**（`docker-compose.yml:123`，FR-001）→ 换来"部署即生效、无需网络往返"，付出"平台与运行端**必须同机同卷**"。

### 2.3 技术架构（判据 A5 / A7 / A6）

| 问题 | 机制（证据） | 触发 → 后果 | 级别 |
|---|---|---|---|
| **跨端契约无版本** | 物化 4 文件（`MCP.json`/`TOOL.json`/`SOUL.md`/`scenario.json`）由 admin 写出（`admin-backend/src/domain/deploy/materialize.ts:91-110`）、由 agent 校验解析（`agent-backend/src/domain/agent-instance.ts:105-108`），**无 `schema_version`**，靠注释约定同口径；两个只读端点响应无版本（`admin-backend/src/infra/runtime-client.ts:79,96`）；SSE 事件无版本（`agent-backend/src/domain/run-events.ts:23-51`）。全仓唯一 `SCHEMA_VERSION` 只在 `.platform-data/meta.json`（`admin-backend/src/infra/platform-store.ts:26`） | 改一次配置格式 → 必须**两端同时升级**，无法滚动升级/回滚 | **P1** |
| **无跨服务 trace** | admin→runtime 调用不带 trace（`infra/runtime-client.ts:116`）；SSE 行只有 `event/data`（`routes/chat.ts:195`）；日志有 `instance_id`/`thread_id` 但无跨服务关联（`logging.ts:130-132`）；无指标、无链路追踪 | "这一步为什么慢/为什么失败"靠时间戳猜；MCP 调用统计无法归属到某次提问 | **P1** |
| **签名密钥未进入正规部署通道** | 读方向 `GET /api/files/raw`、写方向 `POST /api/files/put` 共用密钥（`infra/file-sign.ts:55-65`），时效 24h（`:14`）；密钥缺失时**每次启动随机生成**（`config.ts:173`）；`.env.example:19` 该项为空；实证：`agent-backend/.env`（**入库**）**无**该项，`agent-backend/.env.local`（**gitignore**）有（64 字符） | 换机器 / 纯用入库配置部署 / 清理 `.env.local` → 退化为"每次重启换钥匙"：重启后仍在 24h 有效期内、已发出的链接全部失效 → ① MCP 回源取文件被拒（工具调用失败）② 异步任务产出回写被拒（**产出丢失**），且**日志不会说"密钥换了"** | **P1** |
| 明文令牌落两处 | 设计态 `mcp-services.json` 与物化 `MCP.json` 均明文（`materialize.ts:50-53`；`domain/mcp/service-config.ts:22-26` 注释"存明文、响应只回掩码"；`service-config-fields.ts:167` `maskHeaders`；`service-list.ts:168` 只给 `has_headers`） | 令牌是当前**唯一凭据**（无鉴权）→ 文件可见面 = 权限面；物化文件权限跟 umask 走 | P1 |
| 单机硬约束写死在多处 | 共享 `.opt-agent` 卷（`docker-compose.yml:102,124`）、本地相对路径 `../optonto/.data/onto_market`（`:128`）、固定 `PUBLIC_BASE_URL=http://backend:3000`（`:97`）、网关**单一上游无负载均衡**（`nginx.conf:47`） | 跨机 / 多实例 / HA 需一次性改造多点 | P2 |
| 无 TLS + 内网受信 | 网关 `listen 80`（`nginx.conf:18`）；`/api/admin/` 与 `/api` 同源暴露 | 与"无鉴权 + 明文令牌"三者相乘，出内网风险陡增 | P2（内网可接受，须与 A1 同批处理） |

### 2.4 应用架构（判据 A2 / A6）

| 问题 | 机制（证据） | 触发 → 后果 | 级别 |
|---|---|---|---|
| **分层视图缺"状态归属"这一维** | 应用图按 `routes/` → `domain/` → `infra/` 描述**静态依赖**；而真实故障源是状态归属：谁拥有 run？谁拥有 HITL 挂起？谁能重建 SSE？答案全是"进程内存"（见 2.2） | 读图者容易误以为"分层清楚 = 系统稳"——分层只保证依赖方向，不保证可恢复性 | P1 |
| 跨应用链路是"共享卷 + 只读端点"混合 | 部署 = 写对方目录（`admin-backend/src/infra/opt-agent-writer.ts:68-75`）；观测 = HTTP 只读端点（`runtime-client.ts:79,96`） | 两条演进路径都要维护：改部署协议动文件格式、改观测协议动 API | P2 |
| 依赖策略优秀，**必须保持** | `admin-frontend` 零第三方运行时依赖；两后端零新增依赖 | 这是资产，不是约束 | — |

## 3. 四个视图的相互关系（为什么会同时出现这三个缺口）

```
业务视图承诺：人工确认 · 过程可审计 · 配置权威源唯一
        │
        │  ① 缺"身份"  → A1 断裂：承诺里的"人"在技术上是常量
        ▼
应用/技术视图：routes → domain → infra 分层清晰，但
        │      ② 状态挂在进程内存 → A2 断裂：分层不保证可恢复
        ▼
数据视图：JSONL + 目录即索引 + 共享卷
              ③ 变更靠 mtime、契约无版本 → A3/A5 断裂：承诺"唯一/可演进"没有判据
```

**要点**：三个缺口都不是"某处写错了"，而是**视图之间的承诺没有落到同一层**。业务视图写的是结果承诺，技术视图写的是构造方式，中间**缺一条"状态与身份的归属线"**。§5 的目标方案就是补这条线。

## 5. 目标方案：三条主线 + 两个治理面

**总原则**：用现有材料修结构。不引入 MQ / Redis / K8s / ORM —— JSONL、文件、SQLite、HTTP 已足够支撑"单机 + 可演进"。

### 主线 1：补上身份与分权（解 A1）

| 步骤 | 内容 |
|---|---|
| M1-1 | **最小可信身份**：`SESSION_SECRET` 签名的会话 cookie（HMAC，复用 `file-sign.ts` 的 crypto 手法）；两后端各加一个 hook：无票据 = 401，`role !== admin` 访问 `/api/admin/*` = 403 |
| M1-2 | **主体落到日志与审计**：把 `PLATFORM_OPERATOR` 常量换成真实主体（`error-codes.ts:97`、`logging.ts:118`）；关键动作记 `who / when / what / target / trace_id` |
| M1-3 | **凭据收口**：物化 `MCP.json` 权限 0600；签名密钥按环境分流（生产缺则拒启动、开发告警）；令牌轮换写成一页 SOP |
| M1-4 | **业务闸门**：`raw_inventory_purchase_action` 的 `confirmation` 改为 `always`（写操作必须人工确认） |

### 主线 2：把"一轮运行"变成可恢复对象（解 A2，并打开多实例）

| 步骤 | 内容 |
|---|---|
| M2-1 | **run journal**：每轮把状态变更**追加**到 `threads/{id}/run.jsonl`（复用既有 JSONL 写法、坏行告警、per-thread 串行链）。事件：`run_started / tool_call / tool_end / interaction_pending / interaction_resolved / text / run_finished / run_aborted` |
| M2-2 | **恢复语义**：启动或首次访问时读 journal → ① 未闭合的 run 标记 `未完成`（与既有 TR-33 语义天然一致）② HITL 挂起项可重建 ③ SSE 改为**事件游标拉取**（`?since=` / `Last-Event-ID`）→ 内存 run 表退化为"本地执行器缓存"而**非权威源** |
| M2-3 | **明确不做**：不做分布式锁、不做消息队列、不做跨机调度。单机语义不变，只把权威状态从内存搬到可重放日志 |

### 主线 3：单向流水线加"版本 + 内容指纹 + 对账"（解 A3 / A4 / A5）

| 步骤 | 内容 |
|---|---|
| M3-1 | **契约加版本**：物化 4 文件加 `schema_version`（无字段 = v0 存量，兼容读取；未知更高版本 = 明确拒绝并告警）；两个只读端点响应加 `schema_version`；SSE 事件加 `v` |
| M3-2 | **指纹改内容摘要**：`size:mtime` → 4 个关键文件的 sha256（文件极小，成本≈0；仓库已有 sha256 用法可复用） |
| M3-3 | **对账任务**（每小时，复用既有调度）：① 孤儿正文（无 sidecar）→ 补 meta 或清理 ② 只有 start 无 end 的工具事件 → 补 `未完成` 终态 ③ **运行态 vs 设计态漂移报告** |
| M3-4 | **清理判据去 atime 依赖**：读取时 touch sidecar，或 meta 记 `last_accessed_at`（先实测 atime 行为再定） |

### 治理面 A：trace 贯通（解 A7）

`trace_id` = 一轮 run 的 id，从浏览器 → agent-backend（日志 + SSE 行）→ MCP 请求头 `X-Trace-Id` → 工具服务日志 → 回源下载。**零依赖**，只是把已有 `thread_id`/`req_id` 提升为跨服务契约。

### 治理面 B：审计不可否认（解 A1 后半）

与 M1-2 配套：部署、删除服务、改令牌、写操作工具调用，均可追溯到"谁、何时、因为哪次提问"。
