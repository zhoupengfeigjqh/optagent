[[IT]]# admin-frontend 重构方案：登录鉴权 + 用户管理 + 设计区注册链接

## 背景

参考 `数字人注册原型.html` 重构 admin-frontend：后端 028 账号域接口已全部就绪（登录/注册/链接/授权/用户扩展字段），但前端还是「无登录页、无守卫」+ 028 阶段 2/3 建的「账号与授权」功能区。本次按原型收敛为：删除「账号与授权」、新增管理员登录页与普通用户注册/登录页、设计区加「生成注册链接」、新建原型样式的「用户管理」页并精简部署区（用户已确认这两个决策）。后端零改动。

**已确认决策**：①「用户管理」为独立一级导航（原型「账户管理」表格样式），部署区只留部署功能；②用户登录成功后页内提示 + 「进入对话」按钮。

## 范围外（明确不做）

- 后端改动 / 角色强制（阶段 4 的 `ADM_FORBIDDEN`，后端目前未启用）——控制台保护仅靠前端守卫
- 对话窗口接入（`my-agents` 前台过滤，下一批）
- 授权通过自动部署（待定项①）
- 原型中的二维码（原型本身已隐藏）、演示账号提示文案

## 改动清单

### ① 会话与路由守卫

- 新增 `src/composables/useAuthSession.ts`（+ 同名 spec）：模块级响应式会话状态 `{ profile: Ref<MeProfile|null>, ready, probe(), login(account, password), logout() }`。`probe()` 调 `fetchMe()`（`src/api/auth.ts`），401 → null；`login` 调 `login({ user_id, password })`；`logout` 调 logout API 并清空。
- `src/router.ts`：
  - `ROUTE_NAMES`/`NAV_ITEMS`：删 `'account'`，增 `'users'`（label「用户管理」，放末位，与原型页签顺序一致）→ 仍 6 项。
  - 新增保留伪路由：`AppRouteName = RouteName | 'login' | 'register'`；`parseLocation` 首段命中 `login`/`register` 时直接返回该名（`register` 的 `?link=` 进 `query`）；`buildPath` 参数放宽为 `AppRouteName`。
- `src/App.vue`：路由三分支——`login` → AdminLoginView；`register` → UserAuthView；其余为受守卫的管理台：挂载时 `probe()`，未登录或 `role !== 'admin'` → `router.navigate('/login', { replace: true })`，探测中显示极简加载态；管理台分支保持现有 Area 切换（account 分支换成 users）。
- `src/components/layout/AppShell.vue`：页头右侧加身份标签（管理员 · display_name）与「退出登录」按钮（emit logout → `logout()` + 跳 `/login`）。

### ② 管理员登录页（新增）

`src/components/auth/AdminLoginView.vue` + spec：按原型 `#view-admin-login` 还原——渐变 auth-shell、品牌头（DH 标 + 「管理员入口」tag）、auth-card（标题/副题、账号+密码+眼睛切换、行内校验、`alert-warn` 错误框复用 `ERROR_MESSAGES.ADM_INVALID_CREDENTIALS`）、底部说明文字（不放演示账号）。成功后跳默认路由。样式用现有 tokens（原型蓝与 `--color-primary` 同值）+ 组件内 scoped CSS 复刻原型版式。

### ③ 普通用户注册/登录页（新增）

`src/components/auth/UserAuthView.vue` + spec：按原型 `#view-auth` 还原——robot-chip（头像取首字 + 服务名 + 「专属注册链接 · 编码」）、`seg` 注册/登录双页签、注册表单（手机号 11 位/用户名 2-20/密码 6-20 + 同意勾选）、「已注册」提示框（`ADM_PHONE_TAKEN` → 「直接登录」按钮切页签并带手机号）、注册成功 alert（展示 `granted_agent.name`）后自动切登录页签；登录表单（手机号+密码）成功后显示成功态 + 「进入对话」按钮（`window.location.href = CHAT_ENTRY_URL`，常量默认 `'/'`）。进页先 `lookupRegisterLink(query.link)`，`ADM_INVALID_LINK` → 警告框「链接无效或已过期」，不渲染表单。无品牌头（原型口径）。
- 新增 `src/constants/entries.ts`：`REGISTER_PAGE_PATH = '/register'`、`CHAT_ENTRY_URL = '/'`。

### ④ 数字人设计区：生成注册链接

- `src/components/agents/AgentCardList.vue`：每卡操作区加「生成注册链接」按钮（新 emit `register-link(agent)`），编码 tag 旁加「注册用户 N 人」绿 tag（display-only，数据来自传入的 agent-services）。
- 新增 `src/components/agents/RegisterLinkDialog.vue` + spec：BaseDialog（项目约定新弹窗必须用 BaseDialog），按原型 `mask-link` 版式——kv 行（数字人/链接标识/有效期）、只读链接框 + 「复制」（复用 `src/utils/clipboard.ts` 的 `copyToClipboard`，失败展示手动复制框，模式同现 RegisterLinkPanel）、有效期 7 天/30 天/长期、页脚「复制链接」「打开注册页面」。打开时按 `platform_agent_name === agent.name` 从 `listAgentServices()` 找服务；找不到 → 提示「该数字人尚未创建对应服务」不生成。**链接 URL 由前端拼**：`` `${origin}/admin/register?link=${token}` ``（后端 `url` 字段在未配 `REGISTER_LINK_PUBLIC_BASE_URL` 时只是 `?link=…` 串，不可直接用）。
- `AgentArea.vue` 透传 emit 并持弹窗；加载 `listAgentServices()` 供卡片 tag。更新 `AgentCardList.spec` / `AgentArea.spec`。

### ⑤ 用户管理区（新导航页，替换「账号与授权」）

- 新增 `src/components/users/UsersArea.vue` + `UserAccountTable.vue` + spec：原型 `pane-accounts` 版式——搜索框（手机号/用户名，当前页客户端过滤）+ 授权状态筛选（全部/含已授权/含申请中，按 `grants_summary` 客户端过滤）+ `acc-table` 表格：手机号 / 用户名 / 注册来源服务（`source_agent_code` → 经 `listAgentServices()` 映射为服务名） / 授权概况（pill：已授权 N · 申请中 N） / 操作（授权详情 · 修改 · 重置密码 · 删除）+ 简易分页 + 「新建用户」。数据走 `listUsers(page, expand=true)`（`src/api/users.ts`）。
- 行操作弹窗：授权详情 → 新增 `GrantDetailDialog.vue` + spec（BaseDialog 宽版：按手机号 `listGrants({phone})` 拉全部分页，逐条 pill 状态 + 通过授权/关闭（`approveGrant`/`revokeGrant`）；未绑手机号显示空态）；修改 → 复用 `UserEditor.vue`（编辑关联数字人）；重置密码 → 复用 `ResetPasswordDialog.vue`；删除 → `ConfirmDialog` + `deleteUser`。
- **移动**：`UserEditor.vue`/`ResetPasswordDialog.vue` 及其 spec 从 `components/deploy/` 迁到 `components/users/`（仅 import 路径变化）。**删除** `UserCardList.vue` + spec（表格取代卡片）。
- 已知限制（写入代码注释与交付说明）：后端 `PUT /users` 仅支持 `agents+revision`，「修改」= 编辑部署关联，不支持改用户名；`GET /users` 无 `created_at`，「注册时间」列省略；搜索/筛选仅作用于当前页（后端无对应 query 参数）。

### ⑥ 部署区精简

`src/components/deploy/DeployArea.vue`：去掉「用户」页签与 UserCardList，保留 DeployPanel + DeployHistoryList（去页签、上下堆叠）。部署目标选择改为 DeployArea 内置精简用户勾选列表（`listUsers` 逐页拉取，勾选 user_id + display_name + 已部署徽标，保留原跨页累积选择语义，`selectedUserIds` prop 契约不变）。重写 `DeployArea.spec.ts`。

### ⑦ API / 类型清理

- `src/api/account.ts`：保留 `listAgentServices` / `createRegisterLink` / `listGrants` / `approveGrant` / `revokeGrant`；删 `createAgentService` / `updateAgentService` / `deleteAgentService` / `listRegisterLinks` / `revokeRegisterLink` / `applyGrant`。
- `src/api/account-types.ts`：同步删无用类型（`AgentServiceCreate/UpdatePayload`、`RegisterLinkItem` 等；`MyAgents`/`MeProfile` 等保留）。`api/auth.ts` 不动（登录/注册/链接校验全要用）。
- `src/api/modules.spec.ts`：重写 `describe('api/account')` 块只覆盖保留函数。

### ⑧ 全局删除

删除 `src/components/account/`（AccountArea、AgentServicePanel、GrantPanel、RegisterLinkPanel 四组件 + 四 spec）、`App.vue` 中 account 分支。同步更新：`router.spec.ts`（删 `/admin/account?tab=grants` 断言，补 login/register 解析用例）、`PrimaryNav.spec.ts`（名称数组改 `['mcp','ontology','skills','agents','deploy','users']`）。

### ⑨ 配置

`vite.config.ts` 覆盖率门禁清单加 `src/composables/useAuthSession.ts`（80% 门禁，宪章要求）；新文件全部 ≤500 行（`npm run check:lines` 把关）。

## 复用清单

`api/auth.ts` 全部函数、`api/users.ts`、`copyToClipboard`（utils/clipboard.ts）、`BaseDialog`/`ConfirmDialog`/`StatusBadge`/`ErrorNotice`/`EntityCardList`（弹窗与徽标）、`ERROR_MESSAGES`（含 `ADM_INVALID_CREDENTIALS`/`ADM_INVALID_LINK`/`ADM_PHONE_TAKEN`，无需加码）、`UserEditor`/`ResetPasswordDialog`（迁移复用）、设计 tokens（与原型同色系）。

## 验证

1. `cd admin-frontend && npm.cmd run test`（新 spec 全绿、删旧 spec）、`npm.cmd run typecheck`、`npm.cmd run lint`、`npm.cmd run check:lines`。（本机须用 `npm.cmd`，PowerShell 策略限制）
2. 端到端手测（后端 :3001 + Vite :5174 均已在跑）：访问 `http://localhost:5174/admin` → 重定向 `/admin/login` → admin 登录进控制台；设计卡片「生成注册链接」→ 复制 → 新标签打开 `/admin/register?link=…` → 新手机号注册 → 成功提示 → 登录 → 「进入对话」；用户管理页增删改查、授权详情审批。必要时用 browser-use 技能做 GUI 验证。
3. 守卫反向验证：未登录直访 `/admin/users` 被弹回登录页。
